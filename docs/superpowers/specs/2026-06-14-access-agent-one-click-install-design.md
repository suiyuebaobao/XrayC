# 中转节点一键安装设计

## 目标

在中转节点页恢复可选“一键安装 Agent”能力，让管理员填写服务器 SSH 信息后，由管理平台在本次请求内临时 SSH 到目标服务器，自动上传安装脚本和依赖并执行现有 `scripts/deploy-access-agent.sh`，无需管理员手动上传脚本，安装完成后自动创建中转节点。原“Agent 安装说明”手动路径继续保留，用于受限网络或需要人工执行的场景。

## 安全边界

- SSH 密码和私钥只允许在本次 HTTP 请求处理期间使用，不写入数据库、审计日志、部署任务 result、前端任务列表或公开日志；如执行 ssh/scp 必须写临时私钥文件，文件在请求结束前删除。
- 平台仍保留“Agent 安装说明”作为手动备用路径，不把一键安装作为唯一入口。
- 一键安装必须复用 `deployment_tasks` 展示进度；失败时只记录脱敏错误摘要。
- 一键安装必须固定强制重装；前端不提供关闭开关，后端即使收到 `force_reinstall=false` 也必须按 true 处理。
- 失败重试不得复用 SSH 密码或私钥，因为平台不保存这些凭据；重试只能回填节点名、地址、端口、安装目录、Compose 项目等非敏感参数。
- API 容器已安装 `openssh-client` 和 `sshpass`，后端通过受控命令行调用它们，不引入新的常驻远程执行服务。

## 安装流程

1. 管理员填写节点名称、客户连接地址、节点端口、备注、SSH IP、SSH 端口、SSH 用户、SSH 密码或私钥。客户连接地址进入订阅、入口默认值和 SSL 检查；SSH IP 只用于本次登录、安装成功后的中转节点运维字段和失败重试预填。
2. 管理员可填写证书域名和 ACME 邮箱；两者同时存在时，安装脚本会在强制重装期间先清理本次域名和旧 env 域名对应的 LetsEncrypt 证书材料，再重新申请 SSL 证书并写入 agent 环境，缺任一项时跳过新证书申请。
3. 后端创建部署任务，生成一次性任务上报 token。
4. 后端在本机生成临时安装目录，写入 `node.env`、安装脚本和脚本依赖。
5. 后端自动通过 SSH 在远端创建临时目录、上传文件并执行 `bash deploy-access-agent.sh`，一键安装路径不要求管理员手动上传脚本。
6. 脚本先停掉旧 Compose 项目和旧容器，清理旧运行状态、配置、制品、env 和 compose 文件，再下载部署产物、启动 `xray-core`、`sing-box` 和 `access-agent`，并向部署任务上报进度。
7. 后端从脚本输出中提取节点鉴权码，调用现有新增中转节点逻辑自动创建中转节点，并把本次 SSH IP 保存到中转节点 `ssh_host` 字段。
8. 部署任务 result 只保存节点 ID、节点名称、客户连接地址、SSH IP、是否申请 SSL 和脱敏摘要；不得保存 SSH 密码、私钥、部署产物 token 或任务上报 token。

## 验收

- 缺少 `DEPLOY_ARTIFACT_TOKEN` 时拒绝一键安装。
- 成功路径必须创建部署任务并返回任务摘要。
- 请求中的 SSH 密码或私钥不得出现在部署任务 JSON 中。
- 填写证书域名和 ACME 邮箱时，远端环境包含 `XRAYC_TLS_CERT_DOMAINS` 和 ACME 邮箱变量。
- 即使请求传入 `force_reinstall=false`，部署任务 safe metadata 也必须显示 `force_reinstall=true`。
