# 接入代理部署指南

本文档描述中转节点上的单内核 Xray 部署：目标服务器固定安装并启动 `xray-core` 和 `access-agent`。后台提供可选“一键安装 Agent”自动 SSH 安装，同时保留手动安装说明；SSH 凭据只在本次请求内用于连接目标服务器，不保存。

## 前置条件

目标服务器需要 Docker、Docker Compose、curl 和 sha256sum。脚本会自动补齐常见缺失工具，但不会停止 SSH 服务，默认也不触碰 systemd。

## 部署步骤

1. 中心执行 `make package-docker-artifacts` 生成 `access-agent` 和 Xray 两个镜像包、manifest 和 sha256 清单。
2. 管理员选择“一键安装 Agent”或生成 Agent 手动安装说明；一键安装会临时使用 SSH 执行远端脚本，手动说明由管理员到目标服务器执行。
3. 目标服务器执行 `scripts/deploy-access-agent.sh`，通过中心下载两个镜像包和 manifest，并校验 sha256。
4. 脚本在目标服务器执行 `docker load` 导入两套镜像，写入节点侧 Compose 文件和环境文件，并在本地生成或复用节点 ID 与 access-agent token。
5. 脚本执行 `docker compose up -d` 启动 `xray` 与 `access-agent` 两个容器；目标环境只存在独立 `docker-compose` 时可使用该二进制兜底。
6. 脚本成功后输出节点鉴权码；一键安装由平台解析鉴权码并自动创建中转节点，手动路径用同一鉴权码完成平台绑定。
7. 入口管理创建入口时只填写协议和网络模式，所有入口都由 `xray` 处理；中转节点页面只展示 Xray 内核状态并可下发启动/停止任务。
8. 中心通过心跳、运行态和订阅真实出站确认部署成功。

如旧节点存在历史 XrayC systemd unit，需要管理员显式设置 `XRAYC_DISABLE_LEGACY_SYSTEMD_UNITS=true` 才会清理；默认部署路径不执行 `systemctl daemon-reload`。

## 回滚

部署脚本默认启用失败回滚。失败时会停止本次 Compose 项目并删除本次生成的 `xray` 和 `access-agent` 容器；如果 `XRAYC_INSTALL_DIR` 是本次新建，会删除该目录；如果部署前目录已存在，则默认保留，避免误删旧生产配置。

## 运行态文件

access-agent 会把已应用配置缓存写入 `XRAYC_AGENT_STATE_PATH`，把中心不可达时尚未成功上报的流量快照写入 `XRAYC_TRAFFIC_BACKLOG_PATH`，并从 `XRAYC_XRAY_ACCESS_LOG_PATH` 增量读取 Xray access log 生成在线会话摘要。

推荐环境变量：

- `XRAYC_SESSION_IDLE_SECONDS=180`：在线会话空闲保留窗口。
- `XRAYC_XRAY_CONFIG_PATH=/etc/xray/config.json`：Xray 配置路径。
- `XRAYC_XRAY_START_COMMAND` / `XRAYC_XRAY_STOP_COMMAND`：节点页控制 Xray 容器启停。
- `XRAYC_AGENT_STATE_PATH=/var/lib/xrayc/access-agent/state.json`：已应用配置缓存。
- `XRAYC_TRAFFIC_BACKLOG_PATH=/var/lib/xrayc/access-agent/traffic-backlog.json`：流量补发队列。
- `XRAYC_XRAY_ACCESS_LOG_PATH=/var/log/xray/access.log`：Xray access log 路径。
