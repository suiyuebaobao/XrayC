# 真实发布资产准备清单

本文只记录变量名、来源和通过标准，不记录真实 IP、密码、Token、订阅链接、数据库 URL、代理 URL 或第三方凭据。真实值只能写入未跟踪的 `.env.real-release` 或 `XRAYC_REAL_RELEASE_ENV_FILE` 指向的私有文件。

## 准备流程

1. 生成私有草稿：`bash scripts/bootstrap-real-release-env.sh --overwrite`。
2. 查看分组缺口：`make real-release-gap-report`。
3. 导入订阅到真实客户端后，在私有 env 填写 `CLIENT_PROXY_URL*`，再运行 `make observe-real-client-env` 自动写入 `EXPECTED_EXIT_IP*`。
4. 补齐私有值后只跑 readiness：`make check-real-release-env`。
5. readiness 通过后再跑真实发布门禁：`make check-real-release`。

## 控制面与部署

- `BASE_URL`：生产必须是 HTTPS。私有测试环境暂未配置 TLS 时，只能使用内部测试开关临时放行 HTTP 控制面地址，公开文档和日志不得记录真实地址。
- `XRAYC_ENV`：真实发布必须显式设置为 `production`。
- `JWT_SECRET`：来自私有密钥库，生产必须使用高强度随机值，只能写入私有 env 或部署密钥，不得出现在公开日志和文档。
- `JWT_EXPIRES_IN`：生产 access token 有效期，建议不超过 `30m`，必须通过私有 env 显式设置。
- `JWT_REFRESH_EXPIRES_IN`：生产 refresh token 有效期，建议不超过 `7d`，必须通过私有 env 显式设置。
- `SEED_DEMO_DATA`：真实发布必须显式设置为 `false`，禁止生产环境写入 demo seed。
- `REAL_RELEASE_MATRIX_MODE`：完整真实发布强门禁必须为 `relay`；固定客户端代理诊断路径只用于已有固定客户端代理和固定中转入口的专项排障，不能作为六协议禁用/超额剔除闭环证据。
- `DEPLOY_ARTIFACT_TOKEN`：来自私有部署 token 文件或后台配置。
- `DATABASE_URL`：必须是真实发布数据库连接串。使用 `change-me`、`example` 或占位密码的本地 Compose 数据库不能作为真实发布数据库；单机 Docker 生产部署若 PostgreSQL 只绑定 loopback，必须显式设置 `XRAYC_REAL_RELEASE_ALLOW_LOCAL_DATABASE=1` 才允许作为真实发布门禁数据库。

## 订阅与接入节点

- `SUB_TOKEN` 或 `SUBSCRIPTION_URL`：来自后台真实用户订阅。
- `AGENT_TOKEN`、`ACCESS_NODE_ID`、`ACCESS_LINE_ID`、`EXIT_ENDPOINT_ID`：来自真实中转节点、中转入口和内部默认出口 endpoint。
- `XRAY_USER_KEY`：真实用户在 access-agent/Xray 中使用的授权标识，用于流量积压恢复 UAT 校验 backlog 文件和账本回放，只能写入私有 env。
- `XRAYC_REAL_E2E_INVENTORY`、`XRAYC_REAL_E2E_TARGET`：来自仓库忽略的私有服务器侧安装清单。
- 当前私有清单角色约定：`server_1` 是直连/非 CF 目标，普通真实流量、订阅兼容和多用户 UAT 默认用它发起请求；`server_4` 是 Cloudflare/橙云目标，只用于 CDN/橙云入口路径专项验证。普通出口宿主选择不得默认落到 `server_4`。
- `CLIENT_PROXY_URL`：真实客户端本地代理入口，例如导入订阅后的本机代理端口。
- `EXPECTED_EXIT_IP`：通过真实客户端代理访问公网 IP 检测服务得到的预期出口 IP。可在填好 `CLIENT_PROXY_URL` 后用 `make observe-real-client-env` 自动观测并写入私有 env；脚本只输出变量名，不输出代理 URL 或 IP。
- `USER_ACCESS_TOKEN`：通过真实用户登录接口写入，推荐使用 `make prepare-real-e2e-auth-env` 写入私有 env。
- `EXPECTED_ACCESS_SERVERS`：订阅中应该出现的中转入口地址列表，格式为 `host:port`，多个用逗号分隔。`scripts/bootstrap-real-release-env.sh` 会尝试从真实订阅 YAML 中解析该值并写入私有 env；如果解析结果仍像 demo、example 或占位值，会自动跳过，不能当作真实发布资产。

## 真实浏览器与管理员凭据

- `E2E_USER_ACCOUNT`、`E2E_USER_PASSWORD`：真实 Playwright no-mock 使用的普通用户账号，只允许写入私有 env。
- `E2E_ADMIN_ACCOUNT`、`E2E_ADMIN_PASSWORD`：真实 Playwright no-mock 和认证 UAT 使用的管理员账号，只允许写入私有 env。
- `ADMIN_LOGIN_ACCOUNT`、`ADMIN_LOGIN_PASSWORD`：relay 模式创建临时中转链路时使用的管理员登录凭据，只允许写入私有 env。
- `ADMIN_ACCESS_TOKEN`：可选管理员 JWT；用于认证 HA UAT 或安全探测触发，优先通过私有登录流程生成，不写入公开日志。

## 真实发布门禁

- `RUN_REAL_ACCESS_INBOUND_MATRIX_E2E`：真实发布默认必须为 `1`，执行用户入站协议矩阵 E2E。
- `RUN_REAL_RUNTIME_RESTORE_DEPLOY`：真实发布默认必须为 `1`，执行真实中转运行态部署恢复，确保门禁后中转节点回到可用状态。
- `REAL_ACCESS_INBOUND_MATRIX_PROTOCOLS`：用户入站协议矩阵，当前矩阵脚本必须覆盖 `vless,trojan,shadowsocks`，全部由 Xray 验证。
- `REAL_ACCESS_INBOUND_MATRIX_EXPECTED_EXIT_IP_VLESS`、`REAL_ACCESS_INBOUND_MATRIX_EXPECTED_EXIT_IP_TROJAN`、`REAL_ACCESS_INBOUND_MATRIX_EXPECTED_EXIT_IP_SHADOWSOCKS`：可选严格出口断言；填入时必须来自真实客户端观测，只能写入私有 env。
- `RUN_REAL_STABILITY_UAT`：真实发布默认必须为 `1`，执行 10 分钟运行态长稳 UAT。
- `RUN_REAL_STABILITY_UAT_24H`：设为 `1` 时追加 24 小时长稳 UAT。
- `UAT_PROFILE`：长稳 profile，当前默认强门禁为 `10m`，`6h` 或 `24h` 仅作为显式追加/扩展 UAT。
- `UAT_DURATION_SECONDS`：`10m` profile 的强门禁时长，当前要求为 `600` 秒，真实值只写私有 env。
- `UAT_ACCESS_NODE_IDS`、`UAT_ACCESS_LINE_IDS`、`UAT_EXIT_ENDPOINT_IDS`：24 小时长稳多副本对象列表，使用逗号分隔 UUID。
- `UAT_CLIENT_PROXY_URLS`、`UAT_EXPECTED_EXIT_IPS`、`UAT_USER_ACCESS_TOKENS`：24 小时长稳多客户端私有列表，使用逗号分隔，值只写私有 env。
- `UAT_STAGE_RETRIES`、`UAT_STAGE_RETRY_DELAY_SECONDS`：长稳单阶段重试次数和间隔，默认 `3` 和 `5` 秒；只有重试后仍失败才记录为 UAT 失败，用于过滤瞬时网络抖动，不得用来掩盖持续业务错误。
- `UAT_AGENT_API_MODE`：默认 `observe`，只观测真实 access-agent 写入状态；只有排障时才设为 `post`。
- `RUN_ACCESS_TRAFFIC_BACKLOG_UAT`：真实发布默认必须为 `1`，执行 access-agent 流量积压恢复 UAT。
- `BACKLOG_VALIDATE_ONLY`：仅用于手工预检，设为 `1` 时只校验环境和目标服务器访问，不阻断控制面或产生恢复流量；真实发布门禁默认不设置。
- `BACKLOG_TARGET_INDEX`：积压恢复 UAT 使用的私有 inventory 目标序号，默认 `2`。
- `BACKLOG_INSTALL_DIR`：目标服务器 access-agent 安装目录，默认 `/opt/xrayc-real-relay`。
- `BACKLOG_WAIT_SECONDS`、`BACKLOG_TRAFFIC_ROUNDS`：积压恢复 UAT 等待窗口和真实客户端流量轮数，默认分别为 `180` 和 `2`。
- `RUN_RUNTIME_LOADTEST`：真实发布默认必须为 `1`，执行运行态大数据压测。
- `RUNTIME_LOADTEST_DATABASE_URL`：运行态压测隔离 PostgreSQL，禁止复用真实发布 `DATABASE_URL`。
- `RUNTIME_LOADTEST_PROFILE`：运行态压测档位，真实发布门禁启用时应为 `large`。
- `RUNTIME_HTTP_LOADTEST_PROFILE`：HTTP/API 运行态压测档位，真实发布强门禁固定运行，默认应为 `large`。
- `RUNTIME_HTTP_LOADTEST_REQUIRE_FULL`：HTTP/API strict full 开关，真实发布强门禁必须为 `1`，缺少用户、管理员或 agent 阶段即失败。
- `RUNTIME_HTTP_LOADTEST_AGENT_CONCURRENCY`、`RUNTIME_HTTP_LOADTEST_AGENT_REQUESTS`、`RUNTIME_HTTP_LOADTEST_AGENT_BATCH_SIZE`：agent 写入阶段使用独立并发、请求数和批量 payload。large 默认应保持用户/API 读接口高并发，同时把 agent 写接口限制为真实控制面上报强度，避免用单个节点模拟上千个 agent 并发行锁竞争；大数据量由隔离 DB large 压测覆盖。
- `RUN_AUTH_HA_UAT`：真实发布默认必须为 `1`，执行多 API 副本认证安全 UAT。
- `RUN_AUTH_HA_STABILITY_UAT`、`AUTH_HA_STABILITY_PROFILE`：真实发布默认必须为 `1`，执行认证多副本长稳 UAT，profile 默认 `10m`，可显式提升为 `6h` 或 `24h`。
- `AUTH_HA_STABILITY_DURATION_SECONDS`：认证多副本 `10m` profile 的强门禁时长，当前要求为 `600` 秒，真实值只写私有 env。
- `RUN_OPS_MISTAKE_RECOVERY_UAT`：真实发布默认必须为 `1`，执行运营误操作恢复 UAT。
- `RUN_OPS_MISTAKE_RECOVERY_LARGE_UAT`、`OPS_MISTAKE_RECOVERY_LARGE_DATABASE_URL`：真实发布默认必须为 `1`，执行大数据误操作恢复演练，数据库必须是隔离 PostgreSQL，禁止复用真实发布库。
- `RUN_REAL_MULTI_USER_TRAFFIC_UAT`：真实发布默认必须为 `1`，执行多用户真实客户端流量 UAT。
- `XRAYC_REAL_MULTI_USER_COUNT`、`XRAYC_REAL_MULTI_USER_DURATION_SECONDS`、`XRAYC_REAL_MULTI_USER_ROUNDS`、`XRAYC_REAL_MULTI_USER_ALLOWED_FAILURES`：多用户真实流量强门禁参数，默认要求 10 个真实客户端容器、每轮 2400 秒、2 轮、每用户每轮最多 3 次瞬时下载或上传失败；真实目标仍来自私有 `XRAYC_REAL_E2E_INVENTORY`。失败容忍只覆盖单次请求级波动，用户 ready、账本、session、endpoint 账本和清理仍必须全部通过。
- `RUN_REAL_SUBSCRIPTION_CLIENT_COMPAT`：真实发布默认必须为 `1`，下载同一份真实订阅并交给 mihomo/clash 转换校验，避免“可下载但客户端导入失败”。
- `RUN_REAL_SUBSCRIPTION_CLIENT_TRAFFIC`：真实发布默认必须为 `1`，在配置校验后优先在私有 inventory 的测试服务器上用 mihomo 容器启动一个真实 mixed proxy，并通过同一份订阅实际代理一次 HTTP 出网；只做配置解析不能替代该闭环。
- `XRAYC_MIHOMO_IMAGE`：本机没有客户端二进制时使用的 Docker 校验/流量镜像；真实值可保持默认镜像或写入私有 env。

## 第三方出口矩阵

当前真实发布必测矩阵为 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2。每个必测协议都必须准备 provider 上游、预期公网出口 IP 和后台 endpoint id；relay 模式由脚本临时生成真实客户端代理，固定客户端代理诊断路径才需要准备对应 `CLIENT_PROXY_URL_*`。provider 上游可使用 raw URL，或使用 host、port 和显式凭据字段拆开填写。

| 协议 | 必填变量 |
| --- | --- |
| SOCKS | `THIRD_PARTY_SOCKS_RAW_URL` 或 `THIRD_PARTY_SOCKS_HOST` + `THIRD_PARTY_SOCKS_PORT`，以及 `EXPECTED_EXIT_IP_SOCKS`、`EXIT_ENDPOINT_ID_SOCKS`；`CLIENT_PROXY_URL_SOCKS` 只在固定客户端代理诊断路径必填 |
| HTTP | `THIRD_PARTY_HTTP_RAW_URL` 或 `THIRD_PARTY_HTTP_HOST` + `THIRD_PARTY_HTTP_PORT` + 凭据，以及 `EXPECTED_EXIT_IP_HTTP`、`EXIT_ENDPOINT_ID_HTTP`；`CLIENT_PROXY_URL_HTTP` 只在固定客户端代理诊断路径必填 |
| VLESS | `THIRD_PARTY_VLESS_RAW_URL` 或 `THIRD_PARTY_HOST`/`THIRD_PARTY_VLESS_HOST` + `THIRD_PARTY_VLESS_PORT` + `THIRD_PARTY_UUID`，以及 `THIRD_PARTY_PUBLIC_KEY`、`EXPECTED_EXIT_IP_VLESS`、`EXIT_ENDPOINT_ID_VLESS`；`CLIENT_PROXY_URL_VLESS` 只在固定客户端代理诊断路径必填 |
| Trojan | `THIRD_PARTY_TROJAN_RAW_URL` 或 `THIRD_PARTY_TROJAN_HOST` + `THIRD_PARTY_TROJAN_PORT` + password/key，以及 `EXPECTED_EXIT_IP_TROJAN`、`EXIT_ENDPOINT_ID_TROJAN`；`CLIENT_PROXY_URL_TROJAN` 只在固定客户端代理诊断路径必填 |
| Shadowsocks | `THIRD_PARTY_SHADOWSOCKS_RAW_URL` 或 `THIRD_PARTY_SHADOWSOCKS_HOST` + `THIRD_PARTY_SHADOWSOCKS_PORT` + method/password，以及 `EXPECTED_EXIT_IP_SHADOWSOCKS`、`EXIT_ENDPOINT_ID_SHADOWSOCKS`；`CLIENT_PROXY_URL_SHADOWSOCKS` 只在固定客户端代理诊断路径必填 |
| Hysteria/HY2 | `THIRD_PARTY_HY2_RAW_URL` 或 `THIRD_PARTY_HY2_HOST` + `THIRD_PARTY_HY2_PORT` + password/auth/key，可选 `THIRD_PARTY_HY2_SERVER_NAME`/`THIRD_PARTY_HY2_SNI` 和 `THIRD_PARTY_HY2_ALLOW_INSECURE`，以及 `EXPECTED_EXIT_IP_HY2`、`EXIT_ENDPOINT_ID_HY2`；`CLIENT_PROXY_URL_HY2` 只在固定客户端代理诊断路径必填 |

`*_RAW_URL` 必须来自 provider 控制台或私有文件，不能由脚本根据 host 猜测。`CLIENT_PROXY_URL_*` 必须来自真实客户端；`EXPECTED_EXIT_IP_*` 可由 `make observe-real-client-env` 通过对应真实客户端代理观测写入，不能由数据库、订阅内容或中心侧请求伪造。

## 通过标准

- `make check-real-release-env` 输出 `real-release-env: passed`。
- `make real-release-gap-report` 所有必填分组均显示 `ready`，运行观测轮询显示 `optional/defaulted` 或合法整数配置。
- `make check-real-release` 完成真实订阅下载、真实 Playwright no-mock、Worker smoke、真实 Agent 安装脚本、access-agent 运行观测、relay 模式六类第三方出口矩阵测试、access-agent 流量积压恢复 UAT、隔离 DB large 压测和隔离 HTTP/API strict large 压测，并同时满足最终退出码 0 和日志包含 `real-release-gate: status=0`，才能作为完整强门禁通过证据。
- 启用真实发布门禁时，长稳 UAT、流量积压恢复 UAT、运行态压测、认证 HA UAT 和误操作恢复 UAT 都必须只输出阶段状态和脱敏失败摘要。
- 公开日志、日报、测试报告和提交信息中不得出现真实值。
