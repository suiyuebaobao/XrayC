# 真实测试用例

## 测试原则

真实测试用于验证 XrayC V2 Rust-only 接入代理控制面链路：Agent 安装、access-agent、Xray 配置、订阅可用性、出口管理路由、流量上报和计费闭环。核心边界是接入节点强控制、出口资源弱管理；第三方或普通自建出口必须先进入统一出口管理，再由入口管理绑定成订阅节点，分组只选择入口出口绑定节点，运行订阅只暴露中转入口。测试服务器必须使用用户提供的真实测试服务器；清单、凭据位置和真实凭据文件路径只允许保存在仓库忽略的本机私有位置。测试服务器信息只能从本机私有记录或安全环境变量读取，禁止写入 Git、公开文档、日志输出或提交说明。

所有真实测试口径必须围绕 V2 接入代理控制面：中心控制面下发配置到固定运行 `xray-core` 和 `access-agent`（单内核 Xray）的中转节点，所有入口都由 Xray 处理；客户端只连接订阅中的中转入口，出口只作为中转节点运行配置引用的出口管理资源。旧 `node-agent` 直连、客户端直连出口、中心侧直连出口或独立出口代理均不是当前主线。本机出口服务专项测试必须支持多协议、服务地址、监听端口和协议配置，并验证其只进入出口管理；后续由入口管理绑定线路生成订阅节点，再由分组归类绑定节点。

产品主路径固定为：先维护统一出口管理中的真实出口线路，再通过入口管理创建中转入口并绑定线路，随后在分组里选择入口出口绑定节点，套餐直接授权分组。本机出口服务登记后也是出口管理中的普通线路。`access_entries`、`access_entry_exit_bindings`、`line_group_binding_nodes`、`access_lines`、`line_groups` 和 `plan_line_groups` 只作为内部订阅来源、授权范围和运行兼容实现，不作为真实测试报告中的运营步骤主语；测试步骤可以引用这些表做断言，但用户可见叙述必须保持“出口管理 -> 入口管理 -> 入口出口绑定节点 -> 分组 -> 套餐授权 -> 订阅只暴露中转入口”。

每次执行真实服务器测试、目标服务器 Agent 安装、目标服务器清理或目标服务器连通性验证前，必须重新读取最新的本机私有测试服务器清单；用户说明清单已更新时，视为测试资产发生变化，禁止沿用记忆里的旧服务器、旧账号、旧角色或旧用途。完整性测试至少需要 3 台真实服务器：一台临时真实客户端执行机、一台中转接入节点、一台出口宿主；清单提供更多服务器时，应全部纳入资产预检和可用节点管理。存在额外非 CF 可用服务器时可作为第二出口宿主；不存在额外非 CF 服务器时，第二出口用出口宿主的不同端口复用。当前私有角色约定中 `server_1` 是直连/非 CF 目标，`server_4` 是 Cloudflare/橙云目标，只用于 CDN/橙云入口验证。V2 当前简化模型的最小闭环为 1 台中转接入节点 + 1 条可分配出口线路 + 1 个入口出口绑定节点，多出口只作为分组冗余能力，不作为必需条件；多中转副本验收时参与副本的节点都必须部署 access-agent 并进入订阅、心跳、真实流量和账本验证。

公开测试文档只记录步骤、断言、命令模板、结果摘要和遗留风险，不记录真实 IP、真实域名、密码、Token、代理凭据或订阅链接。真实测试域名统一称为“私有清单域名”；公开文档、日报和报告统一写“私有清单域名”，不得写入真实域名、可解析主机名或私有清单字段结构。

涉及前端页面、登录注册、订阅展示、管理后台、运营中心运行数据、关键用户路径或 Docker 真实运行链路时，必须同时运行 Playwright 浏览器 smoke 和 `scripts/real-smoke.sh` 真实链路 smoke。Playwright smoke 可用受控路由验证 UI 状态、空值展示和按钮交互；运营中心真实在线、连接数、上下行速率和探测延迟必须以 `runtime-no-mock`、真实接口 smoke 或 curl 模板作为完成证据。真实链路 smoke 应验证健康接口、套餐接口、订阅下载和敏感出口信息不泄露；涉及运行数据接口时，还必须用 curl 或脚本模板验证 `/api/agent/access/metrics`、`/api/agent/access/sessions` 和 `/api/agent/access/probes` 的鉴权、字段校验和汇总展示。执行命令、通过条件和失败截图或日志必须写入当天日报或测试报告。

用户订阅页和用户订阅接口当前统一使用“可用节点”口径。真实测试必须断言 `GET /api/user/subscription` 的可用节点条目返回 `line_group_name`，前端归一为 `lineGroupName` 后展示入口所属分组；页面标题和说明不得再把内部 `line_groups` 写成用户侧“节点分组”。订阅 YAML 中节点名必须体现入口出口绑定节点名称，且不输出入口或分组 `icon` 字段；普通 `select proxy-groups` 必须显示套餐授权分组，组内包含该分组内绑定节点对应的已启用、已同步且可连接中转入口代理项。

真实订阅测试只验证 `/sub/{token}` 可导入、响应头包含订阅用量、订阅不泄露真实出口，并覆盖同一套餐、同一分组、中转入口和 access-agent 用户级账本。

测试执行采用分层门禁。每轮先用 `make check-plan` 查看当前改动需要的最小验证清单，再用 `make check-affected` 执行当前影响范围的最小验证；小改优先运行受影响包级测试、`make check-fast` 或前端单独构建；中等改动追加 `make check-smoke`、PostgreSQL 集成测试或 Playwright 单测；大改、最终交付、依赖变更、Dockerfile、Compose、迁移或部署脚本变化时再执行 `make check-release`、必要的 Docker rebuild、Playwright smoke 和真实链路 smoke。`make check-release` 是本地完整发布门禁，覆盖 Rust 格式、Clippy、workspace 测试、临时 PostgreSQL 集成测试、前端构建、脚本语法、防泄露、隔离 Docker runtime、Worker smoke、真实 smoke、严格 API contract、Playwright smoke 和 Compose 校验，不要求私有真实供应商 env。Dockerfile、Compose、Caddy 或运行时依赖变化还必须执行 `make check-docker-runtime`，该门禁用临时 `COMPOSE_PROJECT_NAME` 和临时本地端口启动当前 Compose 构建，等待服务健康后运行真实 smoke、严格 API contract 和 Playwright no-mock 用例，结束后只清理该临时 project，不得停止当前 `xrayc` 项目服务。`make check-postgres-integration` 必须确保 `test_pg_` PostgreSQL 集成测试真实执行，不得因缺少 `DATABASE_URL` 被跳过；`make check-worker-smoke` 必须验证 Worker 维护任务结果，不得只以容器 running/healthy 作为完成证据。日常验证不得把 `docker compose up --build`、`npm ci` 或 `make package-docker-artifacts` 作为每次改动后的默认动作；subagent 只跑职责范围内的最小测试，主 Agent 集成后统一跑一次高成本门禁。

真实发布门禁使用 `make check-real-release`，只能在私有 env 齐全的环境运行。脚本会自动加载未跟踪的 `.env.real-release`；如需使用其他私有路径，设置 `XRAYC_REAL_RELEASE_ENV_FILE=/absolute/private/env/path`。首次准备或私有资产变更后，可先运行 `make bootstrap-real-release-env` 从本机私有 inventory、私有 token 文件、当前 Compose PostgreSQL 和本地登录接口生成 `.env.real-release` 草稿；该脚本只输出变量数量，不输出真实 token、密码、IP、订阅链接、代理 URL 或数据库 URL。协议矩阵资产可用 `XRAYC_SERVER_ACCOUNT_FILE=<private-server-account-file> bash scripts/prepare-real-protocol-matrix-assets.sh` 准备；脚本按当前清单检查 SSH/Docker/Compose 能力，至少要求 3 台真实服务器，客户端和上游样例只作为临时测试进程或容器运行，只输出角色级状态、私有 env/inventory 草稿路径和缺口摘要，不打印真实地址、账号、密码、Token、代理 URL 或目标服务器 stderr。如需自建真实上游样例，追加 `--deploy-upstream-lab` 或设置 `XRAYC_REAL_PROTOCOL_UPSTREAM_LAB=1`，脚本会调用 `scripts/real-protocol-upstream-lab.sh` 在私有测试服务器上以临时容器方式部署当前必测的 SOCKS、HTTP CONNECT、VLESS、Trojan、Shadowsocks 和 HY2 样例，并把真实上游 host、凭据、raw URL、协议 key 别名和观测出口 IP 只写入未跟踪私有 env 草稿。relay 模式的 `scripts/real-access-third-party-matrix-relay-e2e.sh` 使用同一 inventory，支持密码文件或无口令私钥文件：后台只生成中转节点安装说明，由受控测试执行器或管理员在目标服务器本地执行安装脚本；真实客户端动作临时运行，六协议逐个强制切换出口 endpoint，验证真实出口 IP、`usage_ledgers.traffic_source=access_line` 增量和用户订阅 `used_bytes` 增量，并断言订阅与用户订阅接口不泄露第三方 host、账号、密码、UUID、公钥、key 或 raw URL；同一轮还必须覆盖禁用用户和配额耗尽两种剔除场景，断言订阅移除该中转入口、access-agent 应用新配置后客户端不能继续通过该入口出站，恢复后订阅和真实出站重新可用。执行高成本真实发布前，再运行 `make check-real-release-env`，它只检查变量完整性、占位符和私有文件存在性，不触发目标服务器 SSH、真实部署或三方流量。真实发布门禁必须覆盖真实订阅下载与客户端导入、真实 Playwright no-mock、Worker 维护任务 smoke、真实 access-agent 指标/会话/探测/流量上报、真实目标服务器接入节点安装、自建出口管理真实出站链路，以及三方出口协议矩阵 `socks`、`http`、`vless`、`trojan`、`shadowsocks`、`hy2`；用户入站矩阵脚本必须覆盖 `vless,trojan,shadowsocks`，全部由 Xray 验证。所有必测协议都必须走真实供应商或自建真实上游、真实接入节点和真实客户端流量，不能使用 mock、模拟订阅、伪造出口、中心侧请求或脚本构造值冒充发布验收。完整发布只接受 `make check-real-release` 最终输出 `real-release-gate: status=0` 且退出码为 0；中途 `gate:`、validate-only、单协议或单项压测通过只能作为局部证据。

订阅客户端兼容门禁必须同时完成格式解析和真实客户端流量：mihomo/Clash 要优先在测试服务器上用同一份订阅启动真实代理并完成一次 HTTP 出网；只运行 `-t`、`check` 或 YAML 解析不能作为客户端闭环证据。

当前真实发布记录按层级管理：强门禁必须覆盖本机出口服务真实 E2E、三方出口协议 E2E 必测矩阵、真实服务器本地 Agent 安装验证、真实 access-agent 观测、真实订阅导入、账本扣费、10 分钟长稳、隔离 DB large 压测、隔离 HTTP/API strict large 压测、多副本认证 UAT、认证多副本 10 分钟长稳、运营误操作恢复和隔离大数据误操作恢复；6h/24h 长稳属于显式追加或扩展 UAT。追加 UAT 未执行时，报告只能写“未执行追加 UAT”，不能把它写成强门禁通过证据。测试只验证单一套餐额度、统一账本扣费、入口出口绑定节点后的内部出站映射、订阅防泄露和 access-agent 上报，且不得删除第三方出口对接或普通自建上游出口测试。

三方出口协议矩阵只代表上游出口协议覆盖，不代表用户入站协议覆盖。当前用户入站订阅支持 VLESS、Trojan、HY2、Shadowsocks 2022；HTTP、SOCKS、VMess 和旧 `aes-*-gcm` Shadowsocks 不作为用户入站。Trojan/HY2 用户入站必须启用 TLS，入站协议矩阵中不得接受明文 Trojan 或无证书 HY2 作为通过证据。Shadowsocks 入站矩阵必须验证订阅密码形态和服务端实际入站鉴权一致：只有 2022 系列方法可进入用户订阅和用户级计费，订阅密码必须为 `server:user` 形态；旧 `aes-*-gcm` 只能作为内部或出口协议，不允许出现在用户订阅、用户级路由或计费主链路。入站矩阵由 Xray `vless/trojan/shadowsocks` 验证。

真实 Playwright no-mock 门禁必须使用 `frontend/e2e/runtime-no-mock.spec.ts` 访问真实后端接口，变量为 `E2E_BASE_URL`、`E2E_USER_ACCOUNT`、`E2E_USER_PASSWORD`、`E2E_ADMIN_ACCOUNT` 和 `E2E_ADMIN_PASSWORD`；`make check-real-release` 会在 `real-playwright-no-mock` 步骤自动传入这些私有 env。该门禁禁止 `page.route` mock、静态 fixture、伪造订阅响应或 skipped 用例冒充通过，测试报告只记录脱敏命令和通过/失败摘要，不记录真实账号、密码、Token、Cookie 或响应体。

中心侧定时主动探测用于验证中转入口探测、`access_node -> exit_endpoint` 组合探测、探测延迟、阈值状态和探测队列新鲜度，服务于运营中心展示和当前接入节点出口 failover。Worker 会按运营策略把到期组合探测写成 `queued` 任务，access-agent 下一次心跳领取后复用 `/api/agent/access/probes` 回报结果；租约反复过期且投递次数达到上限后，Worker 必须将任务转成 `timeout` 结果并推动组合状态机，避免 queued 任务永久占用 pending 配额。该调度只证明队列和组合健康状态机，不替代真实客户端经订阅中转入口出站，不能用中心机请求公网 IP 冒充用户出口，不能用中心侧构造值代替 access-agent 本机 metrics/sessions/probes 上报或 `usage_ledgers.traffic_source=access_line` 计费。

真实长稳 UAT 使用 `scripts/real-runtime-stability-uat.sh`，真实发布门禁默认由 `make check-real-release` 执行 10 分钟，也可单独执行 `bash scripts/real-runtime-stability-uat.sh`。脚本自动加载 `.env.real-release` 或 `XRAYC_REAL_RELEASE_ENV_FILE`；必需变量为 `BASE_URL`、`DATABASE_URL`、`SUB_TOKEN` 或 `SUBSCRIPTION_URL`、`CLIENT_PROXY_URL`、`EXPECTED_EXIT_IP`、`ACCESS_NODE_ID`、`ACCESS_LINE_ID`、`EXIT_ENDPOINT_ID`、`USER_ACCESS_TOKEN`，可选变量为 `PUBLIC_IP_URL`、`UAT_PROFILE`、`UAT_DURATION_SECONDS`、`UAT_POLL_INTERVAL_SECONDS`、`UAT_RUNTIME_WARMUP_SECONDS`、`UAT_RUNTIME_STALE_SECONDS`、`UAT_MAX_QUEUED_PROBE_AGE_SECONDS`、`UAT_CLIENT_TRAFFIC_URL`、`UAT_CLIENT_TRAFFIC_RATE`、`UAT_CLIENT_TRAFFIC_MAX_TIME_SECONDS`、`UAT_POST_TRAFFIC_SETTLE_SECONDS`、`UAT_STAGE_RETRIES`、`UAT_STAGE_RETRY_DELAY_SECONDS` 和 `UAT_AGENT_API_MODE=observe|post`。默认 `UAT_AGENT_API_MODE=observe`，只观测真实 access-agent 写入的心跳和配置应用状态；只有显式设置 `post` 才允许脚本主动调用 heartbeat/config-result 辅助检查。默认 `UAT_PROFILE=10m`，要求至少 600 秒；显式 `UAT_PROFILE=6h` 要求至少 21600 秒；`RUN_REAL_STABILITY_UAT_24H=1 make check-real-release` 会强制 `UAT_PROFILE=24h`，要求至少 86400 秒，并默认要求至少 2 个用户 token、2 个中转节点、2 个中转入口/出口副本，变量为 `UAT_USER_ACCESS_TOKENS`、`UAT_ACCESS_NODE_IDS`、`UAT_ACCESS_LINE_IDS`、`UAT_EXIT_ENDPOINT_IDS`、`UAT_CLIENT_PROXY_URLS` 和 `UAT_EXPECTED_EXIT_IPS`，均使用逗号分隔。脚本循环验证健康接口、订阅下载防泄露、真实客户端代理出口 IP、真实下载流量、运行态 metrics/sessions/probes 新鲜度、非 queued 组合探测、探测队列无长期积压和账本增长；单阶段默认最多重试 3 次，重试后仍失败才记录失败；输出只能包含阶段状态、迭代号和脱敏失败摘要。低成本门禁可运行 `make check-real-release-gate-profiles`，该目标只校验 profile 和变量形态，不连接真实服务器、不执行长稳循环。

7. 检查目标服务器 `docker compose ps`，确认 Xray 和 `access-agent` 容器均运行中。
8. 检查 access-agent 心跳。
9. 检查心跳响应的 `config_status`、`config_hash`、`desired_config_version` 和 `config`。
11. 检查 Xray 配置应用结果，并上报 `/api/agent/access/config-result`。
12. 检查接入端口由 Xray 监听。
13. 检查安装脚本摘要只包含步骤状态和错误摘要。

目标服务器命令模板：

```bash
XRAYC_CONTROL_PLANE_URL="https://example.com" \
XRAYC_DEPLOY_ARTIFACT_TOKEN="<set-in-env>" \
bash scripts/deploy-access-agent.sh
```

断言：

- `bash -n scripts/deploy-access-agent.sh` 通过。
- `bash -n scripts/real-remote-access-deploy-e2e.sh` 通过；脚本只打印目标别名和步骤结果，不打印真实 SSH 主机、密码、Token、订阅链接或数据库 URL。
- 一键安装接口返回部署任务摘要，并在成功后能查到自动创建的中转节点；手动安装说明接口只返回 `status=ready`，表示说明已生成，不代表服务器已经安装成功。
- 一键安装请求中的 SSH 密码、私钥内容或私钥路径不得出现在响应体、部署任务、审计日志、公开日志或前端任务列表；手动安装说明接口不包含 SSH 字段。
- 脚本从中心 API 下载 manifest、access-agent 镜像包、xray 镜像包和 sha256 清单，执行 `sha256sum -c`，再执行 `docker load`；中心产物清单必须包含 xray 镜像包，避免缺产物。
- 脚本写入节点侧 Docker Compose 文件和必要环境文件，并执行 `docker compose up -d` 启动或更新 Xray 与 `access-agent` 容器。
- 第一版验收不得以 systemd service 作为默认运行方式或成功标准。
- 默认部署不得执行 `systemctl daemon-reload` 或清理 systemd unit；只有显式设置 `XRAYC_DISABLE_LEGACY_SYSTEMD_UNITS=true` 时，才允许清理本项目旧 unit。
- 目标服务器缺少 Docker 时，部署脚本可以启动 Docker 服务，但不得重启 SSH 服务、结束 SSH 进程或断开用户会话。
- 脚本不执行 `pkill ssh`、`killall ssh`、`systemctl restart ssh`、`systemctl restart sshd` 或等价会中断 SSH 的命令。
- 一键安装响应、手动安装说明响应、安装脚本摘要、脚本输出和审计摘要不含 SSH 密码、完整 Token、私钥内容、私钥路径、第三方代理凭据、真实目标地址或私有安装路径。
- `deploy-access-agent.sh` 的完成日志不得输出 `XRAYC_INSTALL_DIR` 或包含安装目录的 `docker compose -f ...` 命令，只能输出脱敏状态检查提示。
- 目标服务器 Compose 必须把 Xray 配置目录整体挂载到 Xray 和 `access-agent` 的对应配置目录，不得单文件挂载 `config.json`。
- access-agent 应用有效配置、空配置和恢复配置后，宿主配置文件、access-agent 容器内目标 `config.json` 和 Xray 容器内目标 `config.json` 内容必须一致；真实测试需要用 hash 或等价方式断言三处一致。
- access-agent 主动回连中心。
- `config_status.required=true` 时心跳返回非空 `AccessConfig`，其中 `routing_rules.user_email` 等于 Xray client 的中转入口作用域 `email`，格式为 `xrayc-line-<access_line_id>--<xray_user_key>`。
- 重装、清空状态目录或迁移到新服务器后的 access-agent 首次心跳没有 `applied_config_version` 时，中心必须重新下发当前 `AccessConfig`，即使数据库保留旧 `applied_config_hash` 也不能返回 `config: null`。
- 当前阶段 `AccessConfig.exit_endpoints` 主流程覆盖运行成员中的 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 上游出口，也覆盖中转节点本机出口服务生成的多协议 endpoint。第三方供应商出口必须继续用真实公网 E2E 验证出站 IP、账本扣费和订阅防泄露。
- `/api/agent/access/config-result` 成功但未回传 hash 时不能清理 dirty；成功且 hash 匹配 `desired_config_hash` 后才清理 dirty。
- `/api/agent/access/config-result` 即使 hash 匹配，也不能清理晚于该回执产生的新 dirty 状态；线路、分组、入口、用户授权或配额变更后必须清空旧 `desired_config_hash` 并强制下一轮配置重算。
- `config_status.required` 在配置应用成功后变为无需刷新。
- 接入端口监听来自 Xray inbound，不把 outbound 上游端口误判为本机监听端口。
- `scripts/real-remote-access-deploy-e2e.sh` 必须从私有清单读取目标服务器参数，覆盖一键自动 SSH 安装或受控测试执行器触发的同一安装脚本，完成 Docker 镜像下载、`docker load`、Compose 启动、节点鉴权码生成、平台自动创建中转节点、状态哈希落盘和可选期望监听端口检查；失败输出只能是脱敏摘要。
- 真实发布门禁默认执行 `scripts/check-agent-install-cleanup.sh`，覆盖服务器侧安装失败清理契约：失败清理只在部署脚本实际开始后触发，默认只清理本次新建的安装目录和本次 Compose 项目，不清理部署前已存在的目录，不执行本地 `docker compose down`，也不停止或重启 SSH。
- 公开公网环境默认要求 HTTPS；目标服务器本地安装验收对 `http://` 控制面默认失败，仅私有测试环境尚未配置 TLS 时，允许通过内部测试开关临时使用 HTTP 控制面地址，测试报告只能记录脱敏结果，不得记录真实地址。
- 重复生成手动安装说明不会生成 access-agent 凭证或覆盖有效运行配置；凭证只在服务器安装脚本本地生成或复用。一键安装成功后只保存节点 token 哈希和脱敏任务结果，不保存 SSH 凭据。

## 用例 3：订阅下载防泄露

目标：验证 `/sub/{token}` 只输出中转入口，不泄露出口信息。

步骤：

1. 创建测试用户和有效订阅。
2. 创建套餐授权分组。
3. 下载订阅 YAML。
4. 检查 YAML 中的 server、port、协议字段。
5. 检查 YAML 中不存在出口 endpoint 地址、第三方代理 URL 和敏感凭据。
6. 使用 Clash/mihomo 客户端导入订阅并通过该订阅实际代理一次 HTTP 出网。
7. 使用用户 Access Token 请求 `GET /api/user/subscription`，检查可用节点条目包含 `line_group_name`，且不含出口 host、账号密码、原始代理 URL 或旧 `line_group_icon` 字段。
8. 调整套餐分组授权或分组内绑定节点启停，重复下载订阅并检查可用节点随授权和绑定节点可用性变化。
9. 禁用某个已分配中转入口，再次下载订阅并检查是否剔除该入口，且同一分组下存在可用入口时补齐替换。
10. 管理员调用 `GET /api/admin/users/{id}/devices`，确认成功订阅拉取来源写入 IP 观察列表；再使用真实 Clash/mihomo 客户端产生节点流量，确认同一明文 IP 合并为一条并显示订阅拉取与节点使用两类来源。

断言：

- 订阅是 Clash/mihomo YAML。
- 订阅入口地址只来自内部 `access_lines.listen_host/listen_port`。
- 订阅节点显示入口出口绑定节点名称；普通 `select proxy-groups` 显示套餐授权分组名称，组内代理项是该分组下的绑定节点；订阅 YAML 不输出入口或分组 `icon` 字段；同名节点或分组必须自动避让，避免客户端校验失败或合并。
- 分组绑定的规则库必须出现在订阅通用规则之前；同一规则库绑定多个分组时，每个分组都必须输出目标指向自身的规则；`DIRECT`、`REJECT`、`REJECT-DROP` 必须保持原动作；最终 `MATCH` 必须指向套餐配置的默认出口分组，默认分组不可用时回退到该套餐第一个可用分组，未匹配到任何规则时默认走代理。
- `GET /api/user/subscription` 返回的可用节点包含 `line_group_name`，且不返回旧 `line_group_icon`；前端展示口径为“可用节点”，不得把内部 `line_groups` 直接写成用户侧“节点分组”。
- 订阅节点协议只由中转入口入站协议决定：VLESS 输出 VLESS，Trojan 输出 Trojan，HY2 输出 `hysteria2`，Shadowsocks 2022 输出 `ss`；HTTP、SOCKS、VMess 和旧 `aes-*-gcm` Shadowsocks 入站不得被渲染或回退成 VLESS。
- Shadowsocks 用户入站只有 2022 系列方法可进入订阅，订阅密码为 `server:user` 形态；旧 `aes-*-gcm` 只能作为内部或出口协议，不能出现在用户订阅、用户级路由或计费断言中。
- 未绑定可用分组或授权分组下没有可用节点时返回“当前套餐没有可用线路”兼容业务错误；文档语义解释为没有可用节点。
- 同一用户重复拉取订阅时，已分配中转入口保持稳定，不因刷新订阅随机变化。
- 套餐不提供节点数量策略；真实测试只确认“授权分组内绑定节点对应的已启用、已同步且可连接入口”会进入订阅。
- 已分配入口禁用后，订阅会剔除该入口，并在同组有可用入口时补齐替换。
- 订阅中不得出现出口 host、第三方 UUID、公私钥、密码、完整代理 URL。
- 订阅下载日志只记录用户、中转入口数量、请求结果和 request id，不记录 Token 原文。
- 后台设备管理 IP 观察列表只面向管理员，显示订阅拉取来源和节点使用来源的合并结果；普通用户接口、订阅 YAML、公开日志和测试报告不得回显该列表或完整订阅链接。

## 用例 3.1：后台套餐 CRUD 与授权矩阵

目标：验证后台套餐 CRUD、基础套餐保护、公共套餐过滤和中转入口授权范围字段与 V2 方案一致。

前置条件：

- 使用测试 PostgreSQL 数据库或隔离测试环境，不在生产库创建临时套餐。
- 已有基础套餐，且 `is_default=true`、`enabled=true`。
- 已准备至少一个包含可用中转入口的测试授权范围。

接口矩阵：

| 路径 | 方法 | 类型 | 默认 smoke | 执行标准 |
|------|------|------|------------|----------|
| `/api/plans` | `GET` | 只读公共接口 | 是 | 2xx；只返回 `enabled=true` 且 `is_deleted=false` 的套餐 |
| `/api/admin/plans` | `GET` | 只读后台接口 | 鉴权边界 | 未登录 401/403；管理员 JWT 2xx；返回基础套餐标识和授权摘要 |
| `/api/admin/plans` | `POST` | 写接口 | 否 | 测试库创建普通套餐，不允许创建第二个基础套餐 |
| `/api/admin/plans/{id}` | `PATCH` 或 `PUT` | 写接口 | 否 | 普通套餐可改名、额度、倍率、启停；基础套餐必须保持启用 |
| `/api/admin/plans/{id}` | `DELETE` | 写接口 | 否 | 基础套餐删除返回业务错误；普通套餐逻辑删除并迁移活动订阅 |
| `/api/admin/plans/{id}/line-groups` | `PUT` | 写接口 | 否 | 替换分组授权和分组倍率 |

步骤：

1. 不带管理员 JWT 请求 `GET /api/admin/plans`，确认返回 401/403。
2. 管理员请求 `GET /api/admin/plans`，确认基础套餐存在、启用且有 `is_default=true` 标识。
3. 在测试库创建一个普通套餐，字段覆盖单一套餐额度、倍率、时长和 `enabled=true`。
4. 调用 `PUT /api/admin/plans/{id}/line-groups` 绑定测试分组授权范围和倍率，确认当前订阅输出以授权分组内绑定节点对应的已启用、已同步且可连接入口为准。
5. 调用公共 `GET /api/plans`，确认新套餐可见；停用该套餐后再次请求，确认公共列表不可见。
6. 尝试停用基础套餐，确认服务端拒绝或强制保持 `enabled=true`。
7. 创建一名临时用户并开通普通测试套餐订阅，随后删除该普通套餐。
8. 查询临时用户订阅、`plan_line_groups`、`user_access_line_assignments`、`user_exit_assignments` 和接入节点 dirty 状态。
9. 清理临时用户、测试套餐、授权、订单或兑换码数据。

断言：

- 后台套餐 CRUD 路径统一为 `GET/POST/PATCH(or PUT)/DELETE /api/admin/plans`，不新增其他别名。
- 公共 `GET /api/plans` 不返回 `enabled=false` 或 `is_deleted=true` 的套餐。
- 基础套餐不可删除，且必须保持启用。
- 普通套餐逻辑删除后，活动订阅迁移到基础套餐，已删除套餐不再可购买。
- 删除普通套餐会清理相关套餐授权和用户分配，并标记接入节点配置 dirty。
- 授权项语义是分组授权；套餐 UI 不提供节点数量策略。
- 测试报告只记录脱敏命令模板、HTTP 状态码、字段断言和清理结果。

### 破坏性 CRUD 与误操作恢复边界

适用范围：套餐删除迁移、授权范围成员收缩、内部兼容成员替换和中转入口出站映射切换。此类测试只能在临时 PostgreSQL 数据库、事务隔离环境或由测试用例创建的临时 UUID 数据上执行；禁止对生产/真实节点、真实出口资源、真实用户订阅执行不可逆删除。

临时数据执行标准：

- 套餐删除测试必须创建普通临时套餐和临时用户订阅，删除后断言套餐为逻辑删除，活动订阅迁移到基础套餐，分组授权、`user_access_line_assignments` 和 `user_exit_assignments` 中该用户旧分配被清理，接入节点 `config_dirty_reason` 标记为套餐删除。
- 授权范围收缩测试必须创建临时分组和临时中转入口，先确认用户入口授权完整，再将授权范围或分组绑定节点范围缩小，重新拉取订阅后断言失效入口从订阅和 `user_access_line_assignments` 中消失。
- 内部兼容成员替换测试必须创建临时出口资源、临时中转入口和必要的内部兼容映射，先分配到 primary 成员，再将 primary 成员置为 `offline` 或禁用 endpoint，重新拉取订阅后断言迁移到 healthy backup 成员，`failover_reason=failover:unavailable`。
- 出口管理 endpoint 删除/修改测试必须断言运行兼容成员、`user_exit_assignments`、`user_access_line_assignments`、`/sub/{token}` 和 `access_nodes.config_dirty` 状态一致，不能留下已删除或不可用出口引用。
- 中转入口出站映射切换测试必须只使用临时中转入口和临时内部兼容数据，断言该入口旧 `user_exit_assignments` 被清理、对应接入节点 dirty，不允许切换真实运行入口的内部兼容数据。
- 误操作恢复测试必须先恢复临时出口或临时中转入口可用状态，再触发下一次订阅或 heartbeat 自动收敛；通过标准是旧错误分配被删除，重新生成可用分配，dirty reason 记录本次恢复标记，订阅仍不泄露出口 host、UUID、密码或代理 URL。

## 用例 5：出口可用性收敛

目标：验证组合探测达到失败阈值后，订阅输出和 agent 配置会移除或暂停不可用入口。

步骤：

1. 记录测试用户当前订阅节点和 agent active config。
2. 在运营中心确认探测策略，例如连续失败阈值 3、连续恢复阈值 2、窗口 10 分钟。
3. 连续上报同一 `access_node_id + exit_endpoint_id` 的失败探测，次数未达到阈值时不应改变订阅输出。
4. 达到失败阈值后，等待中心写入 `access_exit_probe_states.effective_status=offline` 并标记相关接入节点配置 dirty。
5. 等待 access-agent 应用新配置；SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 出口均需通过 heartbeat `AccessConfig` 验证，第三方公网链路当前强门禁按 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 执行真实 E2E。本机出口服务应按默认主流自建协议 VLESS、HY2、Shadowsocks、Trojan 通过专用动作做专项能力验证，并确认只写入统一出口管理、记录所属中转服务器、可被分组选择。
6. 连续上报恢复探测，达到恢复阈值后确认组合状态恢复为 `healthy`，并在下一次同步中重新生成订阅输出和 agent 配置。
7. 使用真实客户端再次出站。

断言：

- 不可用入口从订阅输出和 agent active config 中移除或暂停。
- `access_exit_probe_states.effective_status` 与接入节点 dirty 状态一致。
- access-agent 配置刷新成功。
- 出口恢复后必须通过探测或人工确认，再重新进入订阅输出和 agent 配置。
- 历史分配和探测记录可审计。
- 被置为 `offline` 的组合状态不会继续进入当前接入节点新配置。
- 同一个出口被其他接入节点引用时，不能因为当前接入节点探测失败而被全局摘除。

## 用例 6：流量上报与扣费

目标：验证 access-agent 累计流量快照按差值入账。

步骤：

1. 清理测试用户历史临时账本或记录测试前基线。
2. 使用真实客户端产生可观测流量。
3. 在接入节点确认 Xray 配置包含 `api.services=["StatsService"]`、`xrayc-api` 本地 API inbound、`stats`、用户级 `policy` 和 `inboundTag=["xrayc-api"] -> outboundTag="xrayc-api"` routing。
4. 等待 access-agent 通过 `xray api statsquery --server=$XRAYC_XRAY_API_SERVER -pattern 'user>>>'` 读取到非零累计值，并上报 `/api/agent/access/traffic`。
5. 查看 `access_traffic_snapshots` 和 `usage_ledgers`。
6. 再次产生流量并等待下一轮上报。
7. 构造一条受控乱序补发快照，验证中心拒绝重复入账。

断言：

- 第一条基线快照不扣费。
- access-agent 上报的每条快照都包含 `access_line_id`，并且该中转入口属于当前接入节点。
- 后续账本只记录累计值差值。
- `usage_ledgers.traffic_source=access_line`。
- 账本包含 `access_line_id`，并在可解析时包含 `exit_endpoint_id`。
- 乱序或小于上一快照的累计值不得重复扣费。
- PostgreSQL 中的账本记录可按用户、中转入口和采集时间追溯到原始快照。

断言：

- 过期订单变为 `expired`。
- 过期基础套餐订阅重置为新的基础周期；过期付费套餐订阅切回基础套餐；禁用、超额或无有效授权的用户才会在 agent 授权中被剔除。
- 该用户的中转入口分配和出口分配被清理。
- 接入节点被标记 `config_dirty=true`，原因是订阅过期维护。
- 过期 Refresh Token、验证码挑战和登录锁状态被清理，未过期数据保留。
- 超过运行态保留期的 metrics、traffic snapshots、sessions、probes 被清理；超过后台运营策略 `traffic_log_retention.detail_retention_days` 的 `usage_ledgers` 明细会先汇总到 `usage_daily_rollups` 和 `usage_hourly_rollups` 后删除；`audit_logs` 和 `payment_records` 不被该维护任务删除。
- 数据库自动备份启用且到期时，`DATABASE_BACKUP_DIR` 下生成 `xrayc-postgres-*.dump`，`site_settings.database_backup_state` 写入 `status=success`、`last_success_at` 和 `last_file_name`；超过 `database_backup.retention_days` 的旧 dump 会被清理，日志不得输出完整 `DATABASE_URL` 或数据库密码。
- Worker 按 `access_operations.probe_policy.exit_probe_interval_seconds`、`probe_queue_batch_size` 和 `max_pending_probe_tasks` 写入 `access_exit_probes.status=queued`，同一组合已有未完成 queued 任务时不得重复排队。
- queued 探测只会在下一次 access-agent 心跳中作为 `probe_tasks` 下发，不能被当作真实成功或失败探测结果；只有 agent 回报非 queued 结果后才参与组合状态阈值。
- Worker 日志只输出处理数量和错误摘要，不输出数据库密码、Token 或第三方代理凭据。

## 用例 10：运行数据接口与运营中心展示

目标：验证 access-agent 上报 `/metrics`、`/sessions`、`/probes` 后，运营中心展示真实在线、连接数、速率和探测延迟。

- 中心服务在真实 Docker Compose 环境中运行。
- 私有环境变量已注入 access-agent token、接入节点 ID、中转入口 ID 和内部出口 endpoint ID。

- 如测试探测策略，需要明确记录阈值、窗口、连续失败次数、连续恢复次数和最终组合状态，不得只用单次失败冒充阈值测试。

## 用例 11：支付回调沙箱验证

目标：验证支付接口在默认暂停状态下不会创建订单或处理回调；如后续启用真实支付沙箱，再验证通用支付回调能在测试库中驱动订单支付和订阅开通，且签名错误、重复回调和异常交易不会造成重复入账。

前置条件：

- 中心服务使用测试 PostgreSQL 数据库和测试 `PAYMENT_CALLBACK_SECRET`。
- 默认验收保持 `XRAYC_PAYMENT_ENABLED=false`，只验证暂停状态。
- 只有执行支付沙箱专项时，才临时设置 `XRAYC_PAYMENT_ENABLED=true`。
- 测试订单由临时用户创建，不能使用真实生产订单。
- 测试报告不得记录回调密钥、完整签名、真实交易哈希或支付商私密字段。

步骤：

1. 默认状态下，用户登录后调用 `POST /api/orders`。
2. 默认状态下，请求 `POST /api/payment/callback`。
3. 确认两个写接口都返回暂停状态，且没有新增订单、支付记录或订阅变更。
4. 支付沙箱专项中，临时设置 `XRAYC_PAYMENT_ENABLED=true` 后调用 `POST /api/orders` 创建测试订单。

## 用例 13：注册、刷新与退出登录

目标：验证普通用户可自助注册，注册后自动获得基础套餐订阅，Refresh Cookie 可刷新 Access Token，退出后刷新凭证失效。

步骤：

1. 使用唯一测试邮箱请求 `POST /api/auth/register`，请求体为 `{email,password}`。
2. 从响应中读取 Access Token，并从响应头确认存在 HttpOnly `refresh_token` Cookie。
3. 使用 Access Token 请求 `GET /api/user/subscription`。
4. 记录当前订阅下载链接，仅记录是否存在，不记录完整 Token。
5. 使用 Access Token 请求 `POST /api/user/subscription/token/reset`。
6. 使用旧订阅 Token 请求 `/sub/{token}`。
7. 使用相同邮箱重复注册一次。
8. 携带 Refresh Cookie 请求 `POST /api/auth/refresh`。
9. 携带 Refresh Cookie 请求 `POST /api/auth/logout`。
10. 再次携带原 Refresh Cookie 请求 `POST /api/auth/refresh`。

断言：

- 注册成功返回 200，响应中包含用户信息和 Access Token。
- 注册时自动生成基础套餐订阅和用户订阅 Token。
- `GET /api/user/subscription` 返回当前注册用户的订阅，不返回其他 demo 用户数据。
- 重置订阅链接返回新的订阅地址，旧 `/sub/{token}` 立即返回 404 或等价无效 Token 响应。
- 重复邮箱注册返回 409。
- 退出前刷新返回 200，退出后使用同一 Refresh Cookie 刷新返回 401。
- 数据库 `refresh_tokens.token_hash` 和 `subscription_tokens.token_hash` 只保存哈希用于运行校验，不在测试报告中记录 Cookie 原文或订阅 Token。

## 用例 14：认证安全策略

目标：验证后台认证安全配置不只是保存，还能在注册和登录链路生效。

步骤：

1. 管理员打开 `/admin/auth-security`，开启邀请码注册，开启用户自助生成邀请码，设置每用户生成上限为 1，开启注册、用户登录和管理员登录算术验证码，开启邮箱验证码并填写 SMTP 主机、端口、用户名、发件人和写入式密码，设置允许邮箱域名，例如 `example.test`，设置登录失败阈值为 2 次、锁定 5 分钟。
2. 不填写邀请码请求 `POST /api/auth/register`。
3. 使用不在白名单内的邮箱请求注册。
4. 普通用户打开 `/invite-codes`，请求 `POST /api/user/invite-codes` 生成一个邀请码。
5. 再次请求 `POST /api/user/invite-codes`，验证达到上限后被拒绝。
6. 请求 `GET /api/auth/captcha?scene=register&target=<email>`，使用白名单邮箱、该邀请码、算术验证码、邮箱验证码完成注册。
7. 请求 `GET /api/auth/captcha?scene=login&target=<email>`，对同一测试账号连续使用错误密码登录达到阈值。
8. 锁定期内再使用正确密码和新的登录算术验证码登录。
9. 管理员账号请求 `GET /api/auth/captcha?scene=admin_login&target=admin`，验证管理员登录必须使用管理员场景验证码。
10. 恢复认证安全配置，清理测试用户、邀请码、验证码挑战和登录锁记录。

断言：

- 缺少邀请码时注册返回 400。
- 邮箱域名不在白名单时注册返回 400。
- 有效邀请码注册成功后，邀请码被标记为已使用，并记录被邀请人邮箱快照。
- `/api/user/invite-codes` 未登录返回 401，关闭自助生成时返回 403，达到生成上限时返回 422。
- 用户只能看到自己生成的邀请码列表，列表返回已用状态、使用人邮箱和使用时间。
- 算术验证码固定 1 分钟有效，注册、普通用户登录和管理员登录按各自开关独立生效，成功或失败后不能重复使用。
- 邮箱验证码固定 1 分钟有效，发送接口受冷却时间限制，注册时缺少、错误、过期或重复使用验证码都必须失败。
- 达到错误阈值后，登录返回 429。
- 锁定期内正确密码也不能登录。
- `/api/auth/security` 不返回 SMTP 主机、用户名、密码等发信配置；管理员后台认证安全配置必须能读取和保存真实 SMTP 配置。
