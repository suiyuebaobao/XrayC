# 套餐接口

## 公共接口

- `GET /api/plans`：只返回 `enabled=true` 且未逻辑删除的套餐。

## 管理接口

- `GET /api/admin/plans`
- `POST /api/admin/plans`
- `PATCH /api/admin/plans/{plan_id}`
- `PUT /api/admin/plans/{plan_id}`
- `DELETE /api/admin/plans/{plan_id}`
- `PUT /api/admin/plans/{plan_id}/line-groups`

`line-groups` 是历史兼容路径，当前产品语义为“套餐授权分组”。套餐不维护多级分组结构，不直接绑定组合成员或出口管理成员。基础套餐不可删除或停用，到期后由 Worker 按基础套餐 `duration_days` 自动重置为新的基础周期，默认 30 天月度口径。普通套餐删除为软删除，并迁移活动订阅。付费套餐到期后自动切换回基础套餐；付费套餐重复购买或兑换码续费会从 `max(existing_expires_at, now)` 延长有效期、叠加流量，并保留已用流量。后台 `PATCH/PUT` 修改套餐按可选字段处理，未传字段不被默认值覆盖；修改 `traffic_limit_bytes` 时，服务端会同步该套餐下现有订阅的 `limit_bytes` 为新套餐额度，保留 `used_bytes`，并触发用户入口授权、出口运行授权重算和接入节点配置刷新。

## 订阅节点口径

- 套餐页只维护授权分组和倍率，不维护节点数量策略。
- 订阅节点计算顺序为：套餐授权分组 -> 分组内入口出口绑定节点 -> 已启用、已同步中转入口 -> 入口和出口可用性过滤。
- 一个入口绑定多个出口时，套餐授权的分组会按绑定节点展开为多个订阅节点；这些节点可能共用同一入口端口，但后台按绑定节点级凭据和 routing 区分出口。
- 若出口管理线路数和客户端节点数不同，前端应明确区分“出口管理线路”和“用户实际可用订阅节点”。
