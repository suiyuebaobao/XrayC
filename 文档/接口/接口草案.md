# XrayC V2 接口草案

## 通用约定

- 中心服务提供 REST API 和 `/sub/{token}` 订阅下载接口。
- 本接口草案面向 XrayC V2，后端、worker、access-agent 和配置编译器保持 Rust-only；主边界是“接入节点强控制、出口资源弱管理”。
- “接口草案”是本文档的固定命名，定位为人工维护的 XrayC V2 接口契约草案和实现对齐清单；`文档/接口/开放接口.yaml` 是 compact route index，不作为完整客户端生成 OpenAPI。
- 浏览器后台接口使用 JWT Access Token，Refresh Token 使用 HttpOnly Cookie。
- access-agent 使用每个接入节点独立凭证，请求头统一为 `Authorization: Bearer <agent_token>`，服务端只保存凭证 SHA-256 哈希。
- 订阅接口使用高熵随机 Token，不使用 JWT。
- 管理接口必须校验管理员身份并记录审计日志；当前关键后台写操作会写入 `audit_logs`，只保存脱敏摘要，不保存密码、Token 或第三方代理完整配置。
- JSON API 错误响应建议统一包含 `code`、`message`、`request_id`。
- 分页接口建议统一使用 `page`、`page_size`，响应包含 `items`、`total`。
- 文档示例只能使用占位值，不得写入真实 IP、密码、Token 或第三方代理凭据。
- API 基础频控在 PostgreSQL 模式下通过 `rate_limit_buckets(scope, identity_hash, window_start)` 原子共享计数，覆盖认证、订阅下载和支付回调；`identity_hash` 是可信客户端来源的 SHA-256 摘要，不保存明文 IP。未配置 PostgreSQL 或共享计数异常时退回进程内内存兜底，仅用于开发或无 PG 场景。该频控不是中转节点用户级带宽限速；带宽限速使用套餐/用户 `rate_limit_bps`、每用户 Xray `sockopt.mark`、user 路由和 access-agent limiter，不恢复旧限速档案。

## 公开与认证接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| `GET` | `/api/auth/security` | 无 | 返回前端渲染所需认证安全开关，不返回 SMTP 密码等敏感配置 |
| `GET` | `/api/auth/captcha` | 无 | 生成一次性算术验证码，查询参数 `scene`、`target` |
| `POST` | `/api/auth/email-code` | 无 | 发送注册邮箱验证码，受邮箱域名白名单、SMTP 配置和冷却时间控制 |
| `POST` | `/api/auth/register` | 无 | 邮箱注册，按配置校验邀请码、算术验证码和邮箱验证码，创建基础套餐订阅和订阅 Token |
| `POST` | `/api/auth/login` | 无 | 普通用户和管理员统一登录，服务端按账号实际管理员身份执行策略 |
| `POST` | `/api/auth/refresh` | Refresh Cookie | 刷新 Access Token |
| `POST` | `/api/auth/logout` | Refresh Cookie | 注销登录，撤销服务端刷新 Token 并清除 Cookie |
| `GET` | `/api/sales-landing` | 无 | 读取公网销售首页配置，供 `/` 销售页渲染 |
| `GET` | `/api/user/invite-codes` | 用户 JWT | 当前用户邀请码列表、生成额度和剩余额度 |
| `POST` | `/api/user/invite-codes` | 用户 JWT | 当前用户自助生成邀请码，受后台开关和额度限制 |

当前 XrayC V2 已落地邮箱注册、真实登录、Access Token 刷新和退出登录：注册请求体为 `{email,password,invite_code?,captcha_id?,captcha_answer?,email_code_id?,email_code?}`，登录请求体为 `{account,password,captcha_id?,captcha_answer?}`，密码使用 Argon2 校验 `users.password_hash`；成功响应返回 JWT `access_token`，同时通过 HttpOnly Cookie 设置 Refresh Token。Refresh Token 只以 SHA-256 哈希保存到 `refresh_tokens`；刷新接口会在同一事务内撤销旧 Refresh Token、插入新 Refresh Token，并通过新的 HttpOnly Cookie 下发，旧 Refresh Token 重放返回未授权；退出登录会撤销当前刷新凭证。管理员可使用 `admin` 别名登录首个启用管理员账号；`/api/admin/*` 在 PostgreSQL 模式下必须携带管理员 JWT，`/api/user/*` 必须携带有效用户 JWT。后台认证安全配置 `GET/PUT /api/admin/auth-security` 已落地并写入 `site_settings`，管理员后台读取时回显真实 SMTP 配置；公开安全接口、订阅、普通用户接口和日志不得返回 SMTP 主机、账号、密码或 Token。

当前方案-实现差距：

- 已实现：`GET /api/auth/security`、`GET /api/auth/captcha`、`POST /api/auth/email-code`、`POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/refresh`、`POST /api/auth/logout` 基础认证闭环。
- 已实现：Refresh Cookie 异常场景和多端会话已补真实 PostgreSQL 路由级覆盖，包括无 Cookie、畸形 Cookie、双会话并存、单会话退出不影响另一会话、旧 Refresh Token 重放失败和并发重复刷新只保留一个有效新 Token。过期或已撤销过保留期的 Refresh Token 由 Worker 清理；Refresh Token 一次性轮换已实现。
- 已实现：`GET /api/auth/security` 读取嵌套 `captcha`、`email_verification`、`login_guard` 公开安全开关并保留兼容扁平字段，且不返回 SMTP 发信字段；`GET/PUT /api/admin/auth-security` 支持管理员后台读取和保存真实 SMTP 配置。
- 已实现：`GET /api/sales-landing` 读取 `site_settings.sales_landing`，未配置时返回默认销售首页文案、卖点、场景和 FAQ。
- 已实现：邀请码注册消费、用户自助邀请码生成与额度限制、邮箱域名白名单校验、登录失败锁定共享状态、算术验证码、邮箱验证码发送，以及 PostgreSQL 模式下认证基础频控共享计数。
- 已实现：`scripts/real-auth-ha-uat.sh` 可验证多 API 副本共享认证状态、邮箱验证码开关/冷却/一次性消费、算术验证码一次性消费、Refresh Token 轮换重放拒绝、登录失败锁定和共享认证频控；长时间生产观察仍按真实发布 UAT 记录。

## 订阅接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| `GET` | `/sub/{token}` | 订阅 Token | 返回 Clash/mihomo YAML，不做 JSON 包装 |

响应要求：

- `/sub/{token}` 是系统唯一订阅方式。
- `Content-Type` 建议为 `text/yaml; charset=utf-8` 或兼容客户端的下载类型。
- 响应头应包含 `profile-title`、`profile-update-interval`、`profile-web-page-url`、`Content-Disposition` 和 `subscription-userinfo`；订阅名称与更新间隔读取后台 `subscription_config`。
- `Content-Disposition` 文件名使用后台订阅名称，禁止自动追加 `.yaml`，避免客户端导入后显示固定 `config.yaml` 或强制后缀。
- 只输出订阅入口。
- 当前订阅主链路只渲染 VLESS、Trojan、HY2 和 Shadowsocks 2022 中转入口。Trojan 使用 `password` 字段；HY2 输出 `type: hysteria2` 并使用用户 credential 作为 `password`，必须配置 TLS/SNI；Shadowsocks 用户入站必须使用 2022 系列方法，使用 `ss` 节点形态且必须有 server password，并按 `server:user` 形态承载用户凭据；旧 `aes-*-gcm` 只允许作为内部或出口协议，不进入用户订阅、用户级路由或计费主链路；HTTP、SOCKS 和 VMess 入站当前不渲染订阅，也不得回退为 VLESS。
- 订阅入口按套餐授权分组、分组内启用且可用的入口出口绑定节点、中转节点状态和用户剩余额度计算。
- YAML 的 `mixed-port`、`allow-lan`、`mode`、`log-level` 和自动测速开关读取后台 `/api/admin/subscription-settings` 保存的 `subscription_config`；通用规则仍保存为 `subscription_config.default_rules`，但管理入口是 `/admin/rule-settings`；规则库由 `/api/admin/subscription-rule-sets` 管理，分组通过 `rule_set_bindings` 绑定规则库；`proxy-groups` 不再由订阅设置自定义，而是由套餐授权分组自动生成，最终 `MATCH` 指向套餐默认出口分组，未匹配到任何规则时默认走代理。
- 普通 `select` 分组来自套餐授权分组，组内成员是该分组下的绑定节点代理项；订阅 YAML 不输出入口或分组 `icon` 字段；客户端 `url-test` 自动测速分组默认关闭，仅在后台显式开启时额外生成一个全节点测速分组。
- 订阅节点名称使用中转入口线路名，保持纯文本，不拼接 `region_flag` 或图标前缀；不得为此暴露出口资源地址或第三方上游信息。
- 无可用中转入口时返回明确业务错误；当前兼容错误文案可为“当前套餐没有可用线路”，但产品说明必须解释为没有可用中转入口，不得返回 500。
- 未授权、过期或无效 Token 返回明确错误，并遵守 PostgreSQL 共享基础频控；无 PG 时使用进程内内存兜底。
- 用户或管理员重置订阅 Token 后，旧 `/sub/{token}` 必须立即返回无效 Token，不允许继续下载 YAML。
- 中转入口端口恒输出内部 `access_lines.listen_host/listen_port`（守真实端口、CF=443）；限速用户不再单独分配入口端口，靠每用户 fwmark + 带 mark 出站在出口侧整形，订阅仍只显示该逻辑入口的一条节点，统计、探测和账本仍通过 `source_line_id` 归属原始绑定节点。

订阅配置专项验证：

- 修改订阅配置下发逻辑后，至少运行 `cargo fmt --check`、`cargo test -p xrayc-core subscription`、`cargo test -p xrayc-api test_subscription_endpoint_returns_yaml_without_exit_host`、`cargo test -p xrayc-db test_pg_store_seed_subscription_and_billing_when_database_url_is_set`。
- 修改前端订阅配置页面或接口字段后，必须追加 `cd frontend && npm run build`。
- 合并前必须运行 `cargo clippy --workspace --all-targets -- -D warnings`、`git diff --check`、`bash scripts/verify-no-secrets.sh` 和 `docker compose config --services`。

订阅输出禁止包含：

- 出口 endpoint 地址。
- 第三方代理 URL。
- 第三方账号密码、UUID、Reality 私钥、公钥、订阅 Token 原文以外的敏感字段。
- 私有测试服务器信息。

管理接口原则：

- 写操作必须记录操作者、目标资源、动作和结果。
- 出口管理出口协议档读取接口面向管理员后台，允许回显真实主机、端口和协议配置；订阅、普通用户接口、公开日志、截图、测试报告和提交说明不得回显账号、密码、私钥或完整代理 URL。
- 后台只生成中转节点 Agent 安装说明；第三方出口和独立出口机器不提供安装接口。
- PostgreSQL 模式下管理接口必须使用 `Authorization: Bearer <access_token>`，且 JWT 中 `is_admin=true`。
- 部署产物下载接口必须使用 `DEPLOY_ARTIFACT_TOKEN`，只允许下载 `deploy/artifacts` 下的安全文件名，禁止路径穿越。

### 套餐 CRUD 合同

套餐 CRUD 必须与 V2 方案保持以下语义：

- 公共 `GET /api/plans` 只返回可购买套餐：`enabled=true` 且 `is_deleted=false`。该接口不得返回逻辑删除套餐，也不得要求用户 JWT。
- 后台 `GET /api/admin/plans` 返回后台管理列表，包含 `enabled`、`is_default`、`is_deleted`、额度、倍率、时长和分组授权摘要。普通列表默认隐藏 `is_deleted=true`，如后续支持审计查询，必须明确标注已删除且禁止再次售卖。
- `POST /api/admin/plans` 创建普通套餐，不允许创建第二个基础套餐；请求可以同时带初始分组授权范围，也可以创建后通过 `PUT /api/admin/plans/{id}/line-groups` 绑定内部授权范围。
- `PATCH /api/admin/plans/{id}` 是推荐更新路径，`PUT /api/admin/plans/{id}` 可作为全量替换兼容路径。基础套餐必须保持 `enabled=true` 且 `is_default=true`；普通套餐停用后不再出现在公共 `GET /api/plans`，但不会迁移既有活动订阅。
- `DELETE /api/admin/plans/{id}` 对普通套餐执行逻辑删除：设置 `is_deleted=true`，清理该套餐的分组授权范围、用户入口授权和用户出口运行授权，把使用该套餐的活动订阅迁移到基础套餐，并标记相关接入节点配置 dirty。基础套餐删除必须返回 400 或等价业务错误。
- `PUT /api/admin/plans/{id}/line-groups` 替换套餐授权范围；当前产品语义为授权分组。每个授权项包含 `line_group_id` 和可选 `billing_multiplier`。
- 基础套餐到期由 Worker 按基础套餐 `duration_days` 重置新周期，默认 30 天月度口径；付费套餐到期自动切回基础套餐。付费重复购买、支付成功和兑换码续费都从 `max(existing_expires_at, now)` 延长有效期、叠加流量并保留已用流量。

## 接入代理接口

接入代理接口统一要求 `Authorization: Bearer <agent_token>`。服务端对请求 token 做 SHA-256 后，按 `access_nodes.agent_token_hash` 校验凭证；缺失、格式错误或凭证不匹配时返回 HTTP 401，响应体不泄露节点凭证、哈希或匹配细节。

PostgreSQL 模式下 access-agent 请求必须携带 UUID 格式的 `access_node_id` 或 `node_id`，服务端按该节点绑定的 token 校验，不再回退到第一台节点。`config-result` 响应只返回固定 `success/accepted`，不得回显请求体。

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| `POST` | `/api/agent/access/heartbeat` | access-agent Token | 上报节点 ID、access-agent 版本、hostname、可选 Xray 版本、本机已应用配置版本和 uptime，返回配置同步指令与手动探测任务 |
| `POST` | `/api/agent/access/config-result` | access-agent Token | 上报 Xray 配置应用结果、applied hash 和错误摘要 |
| `POST` | `/api/agent/access/traffic` | access-agent Token | 上报用户维度累计流量快照 |
| `POST` | `/api/agent/access/metrics` | access-agent Token | 上报中转入口运行指标，如速率、在线用户和连接数 |
| `POST` | `/api/agent/access/sessions` | access-agent Token | 上报在线用户会话摘要 |
| `POST` | `/api/agent/access/probes` | access-agent Token | 上报接入节点到出口 endpoint 的组合健康 |

运行数据接口要求：

- `/metrics`、`/sessions`、`/probes` 必须由 access-agent 从接入节点本机真实观测源采集后主动上报，不能由中心侧估算、订阅数量推导或测试模拟数据替代。
- 中心接收后分别写入 `access_line_metric_snapshots`、`access_user_sessions`、`access_line_probes` 和 `access_exit_probes`，运营中心据此展示真实在线、连接数、上下行速率和探测延迟。
- 所有请求必须携带 `Authorization: Bearer <agent_token>`，公开示例只能使用占位符，不得写真实服务器 IP、密码、Token、订阅链接或代理凭据。

处理要求：

- 请求体的 `node_id` 必须等于当前接入节点 ID；PostgreSQL 模式下也兼容旧字段名 `access_node_id`，但 access-agent 新实现统一发送 `node_id`。

- `config_status.required=false` 时 `config` 必须为 `null`。

- `probe_tasks` 来自管理员手动探测登记或 Worker 定时排队；任务携带脱敏 `target` 时 access-agent 以 `target` 为准，避免本地 active config 滞后时探测旧地址；没有 `target` 时才回退当前 `AccessConfig` 中的出口协议档，并复用 `/api/agent/access/probes` 回报结果。
- 订阅和浏览器用户接口不得泄露第三方出口地址、账号或凭据；access-agent heartbeat 的 `config` 只允许下发 Xray outbound 必需字段，日志和测试报告必须脱敏。
- `routing_rules.user_email` 必须等于 Xray client `email`。当前运行实现使用 `xrayc-line-<access_line_id>--<xray_user_key>` 编码，access-agent 从 Xray Stats 名称还原 `access_line_id + xray_user_key`，避免同一用户多中转入口串账；解析层兼容历史前缀，但新配置不得继续生成历史前缀。

- 探测视角必须是当前接入节点到目标 `exit_endpoint`，中心自身到出口的连通性不能替代组合探测。

- 运营中心按最新 `access_node -> exit_endpoint` 探测结果展示健康状态和延迟，并按探测策略驱动订阅输出和 agent 配置收敛。

## 已落地的 V2 管理写接口

以下接口已进入 Rust API PostgreSQL 模式，均要求管理员 JWT：

- `POST /api/admin/access-nodes`：在平台新增中转节点。手动路径请求字段为 `name`、`public_host`、`public_port`、节点鉴权码和可选备注；一键安装路径由平台从脚本输出解析节点鉴权码后自动调用同一创建逻辑。服务端解析节点 ID 和 token，只保存 SHA-256 哈希，响应和审计只返回脱敏状态，并把节点标记为配置待同步。
- `POST /api/admin/access-nodes/one-click-install`：可选一键安装 Agent。请求包含节点名称、地址、端口、SSH 地址、SSH 端口、SSH 用户、SSH 密码或私钥、部署选项、可选 `tls_cert_domains` 和 `acme_email`。SSH 凭据只允许在本次请求内用于 ssh/scp 远端执行，不得保存到部署任务、审计日志、公开日志或前端列表。成功后平台解析脚本输出的节点鉴权码并自动创建中转节点，任务结果只记录节点 ID、节点名称、节点地址、SSL 申请标记和脱敏摘要。
- `POST /api/admin/access-nodes/install-guide`：生成中转节点 Agent 手动安装说明。`access_node_id` 可选，仅用于为已有节点生成重装说明；不传时生成通用 agent-first 安装说明。安装选项包括 `control_plane_url`/`panel_url`、`deploy_artifact_token`、`install_dir`、`compose_project`/`compose_project_name`、`xray_api_server`、`xray_api_listen_host`、`xray_api_listen_port`/`xray_api_port`、`heartbeat_interval_seconds`、`traffic_interval_seconds`、`session_idle_seconds`、`expected_listen_ports`、`tls_cert_domains`、`acme_email`、`disable_legacy_systemd_units` 和 `force_reinstall`。响应返回安装环境变量、服务器执行命令和步骤说明；该手动接口只生成服务器本地执行材料。
- `GET /api/admin/exit-resources`：已实现的内部出口资源列表路由，返回出口资源摘要；资源本身不保存协议凭据，真实 `host`、端口、账号、密码、UUID、Token、私钥和出站配置由 `/api/admin/exit-endpoints` 管理员接口展示和维护。
- `GET /api/admin/exit-endpoints`：已实现的出口管理出口协议档列表路由，管理员后台返回 endpoint 摘要、所属资源、真实 `host`、协议类型、端口、启停状态、探测状态、`outbound_config`、`stream_config` 和 `probe_config`，用于出口管理增删改查、探测和排障。该明文可见边界仅限管理员后台；订阅、普通用户接口、公开日志、截图、测试报告和提交说明不得回显真实上游地址、账号密码、Token、私钥或完整代理 URL。
- `POST /api/admin/exit-resources`：创建内部出口资源。支持 `name`、`region_code`、`provider_name`、`ownership`、`enabled`；本机出口服务应走中转节点专用接口并按所选明确协议 endpoint 登记。
- `PUT /api/admin/exit-resources/{id}`：更新出口资源基础字段和启停状态；会标记引用该资源的接入节点配置 dirty。
- `POST /api/admin/exit-endpoints`：创建内部出口协议档。支持 `exit_resource_id`、`name`、`outbound_type`、`host`、`port`、`outbound_config`、`stream_config`、`probe_config`、`enabled`；第三方和普通自建出口必须使用 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 等明确上游协议，本机出口服务前端默认只生成 VLESS、HY2、Shadowsocks、Trojan 四类自建协议档。写入前会校验普通上游的 host/port、SOCKS/HTTP 认证成对、VLESS uuid 和 `security` 分支、Trojan password、Shadowsocks method/password、Hysteria/HY2 password 或 auth；VLESS 线路表单默认使用 Reality，`security=reality` 只允许 TCP 网络模式，并由本机出口服务自动生成 public/private key 和 short id；第三方 VLESS Reality 仍需填写供应商真实 public key。`security=tls` 不得被 Reality 字段校验误拒，未知 security 不可写入、不可分配、不可编译；敏感配置只允许下发给 access-agent，不得进入订阅。配置任一字段加密 keyring provider 后，`outbound_config`、`stream_config`、`probe_config` 和 `access_lines.inbound_config` 中的用户名、密码、UUID、私钥、Token 等敏感叶子字段会以 `xrayc:v1:xchacha20poly1305` envelope 保存，读取下发前在服务端解密；provider 可来自 inline、file 或外部 command，command 可对接私有 KMS/Vault/云 KMS wrapper。
- `PUT /api/admin/exit-endpoints/{id}`：更新内部出口协议档。会按更新后的最终协议和配置执行同创建接口一致的基础写入校验；敏感字段只写入，不在订阅或公开接口回显完整代理凭据；会标记引用该端点的接入节点配置 dirty。
- `DELETE /api/admin/exit-endpoints/{id}`：删除内部出口协议档。删除会同步收敛运行兼容成员、用户出口映射、用户入口授权、`/sub/{token}` 和相关接入节点 dirty 状态，避免继续引用已删除或不可用出口。
- `POST /api/admin/exit-endpoints/{id}/probe`：登记一次管理员手动探测请求，按引用该出口端点的接入节点或 self-hosted 所属节点写入 queued 探测记录并标记节点配置 dirty；下一次 access-agent 心跳会返回 `probe_tasks`。access-agent 优先使用 queued 任务携带的脱敏 target 执行协议感知探测，target 缺失时回退当前 `AccessConfig`；TCP 类入口/出口执行 TCP connect，HY2/Hysteria2 入口和出口 endpoint 执行 UDP 可达性探测，本机 UDP 端口明确拒绝时必须上报 `unhealthy`，结果复用 `/api/agent/access/probes` 回报。

### 中转节点专用接口 / 内部维护接口

- `POST /api/admin/access-nodes/{id}/local-exit-lines`：中转节点“本机出口服务”专用批量接口。每条线路保存层仍提交 `outbound_type`、`network_mode`、`port`、`outbound_config`、`stream_config`、`probe_config` 和启用状态；`host` 可选，省略时默认使用所属中转节点地址。前端默认按节点地址生成可保存的四类自建线路配置，包括 VLESS UUID/SNI、HY2/SS/Trojan 密码、Shadowsocks 加密方法和 HY2/Trojan 证书路径，不要求管理员填写连接 JSON，也不默认生成 SOCKS5/HTTP。VLESS Reality 本机出口只允许 TCP 网络模式，保存时由后端生成 Reality public/private key 和 short id；保存后只进入统一出口管理并记录所属中转服务器，不自动创建用户入口，也不会加入分组。
- `POST /api/admin/access-entries` / `POST /api/admin/access-entries/{id}/exit-bindings`：入口管理当前主路径。入口请求维护 `name`、`access_node_id`、`listen_host`、`listen_port`、`protocol`、`transport`、`security`、TLS/CDN/WebSocket 字段和启用状态；绑定请求选择 `exit_endpoint_id` 并创建入口出口绑定节点。分组成员通过绑定节点接口维护，不直接把出口线路写进分组。
- `GET /api/admin/field-encryption/status`：查看字段加密状态，只返回是否配置、主 `kid`、key 数量、site settings、内部 exit endpoints、内部 access lines 扫描数量、旧 `kid` 字段计数、明文敏感字段计数和最近轮换任务摘要。
- `POST /api/admin/field-encryption/rotate`：执行字段加密密钥轮换。`{"dry_run": true}` 只计算将重写的 auth security、内部出口协议档和中转入口入站配置数量；`{"dry_run": false}` 把旧 `kid` 密文和兼容明文敏感字段重加密为当前主 `kid`。每次请求都会写入 `field_encryption_rotation_jobs` 并返回 `job_id`、状态和计数；执行阶段使用 PostgreSQL advisory lock 防止并发轮换，正式重写会对目标行加 `FOR UPDATE` 行锁，超过 2 小时未完成的 running 任务会自动标记为 failed。成功和失败都会写入管理员审计，失败审计只记录错误类别和脱敏标记。响应、任务记录和审计不得包含 key material、密文、明文、SMTP 密码、出口协议档敏感配置或接入入站私钥。
- `GET /api/admin/exit-pools`：只读查看内部运行集合和成员健康，供排障使用。公开管理接口不再提供创建内部运行集合、替换成员或聚合新增出口；入口出口绑定节点由后端使用对应出口线路的运行集合。
- `GET/PUT /api/admin/access-operations/settings`：读取或保存运营策略。当前支持 `probe_policy.exit_auto_failover_enabled`、`exit_failure_threshold`、`exit_recovery_threshold`、`exit_window_minutes`、`exit_probe_interval_seconds`、`probe_queue_batch_size` 和 `max_pending_probe_tasks`；服务端会裁剪阈值范围，状态机只由后续 `/api/agent/access/probes` 非 queued 结果驱动，Worker 只按该策略写入 queued 探测任务。还支持 `traffic_log_retention.detail_retention_days`、`prune_enabled` 和 `delete_batch_size`；服务端会裁剪保留天数和批量删除范围，Worker 把超过保留期的 `usage_ledgers` 明细汇总到 `usage_daily_rollups` 和 `usage_hourly_rollups` 后删除明细，用户已用流量不二次变化。还支持 `database_backup.enabled`、`interval_days` 和 `retention_days`；默认启用且每天备份一次，Worker 使用 PostgreSQL custom dump 写入配置的备份目录并按保留天数清理旧备份。
- 旧中转节点批量出口集合接口和旧中转节点直接写入口接口已删除；中转节点不再批量加载内部集合，也不在节点页维护分组成员。当前公开主路径通过 `POST /api/admin/access-entries` 创建入口，再通过 `POST /api/admin/access-entries/{id}/exit-bindings` 选择出口线路并创建绑定节点。
- `GET /api/admin/access-lines/{id}/sessions`：读取指定中转入口最近在线会话，只返回 `client_ip_hash` 关联标识，不回显明文 IP；响应会话项包含 `active_connection_count`、兼容别名 `active_connections` 和 `status=online/offline/expired/unknown`；公开输出必须使用占位值或截断摘要。
- `GET /api/admin/access-lines/{id}/metrics`：读取指定中转入口最近运行指标快照，包括在线用户、连接数、独立客户端 IP 数和上下行速率；响应同时返回 `ledger_summary`、兼容别名 `traffic_summary` 和按小时聚合的 `ledger_windows`；公开响应不得包含明文客户端 IP。
- `POST /api/admin/line-groups`：创建扁平分组。
- `PUT /api/admin/line-groups/{id}/binding-nodes`：替换分组内入口出口绑定节点，并同步用户入口/出口兼容映射和接入节点 dirty；这是当前分组成员维护主路径。
- `PUT /api/admin/line-groups/{id}/lines`：历史兼容接口，仅用于替换分组内旧出口 endpoint 成员并同步运行兼容集合；新前端和新功能不得以它作为分组成员主路径。
- `PUT /api/admin/plans/{id}/line-groups`：替换套餐授权范围，清理相关用户入口分配，并等待下一轮同步重算。
- 旧手动重算类入口已删除；后台不再提供手工重算入口授权或出口映射按钮，相关运行映射由资源、入口、分组、套餐和用户状态变化自动收敛。

以下能力仍属于 V2 后续增强，不得在验收报告中写成已完成：真实供应商各协议公网实测结果、支付渠道字段映射、高并发压测和探测策略长时间稳定性验证。

字段要求：

- 该请求是手动安装说明请求，不包含 SSH 主机、SSH 密码、私钥内容或私钥路径；一键安装的 SSH 字段只允许出现在 `/api/admin/access-nodes/one-click-install` 请求体内，并且不得保存。

- `control_plane_url` 可由服务端从 `XRAYC_PUBLIC_BASE_URL` 或请求 Host 推断；公开文档只能使用 `https://panel.example.test` 这类占位域名。
- `deploy_artifact_token` 可由服务端 `DEPLOY_ARTIFACT_TOKEN` 兜底；公开文档、响应和日志只能记录已脱敏标记。
- `expected_listen_ports` 为空数组或省略时，服务端不做端口 readiness 断言；订阅入口端口恒为逻辑中转入口端口、不因用户级限速变化（限速靠每用户 mark 区分），但端口监听时序由节点实际收敛决定，默认不读取逻辑中转入口端口作断言。只有显式传入非空数组时，安装脚本才等待这些端口监听。

- 反向代理不再为后台 SSH 安装提供长超时路径；中心只生成安装说明，不执行目标服务器安装。

当前方案-实现差距：

- 已实现：订单表、兑换码表、`POST /api/orders`、`GET /api/orders`、`GET /api/admin/orders`、`POST /api/redeem`、`POST /api/admin/redeem-codes`、`GET /api/admin/redeem-codes` 已进入 Rust API。
- 已实现：普通用户订单只读取自己的记录，管理员接口校验管理员 JWT，兑换码消费在同一事务内完成校验、订阅开通/续费、使用人写入和接入节点 dirty 标记。

- 已实现：后台兑换码页面展示套餐名称，生成数量前后端统一限制为 1 到 100。
- 已实现：兑换码消费使用 `redeem_codes.code` 唯一约束和事务内 `FOR UPDATE` 行锁；真实 PostgreSQL 测试已覆盖同一个兑换码被多个并发任务同时兑换时只能 1 个成功，订阅额度只叠加一次且不会写入流量账本。边界：当前覆盖的是同码并发基础竞争测试，不等同于全链路大规模压测。
- 接口保留：支付功能当前暂停，`POST /api/orders` 默认返回暂停状态；后续启用真实支付后，订单创建和支付成功回调才写入审计日志，摘要只保留订单号、套餐、金额、币种、状态和幂等状态等安全字段，不记录收款地址、签名、Token 或回调原文。

## 支付回调接口

| 方法 | 路径 | 鉴权 | 说明 |
|------|------|------|------|
| `POST` | `/api/payment/callback` | HMAC 签名 | 通用支付回调，订单驱动订阅开通 |

当前方案-实现差距：

- 接口保留：当前 Rust API 已暴露 `/api/payment/callback`，但默认 `XRAYC_PAYMENT_ENABLED=false` 时返回暂停状态，不处理回调。
- 启用后要求：使用 `PAYMENT_CALLBACK_SECRET` 对原始请求体做 HMAC-SHA256 验签，并在 PostgreSQL 模式下使用共享基础频控。
- 启用后字段：回调字段为 `order_no`、`tx_id`、`amount_cents`、`currency`、`payment_address`、`status`、`confirmations` 和 `paid_at`；成功支付会在同一事务中写入 `payment_records`、订单置为 `paid`、开通或续费订阅、保证订阅 token 存在，并标记接入节点配置 dirty。
- 启用后校验：`pending` 不视为成功支付；`paid`、`confirmed`、`success`、`completed` 必须满足 `PAYMENT_MIN_CONFIRMATIONS`，且金额、币种、收款地址必须与订单完全一致。
- 启用后幂等：`payment_records.tx_id` 是幂等键，同一订单重复回调返回幂等成功，不重复叠加套餐时长或流量；同一交易流水号绑定其他订单会拒绝。
- 待增强：支付商字段映射、链上监听或 webhook 对账任务、公网 HTTPS 回调兼容性、异常补偿和生产支付网关 E2E 尚未完成。
- contract smoke 默认不调用支付回调，因为它属于写接口路径；支付回调由 Rust PostgreSQL 集成测试用占位密钥和测试订单验证。

要求：

- Header 使用 `X-XrayC-Signature`。
- 使用原始请求体和 `PAYMENT_CALLBACK_SECRET` 做 HMAC-SHA256 校验。
- `payment_records.tx_id` 是幂等键。
- 重复回调返回幂等成功，不重复叠加套餐时长或流量。
- 同一交易哈希绑定其他订单必须拒绝。
- 日志不得打印原始签名密钥、完整交易敏感字段或用户隐私信息。

## 最小 API Contract Smoke 草案

接口契约 smoke 脚本为 `scripts/api-contract-smoke-draft.sh`，设计目的不是替代集成测试，而是在部署后快速发现“文档声明的接口是否存在、是否需要鉴权、是否泄露敏感字段”。脚本以只读检查为主；对运营策略会执行一次基于当前返回值的幂等 `PUT /api/admin/access-operations/settings`，用于验证 `traffic_log_retention` 和 `database_backup` 保存契约。

默认检查：

- `GET /health` 返回 2xx。
- `GET /api/auth/security` 返回 2xx，且响应体不包含 SMTP 密码、私钥、Token 等敏感字段。
- `GET /api/plans` 返回 2xx；若响应项包含 `enabled` 或 `is_deleted` 字段，必须符合 `enabled=true` 且 `is_deleted=false`。
- 未带用户 JWT 访问 `GET /api/user/subscription` 应返回 401/403；如果返回 2xx 或泄露订阅 Token，判定失败。
- 未带用户 JWT 访问 `GET /api/orders` 必须返回 401/403。
- 未带管理员 JWT 访问 `GET /api/admin/plans` 必须返回 401/403；严格模式下路由缺失判定失败。
- 未带管理员 JWT 访问 `GET /api/admin/redeem-codes` 必须返回 401/403。
- 如果提供 `USER_ACCESS_TOKEN`，脚本可只读检查 `GET /api/user/subscription` 和 `GET /api/orders`；脚本不得打印 Token 或响应正文。
- 如果提供 `ADMIN_ACCESS_TOKEN`，脚本可只读检查 `GET /api/admin/plans` 和 `GET /api/admin/redeem-codes`；脚本不得打印 Token 或响应正文。

不进入默认 smoke：

- `POST /api/orders`，支付启用后会创建订单；默认暂停时应返回暂停状态。
- `POST /api/redeem`，会消费兑换码。
- `POST /api/payment/callback`，支付启用后会改变订单和订阅状态；默认暂停时应返回暂停状态。
