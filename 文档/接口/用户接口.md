# 用户接口

## 接口

- `GET /api/sales-landing`
- `GET /api/user/me`
- `GET /api/user/subscription`
- `POST /api/user/subscription/token/reset`
- `GET /api/user/usage`
- `GET /api/orders`
- `POST /api/orders`
- `POST /api/redeem`
- `GET /api/user/invite-codes`
- `POST /api/user/invite-codes`
- `POST /api/user/password/send-code`
- `POST /api/user/password`

## 规则

`GET /api/sales-landing` 是公开销售首页接口，不需要 JWT，只返回展示文案和销售配置。

所有用户接口必须使用当前 JWT 用户读取数据，禁止回退固定 demo 用户。普通用户不得访问 `/api/admin/*`。

`POST /api/orders` 当前默认处于支付暂停模式，只返回暂停状态，不创建真实支付订单；正式启用支付前必须补齐支付商字段映射、sandbox、公网 HTTPS 回调、对账和异常补偿。

`POST /api/user/subscription/token/reset` 只允许当前用户重置自己的订阅链接。响应返回新的 `token` 和 `subscription_url`，旧 `/sub/{token}` 必须立即失效；服务端会同步轮换节点入站凭据和统计归属 key，让旧客户端配置在中转节点下一轮同步后失效。测试报告不得记录完整 Token 或完整订阅链接。

`POST /api/user/password/send-code` 与 `POST /api/user/password` 是已登录用户经邮箱验证码自助改密的两步：

- `POST /api/user/password/send-code`：把 6 位验证码发到**当前登录身份的注册邮箱**，邮箱以 JWT 为准、绝不接受请求体传入邮箱（防止给他人邮箱发码）。受认证基础频控叠加改密专用挑战冷却 `email_code_cooldown_seconds` 双重限频，验证码 1 分钟有效、一次性消费、场景与注册/登录隔离。响应返回 `{id, expires_in, cooldown_seconds}`；发码失败时立即消费挑战、不占冷却额度，绝不回显明文验证码。频繁发码返回 429。
- `POST /api/user/password`：请求体 `{email_code_id, email_code, new_password}`。先按当前登录邮箱原子校验并消费改密验证码（缺失/错误/过期/已用统一 400「邮箱验证码无效或已过期」），再在同一事务内做密码强度校验（最少 8 位，弱密码 400）、Argon2 重哈希、写 `password_hash`，并撤销该用户全部刷新令牌（含当前会话），同步清除浏览器 Refresh Cookie，响应提示用新密码重新登录。密码明文与验证码绝不写入日志。
