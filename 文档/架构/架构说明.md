# 架构说明

## 目标边界

XrayC V2 面向中转节点，接入节点运行 `xray-core` + `access-agent`（单内核 Xray），所有入口都由 Xray 处理；中心后端和 agent 技术栈保持 Rust-only，提供用户管理、中转入口控制、分组授权、订阅分发和流量计费。

主架构是“中转节点强控制 + 出口弱管理”：出口管理保存第三方出口、普通自建上游出口或中转节点本机出口服务的真实地址和凭据；入口管理维护中转节点上的用户入口，并把入口和出口线路组成可订阅的绑定节点；分组只有一层并直接选择绑定节点；套餐直接授权分组，不维护多级结构或组合成员。同一入口可以绑定多个出口，订阅按绑定节点显示多个节点；agent 非限速运行态会合并相同入口端口，但按绑定节点级用户凭据和 routing 分流到不同出口。

用户客户端只连接系统下发的中转入口，出口管理、出口凭据和运行兼容集合不直接暴露给用户。本机出口服务主路径为批量创建自建线路进入统一出口管理；订阅只暴露入口参数，控制和计费在中转节点/access-agent 链路完成。

本说明以 `开发方案.md` 为公开方案依据，`文档/架构/当前方案与运营闭环.md` 为公开文档总口径。若后续接口、数据库、部署方式、订阅格式、计费逻辑或节点控制策略变化，必须先同步开发方案，再同步 README、总口径和相关公开文档；本地私有规则文件如需同步只在主线程报告，不在公开文档展开。

## 技术栈约束

中心服务统一采用 Rust 技术栈：

- HTTP 服务使用 Axum，公开 REST API、订阅下载、支付回调和 access-agent 控制入口。
- 数据访问使用 SQLx，数据库以 PostgreSQL 为唯一持久化存储。
- 后台任务、基础套餐周期重置、付费套餐到期回基础、订单过期扫描、认证临时状态清理和运行态数据保留策略应复用同一套 Rust/SQLx 领域模型。
- 文档、脚本和示例必须保持 Rust/Axum/SQLx/PostgreSQL 方向一致。

## 运行角色

| 角色 | 职责 | 是否强控制 |
|------|------|------------|
| 中心 API | Rust/Axum 服务，提供 REST API、订阅下载、支付回调、access-agent 控制入口 | 是 |
| Worker | Rust 后台进程，执行套餐周期维护、订单过期、认证临时状态清理、运行态快照保留、详细流量日志汇总清理、数据库自动备份和后台任务 | 是 |
| access-agent | 部署在中转接入节点，生成 Xray 配置、采集流量、上报心跳和探测 | 是 |
| xray-core | 单内核，承载全部用户入站、出站和路由，并作为 Stats API 观测主链路 | 由 access-agent 控制 |
| exit_resources | 内部记录第三方、普通自建上游或中转节点本机出口服务的归属和状态 | 弱管理 |
| exit_endpoints | 内部记录出口协议档，供 access-agent 生成 outbound | 弱管理 |

系统不规划独立出口代理主链路。自建机器如果需要被系统强控制，应作为中转接入节点固定部署 `xray-core` 和 `access-agent`；出口可通过中转节点详情的本机出口服务写入统一出口管理，或作为普通自建上游 endpoint 写入统一出口管理。

前端、后端和数据库在代码边界上分离：前端只通过 HTTP API 调用后端，后端通过 `DATABASE_URL` 访问 PostgreSQL。当前默认部署把 PostgreSQL、API、Worker 和 Caddy 放在同一台主控服务器的 Compose 中；需要拆分到不同服务器时，必须显式配置 API 地址、数据库连接、Caddy 反代目标、TLS 和防火墙策略。

## 主链路模型

主链路对外围绕“出口管理、入口管理、绑定节点、分组、套餐、中转节点和中转入口”建模。以下表名是内部实现、审计和排障对象：

| 对象 | 说明 |
|------|------|
| `access_nodes` | 自建中转接入节点，保存 agent 鉴权、健康、配置同步和流量上报状态 |
| `access_entries` | 入口管理主表，保存中转节点、入口协议、监听端口、传输、安全和 CDN/WS 等入口参数 |
| `access_entry_exit_bindings` | 入口出口绑定节点，一个绑定节点等价于一个用户可见订阅节点 |
| `line_group_binding_nodes` | 分组成员主表，分组只选择入口出口绑定节点 |
| `access_lines` | 运行兼容物化表，由绑定节点展开；允许多个绑定节点共享同一入口端口，订阅按绑定节点展示，agent 可合并 runtime inbound |
| `exit_resources` | 内部出口资源，描述第三方、普通自建上游或中转节点本机出口服务 |
| `exit_endpoints` | 内部出口协议档，描述 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 等 outbound；本机出口服务也按这些明确协议批量写入统一出口管理，`direct` 只允许用于历史兼容 |
| `exit_pools` | 底层运行兼容集合，只服务绑定节点后的内部出站映射和诊断 |
| `exit_pool_members` | 历史命名的运行兼容成员，保存绑定节点对应出口 endpoint 的健康、维护和不可用诊断状态；不表达权重、容量或用户分配策略 |
| `user_exit_assignments` | 历史命名的用户出口映射缓存，当前只记录用户在具体绑定节点后的 `exit_endpoint` 出站目标；不作为调度策略 |
| `line_groups` | 扁平分组的兼容实现，分组直接选择入口出口绑定节点 |
| `plan_line_groups` | 套餐到分组的兼容授权关系；历史数量策略字段不作为当前产品功能 |
| `user_access_line_assignments` | 用户可见中转入口授权快照；来源是套餐授权分组内绑定节点对应的入口 |
| `access_traffic_snapshots` | access-agent 上报的累计流量快照 |
| `access_line_metric_snapshots` | access-agent 上报的中转入口真实速率、在线用户数和连接数 |
| `access_user_sessions` | access-agent 上报的接入用户在线会话摘要 |
| `access_exit_probes` | access-agent 上报的 `access_node -> exit_endpoint` 组合探测流水 |
| `access_exit_probe_states` | 连续失败/恢复阈值后的组合出口生效状态 |
| `usage_ledgers` | 快照差值入账后的用户流量账本 |

## 套餐生命周期

系统必须始终保留一个 `plans.is_default=true` 的基础套餐。基础套餐不可删除，且服务端必须强制保持 `enabled=true`；注册、管理员新增用户、基础套餐周期重置和普通套餐删除后的活动订阅迁移都依赖该套餐。

基础套餐到期后由 Worker 按基础套餐 `duration_days` 重置新周期，默认基础套餐是 30 天月度口径。付费套餐到期后自动切回基础套餐。付费套餐重复购买、订单支付成功或兑换码续费都从 `max(existing_expires_at, now)` 延长有效期、叠加套餐流量，并保留已用流量。

公共套餐列表和后台套餐管理的边界不同：`GET /api/plans` 只返回 `enabled=true` 且 `is_deleted=false` 的可购买套餐；后台统一使用 `GET/POST/PATCH(or PUT)/DELETE /api/admin/plans` 做管理，分组授权范围使用 `PUT /api/admin/plans/{id}/line-groups` 这一兼容内部接口实现。普通套餐删除采用逻辑删除，删除后活动订阅迁移到基础套餐，并清理套餐授权、用户入口授权和用户出口运行授权，再标记接入节点配置 dirty。

套餐入口授权以内部 `plan_line_groups` 兼容关系为准，但产品语义只表示套餐授权哪些分组。订阅、用户订阅读模型、access-agent 心跳和后台套餐节点展示必须基于同一套规则：授权分组展开其分组内绑定节点对应的已启用、已同步且可连接中转入口。

## 数据面路径

1. 用户客户端下载 `/sub/{token}` 获取 Clash/mihomo YAML。
2. 中心按套餐授权分组展开分组内绑定节点对应的已启用、已同步且可连接中转入口，并同步 `user_access_line_assignments`。
3. 订阅只包含中转入口地址，即内部 `access_lines.listen_host/listen_port`，不包含出口地址、第三方代理地址、出口真实 IP 或代理凭据；一个入口绑定多个出口时，多个订阅节点可以共用同一个 `server/port`，但凭据和节点名必须按绑定节点区分。
4. 用户连接接入节点上的 Xray inbound。
5. 接入节点通过当前固定的 `credential` 鉴权和 `xray_email` 统计映射还原稳定 `xray_user_key`。
6. 中心服务按入口出口绑定节点编译用户级 outbound/routing 所需的内部缓存；当前 PostgreSQL 闭环会在订阅、用户订阅读模型和 access-agent 心跳时清理或重建这些缓存。
7. access-agent 心跳在 `config_status.required=true` 时获取中心生成的 `AccessConfig`，其中包含 Xray inbound 用户、SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 outbound 和按用户 `xray_user_key` 生成的 `routing_rules`；`config_status.required=false` 时 `config=null`。如果控制面要求刷新但 `config=null`，agent 必须写入空入口配置清理旧用户，不能静默保留旧 Xray 配置。
8. 用户流量从中转节点转发到该绑定节点对应的内部 `exit_endpoint`；共享入口通过 `xrayc-line-<access_line_id>--<xray_user_key>` 统计 email 保留绑定节点归属，限速用户也共用该入站、靠每用户 fwmark + 带 mark 出站区分，不再按用户拆单独入站。
9. access-agent 从接入节点侧采集累计流量、运行指标、在线会话和出口健康，主动上报中心；运行数据分别走 `/api/agent/access/metrics`、`/api/agent/access/sessions` 和 `/api/agent/access/probes`。
10. 中心用快照差值写入账本，并在过期、禁用或超额时触发配置刷新剔除用户。

## 运行数据与运营中心

运营中心展示的真实在线、连接数、上下行速率和探测延迟必须来自中转节点侧观测。`/metrics` 写入中转入口运行指标快照，`/sessions` 写入在线用户会话摘要，`/probes` 写入中转节点到内部出口 endpoint 的组合探测结果；中心只负责鉴权、校验、落库和聚合展示。

禁止使用订阅数量、授权用户数、心跳是否存在、中心侧请求延迟、出口 endpoint 数据或模拟数据冒充真实在线、连接、速率和探测延迟。运行数据缺失或超过新鲜度窗口时，运营中心应显示未知、过期或未上报，而不是显示 0 或伪造正常状态。

## 入站识别边界

进入用户级计费、用户级出口映射和超额剔除主链路的入站协议，必须能稳定映射到 `xray_user_key`。当前 V2 主链路只承诺以下方式：

- 协议账号天然支持稳定用户标识，例如 VLESS、VMess、Trojan、Shadowsocks 多用户账号。
- HTTP/SOCKS 等入站开启账号认证，并能映射到稳定用户。

独立端口、独立路径、独立监听等复杂线路运维方式不作为当前订阅和计费方案。无法稳定识别用户的入口只能作为内部测试、管理工具或非计费入口，不得进入主计费链路。

## 内部兼容映射与出口可用性

底层兼容映射只服务“入口出口绑定节点”后的实际出站下发。控制面按绑定关系和 `access_node -> exit_endpoint` 组合探测状态判断某个绑定节点是否可编译为 outbound/routing；不可用时必须从订阅输出和 `AccessConfig` 中移除或暂停相关入口，并标记接入节点配置 dirty。系统不自动测速决定容量，不做策略型调度、用户迁移或恢复回拨。heartbeat 下发的 `AccessConfig` 已能把当前接入节点视角可用的 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 出口编译为用户级 routing。真实供应商出口仍需按协议做公网 E2E 验收。

内部运行成员状态：

| 状态 | 语义 |
|------|------|
| `healthy` | 探测正常，可编译为该绑定节点的出站目标 |
| `degraded` | 探测异常或质量下降，默认暂停输出到订阅和新配置，等待恢复或人工处理 |
| `draining` | 维护中，从订阅和下一次 `AccessConfig` 同步中移除相关入口 |
| `offline` | 不可用；从订阅输出和 `AccessConfig` 中移除相关入口，并标记接入节点配置 dirty |

出口恢复后必须重新通过探测或管理员确认，再重新编译订阅和 agent 配置。

## 订阅安全边界

订阅接口只输出订阅入口。以下内容禁止出现在订阅、普通日志、公开文档和提交说明中：

- `exit_endpoints.host`。
- 第三方 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 上游地址。
- 第三方账号、密码、密钥、完整代理 URL。
- 出口真实 IP、测试服务器地址、订阅 Token、access-agent Token、支付回调密钥。

## 计费规则

计费以接入节点上报为准。access-agent 通过接入节点本机 Xray Stats API 读取用户累计上行和累计下行。中心服务必须按快照差值计算增量：

1. 按 `access_node_id + access_line_id + xray_user_key` 读取上一条快照。
2. 当前累计值减上一条累计值，得到增量。
3. 基线快照不扣费。
4. 乱序、过期或小于上一快照的累计值不得直接入账。
5. 根据订阅剩余额度和扣费倍率写入 `usage_ledgers`。

禁止把累计计数器直接累加到账本。

Stats API 只允许在中转节点本机或受控容器网络监听。中心服务不直连各节点 Xray，也不从第三方出口侧反推用户流量。Xray client `email` 使用 `xrayc-line-<access_line_id>--<xray_user_key>` 编码，保证同一用户多个中转入口可以独立入账；解析层兼容历史前缀，只用于旧配置过渡。没有真实用户级累计计数和会话观测前，不得用中心侧估算冒充真实采集。
