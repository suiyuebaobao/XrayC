# 流量生命周期

access-agent 从本机 Xray Stats API 读取用户累计流量。中心按 `access_line_id + xray_user_key` 保存最新快照，并用本次累计值与上次快照求差。

入账写入 `usage_ledgers`，再按当前单一套餐额度扣减。用户禁用、过期或额度耗尽时，中心标记接入节点 dirty，agent 下一轮刷新会剔除用户。当前 V2 使用统一账本。

详细流量日志的保留期由后台“运营中心/运营策略”的 `traffic_log_retention.detail_retention_days` 控制，默认 14 天，允许 1 到 3650 天。Worker 在维护周期内把超过保留期的 `usage_ledgers` 明细先按来源、用户、入口、接入节点和出口端点汇总到 `usage_daily_rollups` 与 `usage_hourly_rollups`，再删除对应明细；该清理只改变明细可追溯范围，不再次扣减 `user_subscriptions.used_bytes`。运营排行和健康检查历史统计读取保留明细加汇总，管理员用户级“流量日志”只展示仍保留的明细。

管理员用户管理里的“设备管理”是 IP 观察列表，数据来源为成功订阅拉取事件和 access-agent 节点使用事件。同一明文 IP 在展示层合并为一条；节点使用侧受会话和流量明细留存影响，订阅拉取事件仅用于排障观察，不进入账本汇总，也不用于封禁、限速或扣费。

`WORKER_RUNTIME_RETENTION_DAYS` 只控制 metrics、traffic snapshots、sessions、probes 等运行态快照保留，不控制用户详细流量日志。需要调整用户流量日志明细保留天数时，应修改运营策略而不是 Worker 环境变量。

套餐周期由 Worker 维护。基础套餐到期后按基础套餐 `duration_days` 重置为新的基础周期，默认 30 天月度口径，并清零 `used_bytes`。付费套餐到期后切回基础套餐。付费套餐重复购买或兑换码续费会从 `max(existing_expires_at, now)` 延长有效期，叠加 `limit_bytes`，保留 `used_bytes`。
