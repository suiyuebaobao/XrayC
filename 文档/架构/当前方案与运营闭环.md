# 当前方案与运营闭环

本文是当前公开文档的总口径。任何 README、方案、接口、部署、前端、测试和运维文档与本文冲突时，以 `开发方案.md` 为最高依据，并同步修正文档。

## 产品主路径

当前 XrayC V2 只保留一条运营主路径：

1. 在出口管理维护出口线路。第三方线路、普通自建上游线路和中转节点本机出口服务创建的线路都在同一个出口清单里维护。
2. 在入口管理里维护中转节点上的用户入口，例如协议、传输、安全层、监听端口、TLS/SNI、WebSocket 和 CDN 字段。
3. 创建入口出口绑定节点。每个绑定节点只组合一个入口和一条出口线路，是后续分组和订阅输出的最小节点。
4. 在分组里把绑定节点归类到一层分组，例如 AI 分组、游戏分组、GPT 分组、视频分组。
5. 在套餐里授权分组并设置分组倍率。
6. 用户通过唯一订阅入口 `/sub/{token}` 拉取 Clash/mihomo YAML。

分组不绑定中转节点，不直接保存出口线路，也不生成入口。一个分组只负责归类入口出口绑定节点；同一个入口可以绑定多条出口线路，同一条出口线路也可以被多个入口绑定，每个绑定节点生成一个用户可见订阅节点。

## 订阅边界

系统只有一种订阅方式：`/sub/{token}`。不存在按客户、设备或客户端单独拆出的第二套订阅，也不存在按客户单独拆线的线路。

成功拉取订阅时记录的来源 IP 只进入管理员后台的 IP 观察列表，用来和节点使用来源合并排障；它不改变唯一订阅模型，不产生新的用户凭据，也不参与线路分配。

订阅生成顺序是：

1. 校验用户、订阅 token、当前订阅、额度和套餐状态。
2. 读取用户套餐授权的分组。
3. 展开这些分组中的入口出口绑定节点。
4. 过滤已启用、已同步且可连接的绑定节点。
5. 按绑定节点的入口协议和客户端网络模式输出节点。

订阅只暴露入口地址、入口协议、客户端网络模式、用户凭据和节点名。订阅、普通用户接口、公开日志和测试报告不得暴露出口管理真实出口地址、第三方账号密码、代理 URL、Reality 私钥、部署 token、订阅 token 或真实服务器地址。

## 出口管理和本机出口服务

出口管理只维护统一出口线路列表。来源只作为展示列和排障字段。

本机出口服务只在中转节点详情中使用，用于批量创建该服务器自己的出口线路。主流协议行展示 VLESS、HY2、Shadowsocks、Trojan、SOCKS5、HTTP；其中 SOCKS5、HTTP 免证书，保存时由后端自动生成 `username` + `password` 凭据，凭据只进 agent 必需的连接配置，不入订阅、普通用户接口和公开日志。每条线路先选「连接方式」再给协议（用连接方式显式驱动取代旧的“隐式选域名留空=免证书”）：本机出口连接方式只有两档——“IP 直连（免证书）”“域名直连（灰云）”，且选项只列该节点支持的（IP 直连永远在；节点有直连域名才出现“域名直连”）。本机出口不提供 CF 直连：CF（橙云）只用于给入口藏中转 IP，本机出口是中转节点同机自家出口、中转直接连它（本地/内网），塞进 CF 绕一圈无意义，所以本机出口不支持 CF 域名/CF 协议（选域名下拉只列 `kind=direct` 域名）。选 IP 直连不用选域名（`node_domain_id` 留空）、协议下拉只放 Reality/SS/SOCKS5/HTTP，不再露出要域名的协议；选域名直连要选一个直连域名（`node_domain_id`=该直连域名）、协议放 Trojan/HY2/VLESS-TLS。后端口径不变：连接方式只是把“`node_domain_id` 空 / 对应直连域名 id”做成显式选择，`validate_local_exit_cert_domain` 护栏在协议字段校验前照旧拦。每条线路再按协议行选择网络模式、端口和必要字段，前端自动生成后端所需连接配置，不要求管理员填写连接 JSON。服务地址默认读取所属中转节点地址，管理员只在默认值不符合实际监听地址时覆盖。

本机出口服务保存后只把线路写入统一出口管理，并记录“自己创建 / 所属中转服务器”。它不会自动创建入口，不会自动创建绑定节点，也不会加入分组。

本机出口线路支持就地编辑和删除：本机出口页列出该节点已建的自建出口线路，可直接改 name、host、port、启用状态、选用的节点域名，以及 `outbound_config`/`stream_config` 协议配置。改配置必须走护栏重新校验、不绕过——要证书协议（Trojan、HY2、VLESS-TLS）在无证书域名节点上仍被拦。接口走 `GET/PUT/DELETE /api/admin/access-nodes/{id}/local-exit-lines`，改完置所属节点 dirty，触发下一轮 agent 同步收敛。中转节点、入口、出口、本机出口服务全部可编辑。

VLESS Reality 的规则：

- 作为用户入口时，Reality 只允许 TCP、XHTTP 或 gRPC，不允许 UDP、XUDP 或 WS。
- 作为本机出口服务时，后端自动生成 Reality public key、private key 和 short id，管理员不需要手填 public key。
- 连接第三方 VLESS Reality 上游时，出口管理表单才要求填写供应商提供的 Reality public key、short id、fingerprint 等字段。

## 中转节点和 Agent 安装

Agent 安装提供两条路径：可选“一键安装 Agent”自动 SSH 安装，以及保留的手动安装说明。一键安装只在本次请求内使用 SSH 主机、端口、用户、密码或私钥，完成后不得保存到数据库、审计日志、部署任务、前端任务列表或公开日志；手动安装说明用于受限网络或人工接入场景。

一键安装的 SSH 目标必须是 IP：域名（尤其橙云 CF 代理）无法直连 SSH，后端校验 `ssh_host` 为 IP，传域名直接拒绝。SSH IP 是节点独立的运维字段，与客户连接地址（域名直连 `cert_domain` / CF直连 `cf_domain` / IP直连 `ip_direct_address`）毫无关系、不联动；前端 SSH Host 自动填值来源是 `ip_direct_address`，而不是任何客户连接地址或 `public_host`。客户连接地址照常可填 IP 或域名，与 SSH 无关。

接入节点部署口径是单内核 Xray（`xray-core`）+ `access-agent`。部署产物必须包含 access-agent 和 xray 镜像包；目标服务器固定启动 Xray，所有入口都由 Xray 处理。

正确流程是：

1. 中心服务器构建并发布 agent 安装产物。
2. 管理员选择“一键安装 Agent”或打开 Agent 手动安装说明。
3. 一键安装由平台临时 SSH 到目标服务器执行 `scripts/deploy-access-agent.sh`；手动安装由管理员到服务器本地执行同一脚本。
4. 安装脚本在服务器本地生成或复用节点 ID 与 access-agent token。
5. 安装成功后，脚本输出节点鉴权码。
6. 一键安装成功时平台解析节点鉴权码并自动创建中转节点；手动路径使用节点鉴权码完成平台绑定。
7. 中心通过 agent 心跳、配置结果、运行指标、会话、探测和真实流量验证节点状态。

平台创建安装任务时会创建部署任务，并把任务 ID 与一次性上报 token 写入执行模板。`scripts/deploy-access-agent.sh` 在安装过程中回传当前步骤、进度、完成状态和脱敏错误摘要；后台只展示部署状态和脱敏结果，不持久化 SSH 凭据。装机进度在管理面板前端实时显示、无需手动刷新页面：前端对部署任务列表接口做轮询自动刷新，进行中任务每约 3 秒自动拉一次最新步骤/进度、进入终态（成功/失败/取消）后停轮询，管理员不必手动刷新页面看进展。后端不变：agent 经 `/report` 实时回报，列表接口已返回当前进度，轮询是纯前端行为。

入口管理页面维护中转节点入口和入口出口绑定节点，不在中转节点页面直接把绑定写进分组。分组只在分组里选择绑定节点，套餐只授权分组。

Agent 安装脚本会提示证书域名和 ACME 邮箱；一键安装和手动安装只要两者同时存在，就会自动申请 SSL 证书并写入 agent 环境。节点为多域名时，agent 从心跳下发的 `node_domains` 列表遍历逐个签证书：直连域名走 HTTP-01、CF 域名走 DNS-01（`certbot-dns-cloudflare` + CF Token），各域名各自签自己的证书，已有效（`x509 -checkend` 通过）即跳过。access-agent 心跳上报各证书域名、状态、有效期、剩余天数和脱敏错误摘要，管理平台在中转节点卡片展示。续期 SSL 是单节点任务：平台写入该节点待续期请求，agent 下一次心跳领取后使用本机 certbot 非强制续期，成功后 reload Xray 并回报脱敏结果；不得回传证书正文、私钥路径、certbot 原始日志或真实凭据。

## 节点多域名模型 + 协议按选中域名过滤 + DNS-01 CF 证书

单台中转节点固定只跑一个 Xray 内核，但对外可同时暴露多行接入地址：一个 IP 直连地址（免证书）+ 多个直连域名 + 多个 CF 域名。不同入口编译成各自端口的 Xray inbound，计费仍按 Xray Stats 快照差值、与协议无关。权威口径见 `开发方案.md` §2.2.1 与 §2.2.2，及对应 spec。

- **多域名模型**：迁移 `202606230001` 新增 `node_domains` 表（一对多），按 `kind∈{direct,cf}` 分两组。节点可有多个直连域名（灰云，HTTP-01 签证书）和多个 CF 域名（橙云，DNS-01 签证书）。旧单 `cert_domain`/`cf_domain` 保留为各组**主域名**快捷指针、向后兼容，写入以 `node_domains` 为准；`cf_enabled` 由“存在任一 `kind='cf'` 域名”派生，无独立开关。IP 直连地址（`ip_direct_address`）给 VLESS（Reality 或 普通 none）/ SS 直连、免证书。每个 `node_domains` 行各自带 `acme_email` 与 `cert_status`（心跳回填）。删除仍被入口或本机出口引用的 `node_domain` 行必须拒绝（先改引用再删）。
- **显式连接方式驱动（入口三档、本机出口两档）**：入口和本机出口都**先选「连接方式」再给协议**，取代旧的“隐式按地址/CDN 推地址类型”。**入口三档**——“IP 直连（免证书）”“域名直连（灰云）”“CF 直连（橙云）”，只列该节点支持的；CF 直连对入口有意义（开 CDN 橙云代理藏中转 IP）。**本机出口只两档**——“IP 直连（免证书）”“域名直连（灰云）”，**不支持 CF 直连**：本机出口是中转节点同机自家出口、中转直接连它（本地/内网），塞进 CF 绕一圈无意义。
- **入口/出口选用节点域名**：入口（`access_entries.node_domain_id`）和本机出口（`exit_endpoints.node_domain_id`，免证书出口留空）下拉选用该节点的某个域名。创建/编辑时下拉列出 `node_domains`（入口可按 direct/cf 两组过滤，本机出口只列 `kind=direct` 域名）。
- **协议护栏按选中连接方式/域名 kind 判定**：入口选 CF 域名时只放 (VLESS|Trojan) + (WS/gRPC/XHTTP) + TLS（CF 只代理 HTTP(S)，Reality/HY2/SS/裸 TCP 无法过 CF）；选直连域名时入口放全族 TLS（Trojan/HY2/VLESS-TLS 等），本机出口放 Trojan / HY2 / VLESS-TLS；不选（留空，免证书）时入口放 VLESS（Reality 或 普通 none）/ Shadowsocks，本机出口放 Reality / SS / SOCKS5 / HTTP；本机出口无 CF 档，不出现 CF 域名/CF 协议选项。要证书协议（Trojan/HY2/VLESS-TLS）在无证书域名节点上，须在协议字段校验之前就被拦，返回“请先配域名直连地址”的清晰原因。前端按选中连接方式/域名 kind 过滤协议下拉，后端 `validation.rs` 护栏兜底。
- **IP 直连入口 VLESS 两种安全模式（Reality / 普通 none）**：IP 直连（免证书）入口的 VLESS 支持 **Reality**（默认，抗封伪装，官方 Xray 口径仅 TCP/XHTTP/gRPC，不开 UDP/XUDP/WS）与 **普通（none）**（裸连免证书，按能力开放 UDP/XUDP/WS，与“非 Reality VLESS 才开 UDP/XUDP/WS”一致；代价是无 TLS/Reality 伪装、流量特征裸露易被 DPI 识别封锁，属可选项非默认）。故 IP 直连入口协议集 = VLESS（Reality 或 普通）+ Shadowsocks，**普通 none 是想在 IP 直连上拿到 UDP/XUDP 的唯一正路**（Reality 不开 UDP/XUDP）。本机出口口径不变（仍 IP 直连/域名直连两档，不涉及此变更）。
- **入口表单「路径 / Host / Server Name」自动默认值**：这三字段按“协议×安全×网络模式”自动带出默认值（未手改才填，管理员手改后尊重不覆盖，编辑态已有值保留），省去手填。Server Name（SNI）——VLESS+Reality→伪装大站 `www.cloudflare.com`（免证书 decoy，与后端 `server_names` 兜底一致），走 TLS 的（VLESS+TLS/Trojan/HY2）→自有证书域名，普通 VLESS(none)/SS→空；路径——gRPC→服务名 `xrayc`，WS/XHTTP→`/xrayc`，tcp/udp/xudp→空；Host——WS/XHTTP→CF 橙云用 CDN Hostname、否则回退 SNI/证书域名，其余→空。
- **CF API Token（仿 SSH 凭据）**：只在安装/续期请求期使用，写节点本机 `/etc/letsencrypt/cloudflare.ini`（0600），**不落控制面库、不入日志/审计/心跳**；心跳只上报 CF 证书域名/valid/剩余天数/脱敏错误摘要。
- **CF 证书走 DNS-01，多域名各自签**：`cf_cert_mode=dns01`（默认，有 token）用 `certbot-dns-cloudflare` + CF Token 给每个橙云域名签**它自己的**真 LE 证书，CF 入口证书锚定该域名 `/etc/letsencrypt/live/{cf_domain}/`，`certbot renew` 自动续期；无 token 退回 `reuse_direct` 复用灰云证书并要求 CF SSL=Full（非 strict）。DNS-01 真证书下 Full 与 Full(strict) 都成立，本方案不自动改 SSL 模式（Token 仅 DNS 权限），文档建议用户设 Full(strict)。多域名节点下各域名各自签证书：agent 从心跳下发的 `node_domains` 列表遍历逐个签证书（`kind=direct`→HTTP-01、`kind=cf`→DNS-01），各域名 `x509 -checkend` 仍有效即跳过，不引入新机制。
- **端口**：同一节点 enabled 入口端口唯一（443 只给一个）；CF 入口必须落 CF 支持端口之一（443/8443/2053/2083/2087/2096）。**智能默认端口**：新建入口/本机出口时端口自动填「合法且未占用」值——CF 橙云在 `443/8443/2053/2083/2087/2096` 挑首个空的、IP直连/灰云直连（对外入口）优先防封端口 `443/8443/2053/2083/2087/2096/8080/2052/2082/2086/2095` 再回退 `10000+`、**本机出口用高端口（直接从 `10000` 起找首个空的）不抢防封端口**（防封端口留给对外入口，避免本机出口先占 443 又撞 CF 入口）；避开该节点已用端口（启用入口 `listen_port` ∪ 该节点自建本机出口 endpoint `port`）；节点/连接方式变化时重算，编辑既有入口不覆盖现有端口；前端即时校验端口占用/CF 端口合规并提交前红字提示，后端端口唯一性校验作兜底。
- **订阅按入口选中域名分化**：入口按其选中的 `node_domain` 输出 SNI/连接地址——CF 域名入口 `server=sni=该 CF 域名`、transport=WS/gRPC/XHTTP；直连域名入口 `server=sni=该直连域名`；IP 直连线 `server=ip_direct_address`。未选时回落节点主域名/IP，行为同今天。多直连/多 CF 域名支持防封轮换：切换入口选用域名即切换该入口流量出口地址。仍只暴露中转入口参数，不输出出口真实地址或凭据。
- **部署任务可清理 + 卡死自愈 + 进度前端实时刷新**：失败/回滚的一键安装不再留下永久卡死的部署任务。新增 `DELETE /api/admin/deployment-tasks/:id` 与 `POST /api/admin/deployment-tasks/:id/cancel`，前端列表加删除/取消按钮；`waiting_for_server` 等非终态任务超时未推进由 worker/扫描自动标记 `failed`（超时未回连）。装机进度由前端轮询实时刷新（进行中每约 3 秒自动拉一次、终态停轮询），无需手动刷新页面；后端不变（agent 经 `/report` 实时回报，列表接口已返回当前进度）。
- 数据迁移走加表、加列、全部可空：迁移 `202606230001` 加 `node_domains` 表并把旧 `cert_domain`/`cf_domain` 回填为各组主域名行，`access_entries`/`exit_endpoints` 加 `node_domain_id`（`ON DELETE SET NULL`）；`cf_cert_mode` CHECK 放开到 `('reuse_direct','dns01')` 默认 `dns01`、`cf_enabled` 改为派生，现有纯直连/纯 IP 节点不受影响。

## 部署架构

代码是前后端分离架构：

- 前端在 `frontend/`，使用 Vue 3、Vite、TypeScript 和 Element Plus。
- 后端 API、Worker、领域逻辑和 access-agent 使用 Rust。
- 数据库使用 PostgreSQL 16+。
- 前端通过 HTTP API 访问后端，不直接访问数据库或 agent。

当前默认部署是单主控服务器 Docker Compose：PostgreSQL、API、Worker 和 Caddy。Caddy 是唯一 HTTP 入口，负责托管前端静态资源、反向代理 `/api/`、`/sub/`、`/health` 和部署产物下载。

架构上允许前端、后端和数据库部署在不同服务器，但默认推荐先使用单主控服务器部署。拆分部署时必须显式配置前端 API 地址、后端 `DATABASE_URL`、Caddy 反代目标、数据库访问网络和 TLS/防火墙策略。

当前公开部署口径只使用 Caddy 作为唯一 Web 入口，不再拆第二个 Web sidecar。

PostgreSQL 自动备份由管理平台运营策略 `database_backup` 控制，默认启用、1 天一次、保留 30 天；`DATABASE_BACKUP_DIR` 只控制 Worker 写入 dump 的目录。自动备份只覆盖 PostgreSQL 业务数据，`.env`、字段加密 keyring provider、部署产物和 TLS/Caddy 配置仍需单独备份。

运营中心的生产告警来自真实数据派生：中转节点心跳超时生成离线告警，access-agent 上报的 SSL 状态生成证书缺失、失效或临期告警，数据库备份状态生成备份失败告警。告警只做运营可视化，不替代配置同步、节点探测或真实客户端连通性测试。

## 一键部署脚本（install.sh）

运维侧一键部署脚本 `install.sh` 在**目标机本地**运行，提供交互菜单或 `--role` 非交互参数，从 5 个角色里选一个把对应组件装起来：

1. **一体机**（`aio`）：postgres（本地库时）+ api + worker + caddy（含前端），带 Caddy。
2. **仅前端**（`frontend`）：caddy（含前端），同源反代到后端公网地址，带 Caddy。
3. **仅后端**（`backend`）：api + worker，对外暴露端口，不带 Caddy。
4. **仅数据库**（`database`）：postgres，不带 Caddy。
5. **镜像仓库**（`registry`）：registry + caddy（仅给 registry 上 HTTPS），带 Caddy。

`install.sh` 只装管理平台，**不含 node 节点角色**；node 节点仍走管理面板现有的一键 SSH 安装（`deploy-access-agent`），不变。脚本只管本机，不做中心远程 SSH 编排多机（远程装 node 仍走面板现有一键安装）。`install.sh` 自身与 compose 模板也由自建中心机 Caddy 用 HTTPS 提供，可 `curl -fsSL https://registry.example.com/install.sh | bash` 一条命令装。重跑幂等：检测到该角色已装时提示升级 / 覆盖重装 / 取消，覆盖前二次确认且**不动数据卷**（postgres 数据、registry 存储、节点运行态保留）。装前检测端口占用，占用者是本项目上次安装则走升级流程，**陌生服务（他人的 nginx/代理服务/别的业务）占用时立即中止报告、绝不自动停别人的服务**。

镜像分发走**自建 registry**：发版时在中心构建机构建 api/worker/caddy（caddy 含前端）镜像并 `docker push` 到 registry，安装时谁装谁公开 `docker pull`（HTTPS，无需 `docker login`、无鉴权）。第三方基础镜像（`postgres`、`registry:2`、caddy 基础镜像）统一 re-tag + push 搬进自家仓库，**装机只访问自家 registry、完全不依赖 Docker Hub/ghcr**，规避国内或 Docker Hub 被墙导致拉取卡死。registry 走 HTTPS 是 Docker 客户端硬要求（非鉴权），由 ⑤ 的 Caddy 自动签 ACME 证书并反代到本机 registry 容器。

前后端拆分鉴权穿透：单一公网入口是前端（面板）域名，浏览器和节点 agent 都只连前端域名；前端 Caddy 把 `/api/*`、`/sub/*`、`/health`、`/api/deploy/artifacts/*` 反代到后端公网地址，其余路径发前端 SPA。前端是静态文件 + 透明反代，前后端之间不做服务间鉴权、无共享密钥；真正的鉴权是浏览器↔后端：Access Token 走 `Authorization: Bearer` 头，Refresh Token 走 `HttpOnly` Cookie（host-only、`SameSite=Lax`、`Secure` 由 `XRAYC_REFRESH_COOKIE_SECURE` 控制）。因为 Refresh Cookie 是 host-only + `SameSite=Lax`，只认浏览器当前访问域名，所以**浏览器只连前端域名 + 前端同源反代到后端是鉴权决定的唯一正确走法**，让浏览器直连后端域名会被 SameSite 挡、需 CORS 带凭证而失败。唯一一处真实代码改动是 `deploy/caddy/Caddyfile` 把反代目标参数化为 `{$XRAYC_API_UPSTREAM:api:3000}`：一体机默认同机 `api:3000`，仅前端填后端公网地址。

初始管理员自带：生产安装口径是 `XRAYC_ENV=production` + `SEED_DEMO_DATA=false` + 显式 `JWT_EXPIRES_IN`/`JWT_REFRESH_EXPIRES_IN`，production 下禁用 demo 种子，因此一体机 / 仅后端安装时脚本走另一条路径建**首个真实管理员**（账号 `admin`，随机密码装完仅打印一次，区别于 demo 账号），并置 `XRAYC_REFRESH_COOKIE_SECURE=true`、`XRAYC_PUBLIC_BASE_URL=https://<面板域名>`。密钥（DB 密码、JWT 密钥）一律本地生成、写 0600 权限 `.env`、被 `.gitignore`/`.dockerignore` 排除，不进 git/日志/截图。安装后端/一体机时迁移由 worker 启动自动跑（`MIGRATIONS_DIR=migrations`，镜像内置迁移文件）。装完按角色做健康检查，并已在真机试验通过（自建 registry 免墙拉取、DB 跨机公网拆分、前后端公网拆分鉴权穿透均实测）。完整设计、各角色配置输入/密钥和健康检查口径见 `文档/部署/2026-06-24-一键部署脚本设计.md`。

## 用户级限速

当前限速是中转节点内的用户级平滑限速。套餐提供默认 `rate_limit_bps`，用户字段可以覆盖套餐值，且用户值优先级最高。

TCP 与 UDP 共用同一个 `rate_limit_bps`，不新增 UDP 独立速率字段，不按 HY2、XUDP、QUIC、游戏 UDP 或 DNS 等应用协议拆分限速。限速用户与不限速用户共用同一入站（守真实端口）、靠每用户 fwmark 区分，确保上传和下载都能按用户限速；订阅端口恒为线路真实端口、不因限速变化。

限速实现不修改 Xray 源码。access-agent 使用 Xray `sockopt.mark`、Linux tc、connmark、IFB 和 HTB 同步规则。limiter 关闭、dry-run、命令失败或 mark 冲突无法分配时必须 fail-closed，不得 reload 新 Xray 入站。

用户级计费、在线会话、速率和超额剔除必须来自 Xray Stats API，不能用接口构造值、中心侧估算或空快照冒充真实采集。

## 套餐周期和续费

系统必须始终存在 `plans.is_default=true` 的基础套餐。基础套餐不可删除，服务端强制保持启用。

基础套餐到期后由 Worker 自动重置为新的基础套餐周期。当前实现按基础套餐 `duration_days` 计算下一周期，默认基础套餐是 30 天月度口径，不表示自然月 1 号统一重置。付费套餐到期后自动切换回基础套餐，并清理付费套餐的分组授权、倍率和限速影响。

付费套餐重复购买或兑换码续费沿用当前单一订阅模型：从 `max(existing_expires_at, now)` 延长有效期，叠加套餐流量，不清零已用流量。支付功能当前暂停，订单查询保留；未来恢复支付时，支付成功也必须走同一订阅开通或续费逻辑。

## 配置同步和失效闭环

删除线路、停用线路、清空分组、套餐授权变化、用户禁用、用户超额、订阅 token 撤销或重置时，不能只让订阅下载失败。中心必须标记相关中转节点待同步，access-agent 下一轮心跳必须收到新配置或空配置，移除旧 Xray 入站用户和旧 routing。

agent 应用配置后必须回报 `/api/agent/access/config-result`。只有回传版本和 hash 与中心期望一致，且结果时间不早于最近一次 dirty 标记，中心才能清理待同步状态。

## 测试和文档规则

真实发布闭环必须使用真实订阅、真实 access-agent、真实中转节点、真实客户端和真实流量。只用 mock、中心侧请求、接口构造值、旧客户端配置或订阅下载结果不能证明运行态闭环。

公开文档更新必须同步覆盖：

- `开发方案.md`
- `README.md`
- `AGENTS.md`
- `文档/说明.md`
- 架构、接口、部署、前端、测试、运维文档
- `docs/superpowers` 中仍作为当前方案依据的计划和规格
- 文档残留检查脚本

协议、客户端订阅格式、Xray、Caddy/Docker/PostgreSQL/Cloudflare 或其他第三方行为存在不确定时，必须先查官方文档或上游主仓库文档，再更新方案、规则、测试说明和实现。官方依据推翻旧描述时，必须同步删除或改写冲突旧口径，必要时把旧模式加入文档残留检查脚本。

历史日报可以保留历史事实，但必须在涉及旧模型时标注“历史口径已废弃”或指向当前方案，不能让历史记录看起来仍是当前操作路径。
