# V2 分组模型

本文是公开文档中描述出口管理、分组、套餐和订阅结构的统一口径。

## 模型层级

1. 出口管理保存出口线路。出口管理由 `exit_resources` 和 `exit_endpoints` 承载，记录外部供应商线路、普通自建线路和中转节点本机出口服务登记后的多协议线路。出口管理只面向后台运营和 access-agent 配置编译，不能进入订阅、普通用户接口、公开日志或测试报告。
2. 入口管理把中转入口和出口线路组成绑定节点。入口由 `access_entries` 承载，绑定节点由 `access_entry_exit_bindings` 承载；一个绑定节点等价于一个用户可见订阅节点。
3. 分组只有一层。分组由 `line_groups` 和 `line_group_binding_nodes` 承载，例如 AI 分组、游戏分组、GPT 分组、视频分组；每个分组直接选择入口出口绑定节点，不拆多级结构。
4. 套餐直接授权分组。套餐选择哪些分组，用户订阅就从这些分组内绑定节点对应的已启用、已同步且可连接中转入口输出节点；套餐不维护层级结构，不直接绑定真实出口，不维护运行成员，也不再保存每个分组展示几条线路的产品策略。
5. 订阅设置不再自定义分组。订阅设置只维护 YAML 基础字段、文件名、更新间隔、线路过滤和可选自动测速组；规则设置页集中维护通用规则和可复用规则库；分组只绑定规则库，普通 `select` 分组和订阅入口由套餐授权分组自动生成。

## 选路规则

- 分组直接归类入口出口绑定节点；订阅只输出套餐授权分组内绑定节点对应的已启用、已同步且可连接入口协议、地址、端口和用户凭据。
- 同一条出口线路可以被同一个或多个入口多次绑定，从而生成多个订阅节点；同一个入口也可以绑定多个出口生成多个订阅节点。
- 底层 `access_lines`、`exit_pools`、`exit_pool_members` 和 `user_exit_assignments` 只作为绑定节点后的内部兼容结构存在，用于 access-agent 获得当前可用出口映射；它们不是分组、套餐或中转节点页面的运营对象。
- 中转节点和 access-agent 只接收运行所需的中转入口、出口协议档、运行兼容成员和用户出口映射；普通用户永远不接触出口管理真实出口、出口凭据或内部探测配置。
- 规则库由 `subscription_rule_sets` 承载，分组绑定关系由 `line_group_rule_set_bindings` 承载；同一规则库可被多个分组绑定，修改规则库后所有绑定分组的订阅规则同步生效。旧 `line_groups.dedicated_rules` 只作为迁移兼容字段，迁移时会生成“分组名-历史规则”规则库并绑定回原分组。

## 写操作一致性

出口管理 endpoint 删除、修改或不可用时，控制面必须同步维护入口出口绑定节点、内部兼容状态、用户出口映射缓存、用户入口授权、订阅输出和接入节点 dirty 状态，避免订阅或 agent 配置继续引用已删除或不可用出口。绑定节点对应状态变为 `degraded`、`draining` 或 `offline` 时，也必须按同一一致性规则清理；self-hosted 出口归属迁移时旧所属节点和新所属节点都要 dirty。

## 兼容命名

当前实现中仍可能出现 `line_groups`、`plan_line_groups`、`access_lines`、`exit_pools` 等历史表名或兼容接口名。公开产品语义必须按本文解释：

- `line_groups` 相关读写只应被描述为普通分组，不再描述为多级分组或套餐直接维护的自定义客户端分组。
- `plan_line_groups` 只表达套餐授权分组的兼容关系；用户订阅和运行时授权必须随绑定节点、出口成员、用户状态、订阅 token 状态和套餐状态自动收敛。
- `exit_pools` 只作为内部兼容集合，不是用户可见分组，也不是套餐授权对象。
