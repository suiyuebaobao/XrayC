# 文档说明

## 项目简介

XrayC V2 是 Rust-only 的中转节点控制系统。运营先在出口管理维护第三方出口、普通自建上游或中转节点本机出口服务，所有来源的线路都在同一个出口管理里维护；入口管理把中转入口和出口线路组成入口出口绑定节点；分组只有一层，例如 AI 分组、游戏分组、GPT 分组、视频分组，每个分组直接选择不同绑定节点；套餐直接授权分组，不维护多级结构或组合分摊策略；用户只连接订阅下发的中转入口。一个入口可以绑定多个出口，订阅按绑定节点显示多个节点，运行态可合并同入口端口但仍按绑定节点路由和计费。中转节点负责鉴权、出口路由、流量统计和套餐扣费，出口只负责最终流量出站，不直接暴露给用户。

后台用户管理提供“设备管理”IP 观察抽屉，只合并订阅拉取来源和真实节点使用来源，重复 IP 只展示一条；该能力不改变唯一订阅方式，也不新增用户凭据或线路分配模型。

## 启动与验证

- 本地启动：`make up`
- 最小检查：`make check-plan`、`make check-affected`
- 运行态验收：`make check-runtime`，验证当前已启动服务。
- 发布门禁：`make check-release`，会启动隔离 Docker runtime 验证当前工作树构建产物。
- 真实发布 env 引导：`make bootstrap-real-release-env`，从本机私有来源生成未跟踪的 `.env.real-release` 草稿，只输出变量统计，不输出敏感值。
- 真实发布 env 检查：`make check-real-release-env`，只校验私有 env 完整性，不触发目标服务器 SSH 或三方流量。
- 真实发布门禁：`make check-real-release`，必须使用 Docker、真实订阅、真实 access-agent 上报、真实目标服务器接入节点和真实第三方出口流量。
- 数据库集成：`DATABASE_URL=<postgres-url> cargo test -p xrayc-db -p xrayc-api -- --test-threads=1`
- 数据库自动备份：在管理后台运营策略设置 `database_backup`；默认 1 天一次，恢复流程见 `文档/运维手册/备份恢复.md`。

## 一致性规则

- 当前提供中转节点用户级平滑限速：套餐默认速率和用户覆盖速率写入 `rate_limit_bps`，access-agent 通过 Xray mark 与 `tc HTB` 同步规则；TCP 与 UDP 按用户共享同一个 `rate_limit_bps`，不新增 `udp_rate_limit_bps`、不解析应用协议、不做多中转全局累计，也不维护旧限速档案。限速用户与不限速用户共用同一入站（守真实端口）、靠每用户 fwmark 区分，订阅端口不因限速变化；limiter 未启用、dry-run、命令失败或 mark 冲突时必须 fail-closed，不能 reload 新 Xray 入站。
- 协议、订阅格式、Xray、Caddy/Docker/PostgreSQL/Cloudflare 或第三方组件行为不确定时，先查官方文档或上游主仓库文档；采用官方依据修正实现时，同步更新方案、规则和公开文档，并清理冲突旧口径。
- 文档、开发、部署、测试和审查默认拆分并行使用 subagent；除极小单文件修复外，不允许主线程单打独斗。
- 真实链路验收必须使用 Docker/真实流量/Playwright smoke，不能用 mock、模拟订阅、伪造出口或中心侧构造值冒充。

## 安全边界

公开文档只记录路径和流程，不记录真实服务器账号、密码、Token、代理凭据、订阅 Token 或出口真实敏感信息。真实凭据只允许保存在本机私有文件中。
