# 备份恢复

## 备份范围与安全模型

备份对象是 PostgreSQL 业务数据（`pg_dump` 全量 dump，或 WAL/PITR 归档 + base backup）。`.env`、Caddy/TLS 配置、部署产物版本仍按生产运维制度单独备份，不在自动备份范围内。

**字段级加密已下线**：SMTP 发信密码、支付密钥，以及本功能新增的**异地备份机 SSH 密码**、**邮件附件加密口令**都**明文存 `site_settings`**，靠「写时保留（请求体留空/未变时保留原值）+ 输出脱敏成 `_set` 布尔 + 绝不入日志/审计/前端回显」防护，与 SMTP/支付密钥现状一致。

**明文凭据提示（重要）**：因这些敏感字段明文落库，`pg_dump` 生成的 dump **包含**它们的明文；dump 一旦经异地同步推到异地机、或经邮件发出，就等于把 SMTP 密码、支付密钥、异地 SSH 密码、附件口令一并带出。因此：

- 异地备份机、备份邮箱收件人必须是可信主体；
- 邮件模式默认对附件做 `openssl enc -aes-256-cbc -pbkdf2` 加密，加密口令另存、绝不随邮件正文发出；
- dump **不额外剔除** `backup_config` 等敏感设置（保持 dump 完整可恢复），安全由「传输通道 + 接收方可信」保证；
- 公开日志/截图/报告绝不回显这些明文，只出脱敏摘要或 `_set` 布尔；
- 中心机 SSH 私钥（`/var/lib/xrayc/backup_ssh/id_ed25519`，0600）不入库、不外发，只展示公钥指纹。

## 备份方式（可组合可单选，后台「数据库备份」页配置）

后台「数据库备份」页统一读写 `site_settings.setting_key='backup_config'`，四种能力各自独立开关、可组合可单选，调度自定义（间隔分钟 `interval_minutes` / 5 段 `cron` 两档）：

1. **全量 pg_dump**：`pg_dump --format=custom --no-owner --no-acl` 生成 `xrayc-postgres-YYYYmmddTHHMMSSZ.dump`，写入 Worker `/backups`（`DATABASE_BACKUP_DIR`）。`full.exclude_traffic_logs=true` 时对 7 张观测大表追加 `--exclude-table-data=`（`access_exit_probes`、`access_exit_probe_states`、`access_line_probes`、`access_line_metric_snapshots`、`node_runtime_metrics`、`access_user_session_events`、`subscription_pull_events`，只删数据保结构；计费表 `usage_ledgers`、`access_traffic_snapshots`、`usage_*_rollups`、`user_subscriptions` 必留）。按 `full.retention_days` 本地清理旧文件。
2. **异地同步（rsync 增量）**：全量成功后（或独立调度）`rsync -az --partial` 把 `/backups/` 增量推到 `offsite.ssh_user@ssh_host:remote_dir`，走 SSH 密钥免密。异地保留按 `offsite.retention_days`，只删文件名前缀 `xrayc-postgres-` 的过期文件（双重约束防误删）。异地不可达只记状态 + 告警，绝不阻塞本地备份与 postgres。
3. **WAL / PITR（plain 归档 + `pg_basebackup`）**：postgres `archive_mode=on` + `wal_level=replica` + `archive_command` 把 WAL 段只写**本地归档卷**（永不等网络、防爆盘）；Worker 按 `wal.full_backup_schedule` 跑 `pg_basebackup`（走网络复制协议连 postgres，不需本地 PGDATA，PG16 默认 `max_wal_senders=10`）做 base；WAL 归档 + base 一并 rsync 推异地。可恢复到任意时刻（见下）。**开启需一次 postgres 重启**（`archive_mode` 改了才生效），走受控上线（隔离测试 → 受控上线 → 可回滚）。archive/复制不可用时 WAL 模式标 `configured=false` 并告警，绝不阻塞全量 + 同步、更不拖垮 postgres。
4. **邮件发文件**：备份成功后取最新 dump（或 `exclude_traffic_logs` 精简版），`attach_encrypted=true` 用 `openssl enc -aes-256-cbc -pbkdf2` 加密作附件经 SMTP 发 `recipients`；超 `max_attach_mb` 降级为「发精简 dump」→ 再超「只发通知说过大未附，请从异地取」（不静默）。`notify_on_success/failure` 控通知邮件（纯文本、脱敏）。

并发由 PostgreSQL advisory lock（`try_database_backup_lock`）防止多 Worker 同时备份。各模式最近状态写 `site_settings.database_backup_state`（`last_started_at`/`last_success_at`/`last_failed_at`/`error_summary`/`last_file_name` + `offsite_last_sync_at`/`wal_last_archive_ok`/`email_last_sent_at`）供排障。

## 恢复步骤

### 全量恢复（pg_restore，已实测）

1. 准备要恢复的 `.dump`（本地 `/backups`，或从异地机/邮件附件取；加密附件先 `openssl enc -d -aes-256-cbc -pbkdf2 -pass pass:<口令>` 解密）。
2. 确认恢复目标 PostgreSQL 已停止写入或使用新库。
3. 执行恢复：
   ```
   pg_restore --clean --if-exists --no-owner --dbname "$DATABASE_URL" backups/xrayc-postgres-YYYYmmddTHHMMSSZ.dump
   ```
4. 恢复 `.env` 等私有环境变量，`docker compose up -d`，跑迁移与 `make check-runtime`。

### WAL PITR 恢复（恢复到任意时刻，已实测配方）

1. 取一份 base backup 目录（`pg_basebackup` 产物），解到新的数据目录。
2. 在数据目录放空文件 `recovery.signal`。
3. 在 `postgresql.auto.conf` 写：
   - `restore_command = 'cp /wal-archive/%f %p'`
   - `recovery_target_time = '<目标时刻，如 2026-07-01 12:34:56+00>'`
   - `recovery_target_action = 'promote'`
4. 起 postgres，它会从 WAL 归档重放到 `recovery_target_time` 指定时刻后 promote 为可写。
5. 校验数据落点符合预期后再切生产。

## 恢复演练（交付含演练脚本）

恢复没演练 = 用不了。上线前必须在**隔离 PostgreSQL**（不碰 live 发布库）跑通：

- 全量：dump → `pg_restore` → 关键表行数/计费口径核对；
- WAL：隔离库开 archive → 产生若干事务 → base + WAL PITR 恢复到某中间时刻 → 校验该时刻数据；
- 演练命令、结果、遗留风险写当天日报。**禁止对 live 发布库做破坏性恢复测试。**

## 校验

确认 `/health`、管理员登录、订阅下载、agent 心跳和运行态上报正常。运行数据验收必须开启 `STRICT_AGENT_TRAFFIC=1` 并提供私有 agent 变量，确保 traffic 上报走 2xx 成功路径。
