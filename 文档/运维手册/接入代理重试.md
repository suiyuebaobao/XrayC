# 接入代理重试

## 心跳重试

心跳失败不退出进程，等待下一周期重试。连续失败需要检查中心地址、DNS、TLS 和 access-agent token。

## 配置重试

坏配置必须回滚上一份可用配置。修复中心配置后，标记节点 dirty，让下一轮心跳重新下发。`config-result` 只有 `success=true` 且回传的 `config_version`、`config_hash` 或 `desired_config_version` 与中心期望 hash 匹配时，才能清理 dirty；成功但未回传 hash 只能视为收到结果，不能当作同步完成。

重装、迁移或清空状态目录后，access-agent 首次心跳可能没有 `applied_config_version`。中心必须把该节点视为应用版本未知并重新下发当前配置，避免新机器仍停留在空配置。

## 探测重试

出口探测按连续失败/恢复阈值生效，避免单次抖动导致用户频繁迁移。Worker 只负责按策略写入 `queued` 探测任务；queued 任务由 access-agent 心跳领取并执行，随后通过 `/api/agent/access/probes` 回报真实结果。长期 queued 通常说明 agent 未心跳、token 错误、配置未应用或出口协议档无法生成探测目标。

同一出口在不同中转节点上的组合状态相互独立。某个 `access_node -> exit_endpoint` 连续失败达到阈值后，只迁移当前接入节点上分配到该出口的用户，不要直接删除全局出口资源或运行成员。

## 流量补发重试

access-agent 本地队列补发流量快照时，如果中心响应 `config_status.required=true`，必须先应用中心下发的新配置并上报 `config-result`，再继续后续批次，避免超额或禁用用户继续留在 Xray client 中。
