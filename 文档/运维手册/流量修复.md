# 流量修复

## 数据来源

以 `usage_ledgers`、`usage_daily_rollups`、`usage_hourly_rollups` 和 `access_traffic_snapshots` 为准。不得用中心侧估算、订阅下载次数、出口供应商账单或出口 endpoint 侧统计替代 access-agent 上报。当前 V2 计费权威来源是中转节点上报的快照差值，保留期内账本应满足 `traffic_source=access_line`，并能追溯到 `access_line_id` 和可用时的 `exit_endpoint_id`。超过后台运营策略保留期的详细账本会汇总到日/小时汇总后删除，历史总量和小时统计可核对，单条访问 IP 和明细不可恢复。

## 修复原则

先确认快照是否乱序、计数器是否重置、倍率是否正确、`access_line_id` 是否属于当前接入节点，再调整订阅用量。修复后必须重新计算剩余额度并标记相关接入节点 dirty，确保下一次心跳剔除超额、禁用或套餐失效用户。

如果账本缺少 `exit_endpoint_id`，先按 `user_exit_assignments`、中转入口绑定的线路 endpoint 和采集时间窗口定位当时出口；不能从订阅内容或客户端出口 IP 反推并直接写入生产账本。

运行态指标、在线会话和探测记录只用于运营观测和故障定位，不直接改写用户订阅用量。`access_line_metric_snapshots.unique_client_ips`、`access_user_sessions.client_ip_hash` 和探测延迟不能用于补扣费。

## 验证

运行数据库定向测试和 `scripts/real-smoke.sh`，确认超额用户会被配置刷新剔除。真实链路修复后，再用私有客户端代理执行对应 `scripts/real-access-*.sh`，验证订阅仍只暴露中转入口、账本新增来自 access-agent 上报、公开日志不包含真实 IP、Token、订阅链接或代理 URL。
