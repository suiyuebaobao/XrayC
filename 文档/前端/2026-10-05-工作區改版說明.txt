XrayC 系統優化與介面整合總結
更新日期：2026-10-05（台灣時間）
狀態補註（2026-10-06）：下文保留當時方案與第一輪 UI 階段紀錄。其後已完成本輪優化驗收並發布 2026.10.06-opt1，詳見 文档/部署/2026-10-06-優化發布驗收報告.txt。

一、方向與目前進度

保留 Rust / PostgreSQL / Vue / Xray / Agent 架構，以多節點、中轉線路、出口組合、套餐授權及流量管理為核心。先提高可靠性，再減少重複設定與維護成本，讓日常操作集中在清楚的工作區。

目前完成的是本機第一輪 UI、導航整合、線路工作區及部分設定保存修正，尚未發布正式站。下文標示「待實作」的項目仍是方案，不代表後端已完成。
先前經授權修正的舊正式站中心地址屬另一項已完成操作；一鍵安裝尚未重新驗證成功。這次 UI 改版沒有修改正式站資料庫、歷史日誌或保留政策。

二、七個工作區與功能歸屬

1. 總覽
   集中關鍵指標、節點同步狀態、日常操作入口及近期事件。
   後續重點：優先呈現需要處理的異常，詳細紀錄由對應頁面展開。

2. 線路
   包含訂閱線路、入口、出口、分組。
   新工作區已支援搜尋、節點／狀態篩選、分頁、表格／路徑切換與詳情側欄。
   可使用既有入口與出口建立綁定；之後仍須加入分組，才可透過套餐授權給使用者。
   入口、出口、綁定與分組仍保留各自的業務意義，集中操作不等於合併成同一資料物件。

3. 使用者
   包含使用者列表、流量明細、邀請註冊。
   保留使用者狀態、訂閱、流量及 IP 等管理能力；常用操作直接顯示，其餘收進更多選單。
   待實作：整合使用者詳情與全站流量的查詢入口，避免相同資訊分散於多處。

4. 套餐與營運
   包含套餐授權、訂單、兌換碼、支付渠道。
   保留期限、配額、速率、分組授權及流量倍率等既有能力。
   待實作：依是否啟用商業營運，控制訂單、支付、銷售等功能的顯示。
   微信支付目前缺少 provider 實作；現有設定頁不代表已具備完整收款能力。

5. 節點
   管理節點、Agent、部署與配置套用。
   待實作：將一鍵安裝、手動安裝、接入既有 Agent 整合成同一個新增節點精靈。
   待實作：部署前檢查中心地址、認證及必要安裝檔，顯示真實步驟、完整失敗原因與安全重試入口。

6. 監控與日誌
   包含運行監控與操作稽核；流量帳務明細目前歸在使用者工作區。
   健康檢查此前已有整合，不另建一套重複頁面。
   待實作：摘要優先、異常突出、按需展開診斷，以及監控資料分層。

7. 系統設定
   包含訂閱、分流規則、認證與郵件、備份、網站設定。
   備份頁已有集中管理；全量備份、WAL/PITR 與異地保存仍各有用途。
   待實作：清楚顯示 API／Worker／Agent／Xray 版本、部署環境與相容性。

以上已落實的是導航及頁面歸屬。既有管理 URL 與權限保留；並非每個舊頁面的業務流程都已重新設計。

三、這一輪已完成的本機改版

- 介面採深色側欄、淺色內容區及一致的強調色，統一字級、留白、表格、表單和對話框。
- 側欄分成日常管理、運維、系統；相關頁面以工作區頁籤呈現。
- 重做總覽及新增線路工作區，資料接自既有 API。
- 線路路徑呈現已知的公布地址、處理節點與出口，不由 IP 猜測額外轉送關係。
- 狀態區分設定已同步、待同步、停用、節點離線及關聯缺失。「設定已同步」不代表手機端已實際連通。
- 使用者表格縮減操作欄寬度，保留常用操作並增加更多選單。
- 手機導航可收合，隱藏後不會被鍵盤誤聚焦；手機線路預設路徑卡片，仍可切換表格。
- 規則頁只提交規則，訂閱頁排除規則欄位，避免舊的整頁設定覆蓋另一頁內容。保存時保留 false、0、空陣列等有效值。
- 上述設定修正沒有實作多管理員並行編輯的版本衝突控制。
- 增加僅使用本機回環地址的示例預覽服務，與正式資料隔離。

四、前面討論的功能整合：仍待實作

1. 新增節點精靈
   同一入口選擇部署方式，依序填寫、預檢、安裝、確認上線；進階選項按需展開。

2. 共用出口編輯器
   節點內的本機出口與全域出口管理共用表單、驗證及保存邏輯，保留不同檢視入口。

3. 統一流量查詢
   使用者詳情與全站紀錄共用篩選、分頁及詳情元件；從使用者進入時自動帶入條件。

4. 使用者端簡化
   將首頁與我的訂閱整合成以可用線路、訂閱地址、用量、期限為主的服務頁。
   套餐、訂單、兌換、邀請依啟用情況呈現，帳號安全保留。目前使用者端仍維持原有七個入口。

5. 進階與可選功能按需顯示
   低頻傳輸參數、進階路由及診斷項目收進進階區；未啟用的支付、營銷及邀請功能可隱藏。
   隱藏選單不等於刪除能力或資料，也不能取代後端權限檢查。

不應混為一談的功能：
- 節點是執行位置，入口是接入配置，出口是離開路徑。
- 分組管理線路集合，套餐決定誰能使用及使用條件。
- 邀請碼控制註冊／邀請，兌換碼發放權益。
- 操作稽核記錄管理行為，流量帳務支援配額與查帳。
- 全量備份提供還原基礎，WAL/PITR 提供時間點還原；異地保存是備份目的地。

五、日誌與流量：減少雜訊，保留帳務正確性

現有系統已具備明細、小時、日彙總。程式預設明細保留 14 天，先前查核未發現相關政策覆寫；這是當時的查核結果，不代表持續監測。

建議的新設計仍待實作：
- 日常頁面以今日／本月用量、扣費量、在線狀態及異常為主，明細分頁按需查詢。
- 正常探測以最新狀態及時間桶統計呈現，故障與恢復另留事件。
- 監控資料採細到粗的分層彙總，完整診斷可臨時開啟並自動退出。
- 計費累計快照、增量計算、去重、重啟基準及必要帳務紀錄繼續保留。
- 節點退役後仍能解讀歷史流量，名稱變更不應改寫過去帳務的含義。

曾討論高頻監控只保留 24–72 小時等候選值，尚未採用。現有資料規模也不足以支持立即更換時序資料庫或大規模分庫的決策。

使用者已明確要求保留伺服器既有日誌。本方案沒有授權清空、輪替、縮短保留期或移除保存日誌的容器；任何會刪除歷史資料的後續操作，必須另行取得明確授權。

六、後端待修復問題與優化

優先處理已確認問題：
1. 帶歷史流量的節點刪除觸發 usage_daily_rollups_exit_endpoint_id_fkey。
   已定位到歷史關聯與多級刪除流程，具體觸發順序仍需隔離重現；不能靠刪帳本或移除外鍵解決。
2. 出口停用後重新啟用，衍生線路狀態可能未恢復一致。
3. 一鍵安裝錯誤摘要截斷末尾原因，未執行步驟可能誤顯示完成。
4. 未配置主機重啟命令時，結果仍可能顯示成功，應如實區分自檢與實際重啟。

再處理已辨識的結構風險：
- 心跳無配置變更時仍可能同步全部使用者並載入全域資料；改為依受影響節點更新。
- 入口、出口、綁定與授權作為主資料，執行期線路和分配快取由同一流程生成，降低狀態不一致。
- 套餐到期、帳務彙總、探測、歷史保留及備份分開處理交易、失敗與重試。
- 部署先檢查地址、認證與安裝檔，再修改既有運行環境。
- 建立明確版本、發布紀錄、遷移及回退路徑；切換 production 環境變數本身不等於完成正式化。

這些後端修復尚未因 UI 改版而完成，也尚無效能量測可支持具體提升百分比。

八、建議後續順序與完成標準

第一批：可靠性修復。
修復歷史流量刪除、出口恢復、安裝預檢／進度／錯誤、重啟狀態。以隔離資料驗證歷史帳務不丟失、保留線路不受影響、失敗可回滾。

第二批：操作整合與同步成本。
完成新增節點精靈、共用出口編輯器、流量查詢、使用者服務頁；逐步改善心跳與維護交易。確認停用、配額耗盡及憑證輪替仍及時生效，再量測 SQL 次數、心跳延遲、配置套用時間及資料增長。

第三批：正式發布。
完成測試环境驗收，核對 HTTPS、Cookie、密鑰、版本相容性、備份還原與遷移回退，再發布獲准的改動。正式站歷史資料和日誌保留限制持續有效。
