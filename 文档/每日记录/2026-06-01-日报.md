# 2026-06-01 日报

## UDP 订阅显示排查

- 排查中转节点关闭 UDP 后 Clash 订阅仍显示 UDP 的问题，确认订阅 YAML 的 `udp` 字段来自 `access_lines.udp_enabled`，不是 Clash 客户端自行推断。
- 当前数据中只有一个中转节点的入口线路关闭了 UDP，其余中转节点仍保持 `udp_enabled=true`；套餐/分组包含这些线路时，订阅仍会出现 `udp: true`。
- 补充控制面读模型字段 `udp_enabled`，前端中转节点卡片和出口管理表格显示“UDP 开/关”，避免只看协议/传输时误判。
- 修正中转节点绑定线路弹窗的 UDP 默认值，重新打开已有节点时按当前绑定状态回填，避免默认 `true` 覆盖已关闭状态。

## 中转线路延迟显示修正

- 排查“美国4-HY2 线路显示延迟，其他线路显示 0”的问题，确认所有启用线路都有探针记录。
- 根因是 TCP 本机端口探测耗时小于 1ms，被毫秒取整保存为 `0`；HY2 入口走 UDP 探测，会等待短窗口确认端口状态，因此显示为百毫秒级。
- 前端中转节点、出口管理和运营中心统一把 `0ms` 展示为 `< 1 ms`，避免误解为未探测或异常。

## 套餐节点数量口径修正

- 排查“客户端显示 17 个节点，但套餐授权里显示 25 个节点”的问题，确认差异来自原始线路绑定数和订阅可见节点数口径不一致。
- 当前默认线路分组绑定了多条线路，真实订阅会按套餐有效 分组授权 和用户可用入口分配生成客户端节点，所以客户端不会显示全部原始绑定。
- 套餐授权列表和编辑弹窗已改为显示“客户端节点”数量，并在存在限制时提示“原始绑定 X 条，按订阅口径输出 Y 个客户端节点”。
- 新增 Playwright smoke 用例覆盖原始绑定被套餐数量限制后减少的场景，防止后续再次把原始绑定数误当客户端节点数。

## 订阅重置凭据轮换

- 排查“重置订阅链接后旧客户端仍能继续使用流量”的问题，确认原实现只轮换下载 Token，订阅 YAML 和 access-agent 下发配置仍使用稳定用户 ID 作为节点入站凭据。
- 新增 `users.access_credential` 作为可轮换入站凭据；注册、管理员新增用户和历史数据迁移都会生成或补齐该字段。
- 用户或管理员重置订阅链接时，同步轮换 `access_credential` 与 `xray_user_key`，清理旧会话/快照，并标记中转节点配置待同步，确保旧客户端配置在节点同步后失效。
