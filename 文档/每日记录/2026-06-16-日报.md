## 发现与处理

### 真实 BUG：孤儿 xray 进程污染 Stats API 端口，导致计费失效
- 现象：流量真实出站成功，但 `last_traffic_report_at` 长期 NULL、`used_bytes=0`，计费不入账。
- 根因：测试节点上存在**已删除容器残留的孤儿 xray 进程**（2 天前部署遗留），通过 `SO_REUSEPORT` 与当前 xray 共占 Stats API 端口；agent 查 stats 被内核分流到旧进程，读不到当前用户级流量 → 无可上报 → 不计费。`docker restart` 杀不掉这些容器外的孤儿。
- 处理：确认两个 PID 的 cgroup 对应容器均已不存在（孤儿）后清理；清理后 Stats API 单一进程，`user>>>` 级流量立即可见，计费与超额剔除随即闭环。
- 建议（代码侧后续）：access-agent 在 reload/redeploy 切换 xray 时应确保**旧 xray 进程被回收**，否则残留进程会持续污染 Stats 端口并破坏计费；与本轮代码审查中 access-agent reload 处理的风险点一致，建议补进程清理 + Stats 端口归属校验。

### 架构澄清
- `.env` 的 `XRAYC_PUBLIC_BASE_URL` 原指向一套独立面板（已停用）；用户已将该域名重指到本机，base URL 现解析到本机，订阅可正常拉取（此前 timeout 即由旧 DNS 指向引起）。
