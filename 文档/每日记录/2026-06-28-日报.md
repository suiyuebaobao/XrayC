## 一、本机出口 IP 直连 VLESS 恢复「普通 none」安全模式(612d04e)

- **由来**:用户 review 时质疑「本机出口 VLESS IP 直连就一个安全模式(只 Reality)?我记得有很多」。
- **核实(没凭记忆,翻 git + 开发方案)**:
  - 改前原代码 `localExitVlessSecurityOptionsForDomainKind` 的 IP 分支 = `filter(value !== 'tls')` = **reality + 普通none 两个**;我在出口修复 #7(95f3479)误改成 `filter(value === 'reality')` 只剩一个。
  - 开发方案 §237「**本机出口口径不变**」+ §47「**非 Reality VLESS 本机出口才允许 XHTTP/XUDP**」都要求保留 none;后端一直接受(Agent C 真机验过 VLESS-none 落库 `network=tcp+packetEncoding=xudp`),仅前端下拉错误隐藏。
  - 后果:VLESS 本机出口被砍成**仅 TCP、丢了 TCP+UDP/XUDP 能力**(Reality 不开 UDP/XUDP)。#7 的另一半「域名直连只放 TLS」是对的(那才是用户当初报的 bug),保留。
- **修复**:IP 分支恢复 `filter(value !== 'tls')`(reality+none);传输/承载下游函数早已按非 Reality 给 RAW+XHTTP、TCP+UDP/XUDP,无需动。开发方案 §47 + CLAUDE/AGENTS §4 澄清「两档=连接方式」、IP 直连本机出口 VLESS 含 Reality+普通 none。
- **验证**:VLESS none 本机出口 IP 直连 API `security='none'`/`''` 均 rc=200、落库 `net=tcp(+packetEncoding xudp)`;前端构建绿。

## 二、编辑用户邮箱:只读不可改 + admin 非标准邮箱不卡格式(bea64f3)

- **由来**:用户两条反馈——①「编辑用户时不容许修改邮箱」②「编辑 admin 用户提示『邮箱格式不正确』,admin 不需要遵守」。
- **核实**:admin 账号 `email='admin'`(非标准格式);后端 `update_admin_user_json:159` 先 `normalize_email` 把 `admin` 判为格式无效 → 整个更新失败。前端 `UserFormDialog` 邮箱框编辑态也可改、且把 email 发给后端。
- **洞察**:既然编辑本就不该改邮箱,就根本不该再对它做格式校验——一举解决两件事。
- **修复**:
  - 前端:编辑态邮箱框 `:disabled` 只读 + 提示「邮箱是账号身份,创建后不可修改」。
  - 后端 `update_admin_user_json`:删 `normalize_email`、邮箱列移出 `UPDATE SET`、按原始串比对——传入邮箱与现值不同一律拒(`InvalidAgentPayload`),相同/未传为无害空操作。故 admin 等非标准邮箱账号编辑其它字段正常,不再卡格式。新建用户仍严格校验邮箱格式。
- **测试**:db part69 新增 2 测——改邮箱被拒 / 非标准邮箱编辑不卡格式,**2/2 过**;clippy(db)+ 前端构建绿。
- **文档**:开发方案「邮箱即账号」段 + CLAUDE/AGENTS 密码管理段同步规则。
