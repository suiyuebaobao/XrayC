# 发布变更

## 发布前

运行 `make check-release`，确认 Rust 格式、Clippy、workspace 测试、前端构建、防泄露、隔离 Docker runtime、真实 smoke、API contract、Playwright 和 Compose 校验通过。该门禁必须验证当前工作树构建产物，不得只依赖已经启动的旧服务。

真实发布前先运行 `make check-real-release-env` 和 `make real-release-gap-report`，确认私有 env、目标服务器清单、真实客户端代理、三方出口矩阵、Playwright no-mock 账号和运行观测变量均齐全。完整真实发布强门禁必须使用 `REAL_RELEASE_MATRIX_MODE=relay`，其他专项脚本只能作为脱敏诊断证据。`make check-real-release` 会串联真实订阅、Worker smoke、目标服务器本地安装流程验收、access-agent 运行观测、自建出口管理链路和 `socks`、`http`、`vless`、`trojan`、`shadowsocks`、`hy2` 六类第三方出口矩阵。启用 `RUN_REAL_STABILITY_UAT*`、`RUN_RUNTIME_LOADTEST`、`RUN_AUTH_HA_UAT`、`RUN_AUTH_HA_STABILITY_UAT`、`RUN_OPS_MISTAKE_RECOVERY_UAT` 或 `RUN_OPS_MISTAKE_RECOVERY_LARGE_UAT` 时，必须在日报记录脱敏结果。

## 发布后

检查 `docker compose ps`、`/health`、管理员登录、订阅下载、access-agent 心跳、配置 hash、`metrics/sessions/probes` 新鲜度、Worker 日志、`database_backup_state` 和备份目录写入状态。部署脚本或镜像变化后重新生成 `deploy/artifacts`。

## 回滚

优先回滚镜像和配置。数据库迁移涉及不可逆变更时必须先备份 PostgreSQL；不能只假设每日自动备份足够新，必须确认 `database_backup_state.last_success_at` 满足回滚窗口，或在变更前手动执行一次即时 `pg_dump` 并验证文件可读。

回滚后要确认订阅只暴露中转入口，运行成员状态没有被误删，接入节点 dirty 状态能在下一次心跳后清理。
