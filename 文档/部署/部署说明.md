# 部署说明

## 部署边界

XrayC V2 优先采用 Docker Compose 单机部署。中心服务由 Rust/Axum API、Rust Worker、PostgreSQL 和 Caddy 组成；数据访问统一使用 SQLx；中转节点固定部署并运行 `xray-core` 和 `access-agent`（单内核 Xray），所有入口都由 Xray 处理。第三方出口、普通自建上游和中转节点本机出口服务先进入统一出口管理，再由入口管理把入口和出口组成绑定节点，分组只选择绑定节点，套餐直接授权分组。这些出口不提供独立后台安装。

常规流程是先在出口管理维护第三方、普通自建上游出口，或在中转节点详情批量创建该服务器自建出口线路；再在入口管理创建中转节点上的用户入口，并把入口绑定到一条或多条出口线路形成绑定节点；随后在分组中选择这些绑定节点，最后让套餐授权分组。中转节点需要提供本机出口能力时，在节点详情打开“本机出口服务”，默认一次性添加 VLESS、HY2、Shadowsocks、Trojan 四类自建出口线路，按协议行选择网络模式、监听端口和必要字段，系统自动生成连接配置；服务地址默认读取所属中转节点地址，管理员只在默认值不符合实际监听地址时覆盖。该服务只进入统一出口管理，不自动创建订阅入口、绑定节点，也不会加入分组。订阅只暴露中转入口，控制和计费在中转节点/access-agent 链路完成。

当前公开部署只使用 Caddy 作为唯一 Web 入口并托管前端静态资源。前端、后端和数据库在架构上可以拆分到不同服务器，但默认部署推荐单主控服务器 Compose；拆分部署时必须同步配置前端 API 地址、Caddy 反代目标、后端 `DATABASE_URL`、TLS 和数据库访问网络。

## 中心服务组件

| 服务 | 说明 |
|------|------|
| `api` | Rust/Axum 后端应用，提供 `/api/` 和 `/sub/` |
| `worker` | Rust 后台任务，执行基础套餐周期重置、付费套餐到期回基础、订单过期、认证临时状态清理、运行态数据保留、详细流量日志汇总清理、PostgreSQL 自动备份和定时组合探测排队 |
| `postgres` | PostgreSQL 16+，保存业务数据和共享认证状态 |
| `caddy` | 构建并托管前端静态资源，反向代理 `/api/`、`/sub/`、`/health` 和部署产物下载 |

Caddy 反向代理必须对 `/api/`、`/sub/` 和 `/health` 指向后端 API，并由 Compose 内置 DNS 解析 `api` upstream。`/api/deploy/artifacts/` 必须使用独立长超时路由，避免目标服务器首次下载镜像包时被反代提前断开。

认证链路依赖 `Authorization`、`Cookie` 和 `Set-Cookie` 头。反向代理必须保留这些头，不能缓存 `/api/auth/*` 响应；生产环境建议在 HTTPS 下运行，使 HttpOnly Refresh Cookie 只在可信链路中传输。
API 基础频控在 PostgreSQL 模式下使用 `rate_limit_buckets` 共享计数，登录、注册、验证码、邮箱验证码、订阅下载和支付回调会按可信客户端来源摘要做分钟级限制，适合多 API 副本共享状态；未配置 PostgreSQL 或共享计数临时失败时才退回进程内内存兜底，内存兜底仅用于开发或无 PG 场景。该机制只保护 HTTP 接口，中转节点用户级带宽限制由 access-agent 按 `rate_limit_bps` 执行。

后端镜像必须基于 Rust 构建产物发布，数据库迁移由 SQLx 迁移目录或等价受控流程执行。部署文档、Compose 注释和脚本必须保持 Rust/Axum/SQLx/PostgreSQL 方向一致。

### 数据库备份的卷、镜像与 postgres 归档要求（新增）

后台「数据库备份」页支持全量 pg_dump、异地 rsync 同步、WAL/PITR 和邮件发文件四种能力（详见 `开发方案.md` §11.4、`文档/运维手册/备份恢复.md`）。开启异地/WAL 需以下部署侧支持：

- **Worker 镜像**：除已内置的 `pg_dump`/`pg_restore` 外，异地同步需补 `rsync`（Dockerfile 加装）；WAL base 走 `pg_basebackup`（postgres 客户端已含）。
- **Worker 新增卷**：
  - `./wal-repo:/var/lib/xrayc/wal-repo`：worker 侧 base backup（`pg_basebackup` 产物）仓库；
  - `./backup-ssh:/var/lib/xrayc/backup_ssh`：中心机 SSH 私钥（`id_ed25519`，0600）持久卷，异地免密同步与装公钥用；api 若承担一次性装公钥则以只读挂同一卷；
  - 全量 dump 仍写既有 `./backups:/backups`。
- **postgres 归档（WAL 模式）**：需给 postgres 加 `archive_mode=on`、`wal_level=replica`、`archive_command`（只写本地归档卷），并挂 `./wal-archive:/var/lib/postgresql/wal-archive`（postgres 写、worker 读）。**修改 `archive_mode` 需一次 postgres 重启才生效**，按受控可回滚步骤上线（先 `archive_command='/bin/true'` 确认能起，再切实际；失败即回滚 compose 重起 postgres），绝不拖垮 live 库。
- 异地/邮件失败只记状态 + 告警，绝不阻塞本地全量与 postgres。异地机 SSH 密码、邮件附件口令明文存 `site_settings.backup_config`（字段加密已下线），会随 dump 进异地/邮件，运维手册已诚实提示。

## 接入节点组件

| 服务 | 说明 |
|------|------|
| `xray-core` | 单内核，承载全部入口、上游出站和路由，并作为 Stats API 观测主链路 |
| `access-agent` | 主动回连中心，生成 Xray 配置，采集流量和指标，执行 Xray reload/start/stop |

access-agent 必须具备以下能力：

- 使用独立 access-agent 凭证访问中心服务，所有 `/api/agent/access/*` 请求必须带 `Authorization: Bearer <agent_token>`；中心数据库只保存该凭证的 SHA-256 哈希。
- 拉取中心下发的入口出口绑定节点、绑定节点对应的出口管理 endpoint、用户授权和内部出口映射；当前中心 heartbeat 已能下发 SOCKS、HTTP、VLESS、Trojan、Shadowsocks、Hysteria/HY2 `AccessConfig` 和用户级 `routing_rules`，第三方上游和本机出口服务凭据只允许进入 access-agent 必需配置，不得出现在订阅、页面和公开日志。本机出口服务主路径是批量写入出口管理中的 `self_hosted` 出口线路。
- VLESS 线路表单默认使用 Reality；内部出口协议档必须按 `security` 区分 Reality 与 TLS 校验：第三方或普通自建 `reality` 分支校验供应商 public key、short id、fingerprint 等 Reality 字段，`tls` 分支只校验 TLS/SNI/ALPN 等 TLS 字段，不要求 Reality public key 或 short id。本机出口服务创建的是本服务器自己的 VLESS Reality 服务，网络模式固定 TCP，后端自动生成 public key、private key 和 short id，管理员不填写 public key。网络模式支持多选并按协议与 VLESS security 过滤；中转入口保存时展开为多条单模式 `access_lines`，前端创建入口会按选择顺序递增监听端口，本机出口服务保存时展开为多条单模式出口管理 endpoint。非 Reality VLESS 出站会读取 endpoint `stream_config`，XHTTP 写入 Xray `streamSettings`，XUDP 写入 outbound mux/XUDP 配置。
- Trojan 用户入站必须启用 TLS；中转入口配置出现 `security=tls`、SNI 或证书字段时，安装和发布前必须主动准备或验证证书文件存在、权限可读、域名匹配和 Xray 配置预检通过，失败时不得继续发布明文或缺证书的 Trojan 入口。
- Agent 安装脚本只有在证书域名和 ACME 邮箱同时存在时才自动调用 certbot 申请 SSL 证书；任一缺失时跳过自动申请并提示原因。证书域名会写入 agent 环境，后续由心跳上报证书摘要，管理平台按单个中转节点下发续期任务。
- Xray 生成 Xray inbound、outbound、routing、Stats API 配置；Stats API 使用 `xrayc-api` 保留 tag，默认只监听本机 `127.0.0.1:10085`，多实例时必须下发独立端口。
- 周期性上报心跳、配置结果、从本机 Xray Stats API 读取到的用户累计流量、运行指标、在线会话和出口组合健康；运行数据分别通过 `/api/agent/access/metrics`、`/api/agent/access/sessions` 和 `/api/agent/access/probes` 上报，运营中心据此展示真实在线、连接数、上下行速率和探测延迟；配置应用后必须回报 `/api/agent/access/config-result`，只有成功且 hash 匹配才会清理中心 dirty 状态。
- 在中心返回配置刷新要求时应用新配置并剔除禁用、过期或超额用户。
- 节点侧 Compose 必须把安装目录下的 Xray 配置目录整体挂载到 Xray 和 `access-agent` 的对应配置目录，禁止只挂载单个 `config.json`。Xray 使用 `xray` 目录和 `/etc/xray:rw`。access-agent 应用配置后必须回读目标 `config.json` 校验，空配置也必须真正覆盖到宿主文件、access-agent 容器和 Xray 容器三处，避免订阅不可用后旧入站用户继续可用。

当前版本提供中转节点用户级平滑限速。目标服务器 Docker Compose 默认为 Xray 增加 `NET_ADMIN`，为 access-agent 增加 `NET_ADMIN`、`SYS_MODULE` 和 `/lib/modules` 只读挂载，用于 `SO_MARK`、tc `connmark` action、IFB 和 `tc HTB` 规则同步；TCP 与 UDP 共用同一个用户 `rate_limit_bps`，不拆独立 UDP 速率字段。目标服务器安装脚本未显式设置 `XRAYC_RATE_LIMITER_INTERFACE` 时会从默认路由自动选择网卡。

## 环境变量

主要环境变量应通过部署环境或 `.env` 注入，不得提交包含真实值的 `.env`。

| 变量 | 说明 |
|------|------|
| `POSTGRES_DB` | PostgreSQL 数据库名 |
| `POSTGRES_USER` | PostgreSQL 用户名 |
| `POSTGRES_PASSWORD` | PostgreSQL 密码 |
| `POSTGRES_PORT` | 本机开发时 PostgreSQL 绑定端口，Compose 默认只绑定 `127.0.0.1:15432` |
| `DATABASE_URL` | 后端连接数据库的 URL |
| `XRAYC_ENV` | 运行环境，生产必须设为 `production` |
| `MIGRATIONS_DIR` | SQLx 迁移目录，容器内默认 `migrations` |
| `SEED_DEMO_DATA` | 是否写入 demo seed，Compose 默认 `false`；只允许隔离 smoke/测试库临时设为 `true`，生产必须为 `false` |
| `JWT_SECRET` | JWT 签名密钥 |
| `JWT_EXPIRES_IN` | Access Token 有效期，支持秒数或 `s/m/h/d` 后缀，开发默认 `24h`，生产必须在 `60s` 到 `30m` 之间 |
| `JWT_REFRESH_EXPIRES_IN` | Refresh Token 有效期，支持秒数或 `s/m/h/d` 后缀，开发默认 `7d`，生产必须在 `1h` 到 `30d` 之间 |
| `XRAYC_REFRESH_COOKIE_SECURE` | Refresh Cookie 是否追加 `Secure`；开发默认 `false`，生产环境默认启用且不允许关闭 |
| `XRAYC_PAYMENT_ENABLED` | 支付启用开关，默认 `false`；false 时订单创建和支付回调写接口稳定返回 503、`code=payment_disabled` |
| `PAYMENT_CALLBACK_SECRET` | 启用真实支付时必填的支付回调 HMAC 密钥 |
| `PAYMENT_MIN_CONFIRMATIONS` | 启用真实支付时使用的支付最小确认数，默认 `1` |
| `PAYMENT_RECEIVE_ADDRESS` | 启用真实支付时必填的订单收款地址，回调必须带同一地址 |
| `XRAY_USER_KEY_DOMAIN` | 生成 `xray_user_key` 的域名后缀 |
| `SUBSCRIPTION_TOKEN_TTL_DAYS` | 订阅 Token 有效期天数，默认 3650，允许 1 到 3650 |
| `DEPLOY_ARTIFACT_TOKEN` | 部署产物下载授权；中心 API 与服务器侧 Agent 安装私有清单必须使用同一私有值 |
| `DEPLOY_ARTIFACT_DIR` | 部署产物目录，Compose 默认只读挂载 `deploy/artifacts` 到 `/root/xrayc-artifacts` |
| `XRAYC_XRAY_CONFIG_PATH` | Xray 配置路径，默认 `/etc/xray/config.json` |
| `XRAYC_XRAY_BINARY` | access-agent 调用的 Xray 预检二进制路径，默认 `/usr/local/bin/xrayc-xray` |
| `XRAYC_XRAY_START_COMMAND` / `XRAYC_XRAY_STOP_COMMAND` | 中转节点页控制 Xray 容器启停的本地命令 |
| `XRAYC_XRAY_API_SERVER` | access-agent 查询 Stats API 的地址，默认 `127.0.0.1:10085` |
| `XRAYC_XRAY_API_LISTEN_HOST` | 写入 Xray 配置的 Stats API 监听地址，默认 `127.0.0.1` |
| `XRAYC_XRAY_API_LISTEN_PORT` | 写入 Xray 配置的 Stats API 监听端口，默认从 `XRAYC_XRAY_API_SERVER` 解析或使用 `10085` |
| `XRAYC_SESSION_IDLE_SECONDS` | access-agent 在线会话空闲保留窗口，默认 `180` |
| `XRAYC_AGENT_STATE_PATH` | access-agent 已应用配置缓存路径，默认 `/var/lib/xrayc/access-agent/state.json` |
| `XRAYC_TRAFFIC_BACKLOG_PATH` | access-agent 流量补发队列路径，默认 `/var/lib/xrayc/access-agent/traffic-backlog.json` |
| `XRAYC_XRAY_ACCESS_LOG_PATH` | Xray access log 路径，默认 `/var/log/xray/access.log` |
| `WORKER_TICK_SECONDS` | Worker 维护任务周期，默认 `60` |
| `WORKER_RUNTIME_RETENTION_DAYS` | metrics、traffic snapshots、sessions 和 probes 运行态快照保留天数，默认 `14`；用户详细流量日志保留天数不由该变量控制，需在后台运营策略 `traffic_log_retention.detail_retention_days` 设置 |
| `DATABASE_BACKUP_DIR` | Worker 自动 PostgreSQL 备份目录，Compose 默认挂载为 `/backups`；自动备份开关、间隔和保留天数在后台运营策略 `database_backup` 设置，默认启用且 1 天一次 |
| `DATABASE_BACKUP_TIMEOUT_SECONDS` | 单次 `pg_dump` 超时时间，默认 `1800`，范围 60 到 86400 |
| `DATABASE_BACKUP_RETRY_SECONDS` | 自动备份失败后的重试退避时间，默认 `3600`，范围 60 到 86400 |

示例中只能使用占位符，例如 `<set-in-env>`、`example.com`，不得写真实密码、真实 Token 或真实服务器地址。

生产环境必须设置 `XRAYC_ENV=production`、`DATABASE_URL`、高强度 `JWT_SECRET`、`JWT_EXPIRES_IN`、`JWT_REFRESH_EXPIRES_IN`，并关闭 demo seed。支付功能当前暂停，默认 `XRAYC_PAYMENT_ENABLED=false`；此时生产启动不要求支付密钥或收款地址，订单创建和支付回调写接口稳定返回 503、`code=payment_disabled`。只有显式设为 `true` 时，生产启动才要求强 `PAYMENT_CALLBACK_SECRET` 和非占位 `PAYMENT_RECEIVE_ADDRESS`。`SEED_DEMO_DATA=true` 只用于本地 smoke，会创建演示管理员、演示用户、基础套餐、订阅 Token、演示入口、出口 endpoint、入口出口绑定节点和分组授权；生产环境若缺少必需变量、JWT 生命周期格式错误或 `SEED_DEMO_DATA` 不是 `false`，API 或 Worker 会直接启动失败。
生产反代必须覆盖 `X-Real-IP` 和 `X-Forwarded-For` 为真实连接来源，不允许把客户端自带的转发链追加给 API；审计和基础频控都使用该可信来源的 SHA-256 摘要，不保存明文客户端 IP。

本地真实部署测试使用的部署产物 token 只允许放在 `.env` 或其他 Git 忽略的本机私有位置。每次重建或重启 API 前必须重新读取最新私有清单，并确认 `.env` 中的 `DEPLOY_ARTIFACT_TOKEN` 与私有清单中的部署产物授权一致，否则目标服务器会在下载 `access-agent-manifest.json` 时收到 401。公开文档不得记录私有清单路径、字段结构或真实 token。

## 部署流程

1. 在中心服务器准备 Docker、Docker Compose、Caddy 入口和环境变量；真实测试域名统一称为“私有清单域名”，公开文档和命令模板统一写“私有清单域名”或占位域名。
2. 校验 Compose 配置：`docker compose config --services`。
3. 启动中心依赖和服务：`docker compose up -d`。
4. API 启动时执行 SQLx 迁移；默认不写入 demo 拓扑，只有隔离 smoke 或测试库需要演示账号/线路时才临时设置 `SEED_DEMO_DATA=true`。
5. Caddy 镜像构建阶段生成前端静态产物，运行时托管 SPA 并反向代理中心接口；Worker 镜像内置 `pg_dump`，首次到期时会按后台 `database_backup` 策略写入备份目录。
6. 选择后台“一键安装 Agent”或打开 Agent 手动安装说明安装 access-agent；安装成功后脚本输出节点鉴权码，一键安装由平台自动创建中转节点。
   如需自动申请 SSL 证书，安装时必须提供证书域名和 ACME 邮箱；域名会保存为 `XRAYC_TLS_CERT_DOMAINS`，邮箱保存为 `XRAYC_TLS_CERT_EMAIL`。未同时提供时，脚本不会申请证书，但 agent 仍可安装并等待后续配置。
7. 手动安装路径在后台用节点名称、节点地址、端口、鉴权码和备注完成平台绑定；一键安装成功后只需确认自动创建的中转节点状态。
8. 等待 access-agent 心跳、Xray 配置应用、接入端口监听和流量上报正常。
9. 先在出口管理维护第三方、普通自建上游或中转节点本机出口服务。
10. 在入口管理创建中转节点用户入口，选择入口协议、客户端网络模式和 Cloudflare/TLS/Reality 等入口参数，再绑定具体出口线路形成绑定节点；随后在分组页选择绑定节点，并让套餐授权分组。如入口启用 TLS、SNI 或证书字段，部署前必须完成证书准备/验证。节点可同时承载直连与 Cloudflare（CF）橙云入口：入口对外地址命中官方 Cloudflare IP 段时自动识别为 CF 模式，当前只允许 VLESS-WS、端口限定 CF 支持端口（443/8443/2053/2083/2087/2096），回源复用节点灰云直连证书（`cert_domain`）且 CF 控制台 SSL 必须设 Full（非 strict）；Reality/HY2/Trojan/SS 挂 CF 会被拒。同一节点 enabled 入口端口唯一；新建入口/本机出口时前端自动填「合法且未占用」的默认端口（CF 橙云限 CF 端口挑首个空的，对外入口优先防封端口再回退 10000+，本机出口直接用高端口 10000+ 不抢防封端口），避开该节点已用端口并提交前即时校验，后端端口唯一性校验作兜底。详见 `开发方案.md` §2.2.1/§2.2.2。
11. 用真实链路测试验证订阅导入、出站、出口分配、流量入账和超额剔除闭环。

运行数据验收必须在 `scripts/real-smoke.sh` 中开启 `STRICT_AGENT_TRAFFIC=1`，并通过私有环境变量提供 `AGENT_TOKEN`、`ACCESS_NODE_ID` 和 `ACCESS_LINE_ID`，确保 traffic 上报是 2xx 成功路径；未开启严格模式时只能视为接口拒绝路径观察。

## Agent 安装要求

后台提供可选“一键安装 Agent”自动 SSH 安装，并保留手动安装说明。自动 SSH 安装只在本次请求内使用 SSH 主机、端口、用户、密码或私钥，不保存到数据库、审计日志、部署任务、前端任务列表或公开日志；手动安装由管理员拿到说明后到目标服务器执行脚本。目标服务器安装流程必须满足：

- 中心服务器本机构建 `access-agent` 和 Xray 相关镜像。
- 中心通过 `make package-docker-artifacts` 导出 `access-agent-image.tar.gz`、`xray-image.tar.gz`、`access-agent.sha256` 和 `access-agent-manifest.json` 到 `deploy/artifacts`。
- API 容器只读挂载 `deploy/artifacts` 到 `/root/xrayc-artifacts`，并通过 `DEPLOY_ARTIFACT_TOKEN` 保护 `GET /api/deploy/artifacts/{name}`。
- 管理员可通过 `POST /api/admin/access-nodes/one-click-install` 执行一键安装，或通过 `POST /api/admin/access-nodes/install-guide` 生成手动安装说明。手动说明接口返回环境变量、服务器执行命令和步骤；一键安装接口接收的 SSH 凭据只在请求处理期间使用。
- 目标服务器使用短期部署产物授权从中心下载镜像包，执行 `sha256sum -c` 和 `docker load` 后，必须通过节点侧 Docker Compose 执行 `docker compose up -d` 启动。
- 目标服务器预检缺少 Docker、Docker Compose、curl 或 sha256sum 时，应自动补齐；Compose v2 插件不可用时，可使用独立 `docker-compose` 兜底。
- 第一版默认运行方式必须是 Docker Compose，不得把 systemd 作为默认部署或验收口径；systemd 只能作为后续兼容方案另行设计。
- 部署日志只保存脱敏摘要、步骤结果、耗时和错误原因。
- 部署接口和脚本不得在日志、公开文档、响应或任务摘要中输出或保存 SSH 密码、私钥内容、私钥路径、完整 Token、Reality 私钥、第三方代理账号密码、真实目标地址或私有安装路径；节点本机运行必需的 access-agent token 只能写入 root `0600` 的安装目录环境文件。
- 中心 Compose 服务应配置 `restart: unless-stopped`；PostgreSQL、API 和 Caddy 必须有可执行健康检查，Worker 至少保留进程级健康检查，生产环境再叠加外部监控。
- Caddy 对 `/api/deploy/artifacts/` 必须单独配置长超时，当前响应头等待超时为 900 秒，避免目标服务器首次下载镜像包时被反代提前断开。
- access-agent 应用配置时先编译并通过 `XRAYC_XRAY_TEST_COMMAND` 校验候选配置；若配置包含正数 `rate_limit_bps`，必须先成功应用 limiter 规则，`XRAYC_RATE_LIMITER_ENABLED=false`、`XRAYC_RATE_LIMITER_DRY_RUN=true` 或 tc/iptables 命令失败都必须 fail-closed，不得 reload 新 Xray 入站。limiter 成功后再覆盖 Xray 目标配置、回读校验并执行 `XRAYC_XRAY_RELOAD_COMMAND`；reload 失败必须恢复 Xray 上一份可用配置并上报失败。预检成功后通过复制覆盖目标配置并回读校验，不能依赖对单文件 bind mount 不稳定的 rename 语义；当中心下发空配置时，也必须写入空 Xray 配置并重启或 reload，使旧客户端无法继续使用旧入站。
- access-agent 应开启 Xray access log，使用 `XRAYC_XRAY_ACCESS_LOG_PATH` 增量解析在线会话，并将断线期间未上报成功的流量快照保存到 `XRAYC_TRAFFIC_BACKLOG_PATH` 等待补发。
- 节点重装或迁移后，目标服务器状态目录可能为空。中心收到未携带 `applied_config_version` 的心跳时必须重新下发当前配置，不能因为数据库里已有旧 `applied_config_hash` 就返回 `config: null`。

## 接入节点安装脚本

脚本为 `scripts/deploy-access-agent.sh`。脚本在目标服务器接入节点执行，只使用环境变量接收中心地址和部署产物授权；节点 ID 和 access-agent token 由脚本在服务器本地生成或复用既有安装目录环境文件，不在脚本或文档中写死 IP、密码或 Token。一键安装由平台临时上传执行材料并远端运行该脚本，成功后解析脚本输出的节点鉴权码并自动创建中转节点；手动安装说明只生成模板和执行命令，管理员自行在服务器上执行并使用脚本输出的节点鉴权码完成平台绑定。

脚本执行流程：

1. 从 `${XRAYC_DEPLOY_BASE_URL:-$XRAYC_CONTROL_PLANE_URL}/api/deploy/artifacts/{name}` 下载 `access-agent-manifest.json`、`access-agent-image.tar.gz`、`xray-image.tar.gz` 和 `access-agent.sha256`。
2. 在目标服务器执行 `sha256sum -c access-agent.sha256`，校验范围必须包含 manifest、access-agent 镜像包和 Xray 镜像包，避免 manifest 与镜像包版本不一致。
3. 对两套镜像包执行 `docker load`，并按 manifest 中的镜像名校验镜像存在。
4. 写入节点侧 Compose 所需的环境文件、Xray 初始 runtime 配置和 `docker-compose.yml`，环境文件权限必须限制为 root 可读写；Compose 只允许把配置目录整体挂载到容器，不允许单文件挂载 `config.json`。
5. 执行 `docker compose up -d` 启动或更新 `xray` 与 `access-agent` 两个容器；目标环境只存在独立 `docker-compose` 时可使用该二进制兜底。
6. 启动后必须等待 Xray 容器和 access-agent 容器进入运行态、access-agent 状态文件写入期望配置版本；如传入 `XRAYC_EXPECTED_LISTEN_PORTS`，还必须逐个等待这些接入端口进入监听态。
7. 部署失败时默认执行失败回滚：只有本次已经触碰 Compose 启动或容器名后，才停止本次 Compose 项目、删除本次生成的容器；如果安装目录是本次新建，会删除该目录；如果安装目录部署前已存在，则默认保留文件，除非显式设置 `XRAYC_DEPLOY_ROLLBACK_REMOVE_EXISTING=true`。
8. 默认只允许停止或替换本项目节点侧 Docker 容器，不停止或重启 SSH 服务，不执行会影响 SSH 进程的命令。
9. 默认不清理旧版 XrayC systemd unit、不执行 `systemctl daemon-reload`；目标服务器缺少 Docker 时脚本可能通过系统服务管理器启动 Docker 服务，但不得重启 SSH 服务或结束用户会话。如确需清理旧版 XrayC systemd unit，必须显式设置 `XRAYC_DISABLE_LEGACY_SYSTEMD_UNITS=true`，且只允许处理本项目旧 unit。

完整发布门禁会额外执行 `scripts/check-deploy-artifact-endpoint.sh`，在服务器侧安装前比对控制面 artifact endpoint 返回的 manifest/sha256 与本机刚生成产物是否一致。

目标服务器执行命令模板：

```bash
XRAYC_CONTROL_PLANE_URL="https://example.com" \
XRAYC_DEPLOY_ARTIFACT_TOKEN="<set-in-env>" \
bash scripts/deploy-access-agent.sh
```

安装脚本固定安装并启动 Xray，所有入口都由 Xray 处理。如下载部署产物的 API origin 与 access-agent 回连地址不同，可额外设置 `XRAYC_DEPLOY_BASE_URL`。如同机多实例或端口冲突，可设置 `XRAYC_XRAY_API_SERVER`、`XRAYC_XRAY_API_LISTEN_HOST` 和 `XRAYC_XRAY_API_LISTEN_PORT`。如需要让脚本验证中转入口已被 Xray 监听，可设置空格分隔的 `XRAYC_EXPECTED_LISTEN_PORTS`；等待超时由 `XRAYC_DEPLOY_READY_TIMEOUT_SECONDS` 控制，默认 120 秒。脚本默认使用 Docker Compose 管理节点侧进程，`XRAYC_DEPLOY_START=false` 时只安装 Compose 文件、环境文件和配置文件，不启动容器；`XRAYC_DEPLOY_ROLLBACK_ON_FAILURE=false` 可关闭失败回滚，但真实发布和 UAT 不建议关闭；`XRAYC_DISABLE_LEGACY_SYSTEMD_UNITS=true` 只用于显式清理旧版 XrayC systemd unit。安装脚本默认会在部署非默认 Compose 项目时清理旧默认 `xrayc-access` 项目容器，防止历史 Xray 继续监听旧入口端口；如确需保留同机旧默认项目，必须显式设置 `XRAYC_CLEAN_LEGACY_COMPOSE_PROJECTS=false`。测试脚本内部可覆盖失败清理策略，但这只是 UAT 对目标服务器本地安装流程的验收开关，不是后台远程安装能力；默认只删除本次新建的目标服务器安装目录和本次 Compose 项目，若清单指向安装前已存在的目录，则保留目录和既有服务，除非测试环境显式允许清理既有安装目录。安装完成日志只能输出完成状态和脱敏状态检查提示，不得打印 `XRAYC_INSTALL_DIR`、包含安装目录的 `docker compose -f ...` 命令或其他私有安装路径。

公网生产控制面必须使用 HTTPS。真实目标服务器 UAT 默认拒绝 `http://` 控制面地址；只有私有测试环境暂未配置 TLS 时，才允许通过内部测试开关临时使用 HTTP 控制面地址；公开日志和文档只能记录脱敏结果，不得记录真实地址。

Docker Compose 形式的 Agent 安装默认 reload/start/stop 命令通过挂载到 access-agent 容器的 `/var/run/docker.sock` 调用 Docker API，按 `XRAYC_XRAY_CONTAINER_NAME` 精确控制本节点的 Xray 容器。这样不依赖 host PID namespace、`/proc/<pid>/exe` 或进程环境读取权限，也避免误杀同机其他代理进程。该 socket 只用于重启或启停本项目生成的 Xray 容器，公开文档和日志不得输出真实容器所在主机地址或 Token。

后台安装说明默认不推导 `XRAYC_EXPECTED_LISTEN_PORTS`，因为订阅入口端口恒为逻辑中转入口端口、不因用户级限速变化（限速靠每用户 mark 区分），而端口监听时序由节点实际收敛决定，默认不宜作安装成功断言。管理员确实需要端口监听断言时，应显式填写空格分隔端口清单；脚本只接受本次启动后新写入的 access-agent state，强制重装会清理旧 `state.json` 和旧 backlog，避免复用历史配置造成假成功。

一键安装仅在请求生命周期内执行目标服务器 SSH 命令，手动说明不执行远端命令；两条路径都不得保存 SSH 凭据。安装脚本负责安装中转运行组件并加载运行所需的线路配置；本机出口服务通过中转节点详情专用动作批量添加出口管理线路，不由安装脚本自动创建。

目标服务器运行状态检查：

```bash
docker compose ps
docker compose logs --tail=100 access-agent
```

## 验证命令

本地静态验证：

```bash
bash scripts/verify-no-secrets.sh
make check-smoke
```

中心服务验证：

```bash
docker compose config --services
make package-docker-artifacts
docker compose up -d
DATABASE_URL=<postgres-url> cargo test -p xrayc-db -- --nocapture
cd frontend && E2E_BASE_URL=http://127.0.0.1:8080 npm run test:e2e
```

真实链路 smoke 需要提供环境变量，不允许把真实值写入命令历史、文档或脚本：

```bash
BASE_URL="https://example.com" bash scripts/real-smoke.sh
```

如需要验证订阅下载，可由私有环境注入 `SUB_TOKEN` 或 `SUBSCRIPTION_URL`。公开文档不得记录真实 Token。

真实公网 E2E 使用以下脚本，必须从私有环境注入真实订阅、真实客户端本地代理和期望公网出口；缺少真实值时脚本会失败，不允许跳过后伪装成功：

```bash
bash scripts/real-access-pool-e2e.sh
bash scripts/real-access-third-party-socks-e2e.sh
bash scripts/real-access-third-party-http-e2e.sh
bash scripts/real-access-third-party-vless-e2e.sh
bash scripts/real-access-third-party-trojan-e2e.sh
bash scripts/real-access-third-party-shadowsocks-e2e.sh
bash scripts/real-access-third-party-hy2-e2e.sh
```

运行数据接口验证必须在真实 Docker 环境中执行。curl 或脚本只能使用占位地址和私有环境变量注入凭证，例如：

```bash
BASE_URL="https://example.com" AGENT_TOKEN="<from-private-env>" ACCESS_NODE_ID="<from-private-env>" bash scripts/real-smoke.sh
```

验证项至少包括：无 access-agent token 返回 401；有效 token 可上报 `/metrics`、`/sessions`、`/probes`；运营中心汇总能展示真实在线、连接数、上下行速率和探测延迟；日志和报告不包含真实服务器 IP、密码、Token、订阅链接或代理凭据。

## 回滚原则

- 中心服务回滚优先使用上一版本镜像和兼容迁移策略。
- 数据库迁移必须提前评估是否可逆；不可逆迁移需要备份和人工回滚步骤。
- 接入节点配置应用失败时，access-agent 应保留上一份可用 Xray 配置。
- 出口管理出口或内部运行成员维护时优先标记成员 `degraded`、`draining` 或 `offline`；接入节点到出口的实时异常优先通过组合探测状态和阈值策略处理，不要删除出口资源和历史映射。
